## 1.2\_Developer Build

Enter the root directory of the Typora Code repository `enhancements` and then execute:

```powershell
cd enhancements
npm ci
npm run build
npm run check
npm run check:ui
```

Requirements, use case classification, pressure levels, and current evidence are unified in [Stability Test Architecture](../docs/stability_testing.en.md). `npm run check:ui` uses precisely locked Electron `43.2.0`, running hidden window regression tests in sequence without starting real Typora. Each test runs in an independent Electron process, and fixtures using files or user data use isolated temporary directories, reporting individual execution times and failures at the end. `npm run check:all` executes platform neutrality checks and hidden UI checks in sequence. Use `npm run check:ui -- --list` to view fixed suites, or list one or more test files after `--` for focused validation. The installation script will back up `resources/window.html`, managed running assets, pending migrated old settings, terminal files, and optional themes to:

The current release list manages 29 assets (including update service and community plugin service), including `workspace_core.css`, `workspace.css`, `workspace_core.js`, `workbench.js`, language, and license resources, installed to the user data directory `typora_code/`. The `window.html` head will first load two static CSS files, then defer the start of core and workbench. The core waits for the host and styles to be ready before initializing once, and the workbench waits for its `ready`. Switching files or folders will not rebuild. The current installation and recovery use schema 4 JSON list; pre-check, backup, and copy verification are done first, and failure leads to rollback. The installation uses schema 4's `native_profile` to record complete backup and SHA: `profile.data` is a lowercase hexadecimal text of UTF-8 JSON, only setting `framelessWindow` as `true`; when the original profile does not exist, it creates a minimal HEX JSON containing only that field and records the default value of the original file. Recovery only restores the original value or default of that field, preserving other settings installed after. Installation does not modify `app.asar`, and does not deploy the main process menu bridge. Old lists still reject writing when other plugins are enabled; require disabling them first, and other plugin files are not overwritten; do not retain parallelly running old plugin entries. Linux executes JSON and file transactions via Python 3. Execution:

```powershell
# Run from the repository root.
powershell -ExecutionPolicy Bypass -File .\install_windows.ps1
```

This script reuses `scripts/lib/typora_environment.ps1`, does not maintain its own fixed installation directory candidates. Typora updates will replace the installation directory, and after the update, if the entry disappears, the installation script should be run again. Do not force quit Typora when the document has unsaved modifications; after installation, save the document and restart normally, the extension will then enter the new window.

All the following commands are run in the root directory of the repository. When rolling back, pass in the backup directory from the installation output:

The recovery script first pre-checks the complete backup, saves the current state as a secure snapshot in the original backup directory, then restores the original entry and managed assets according to schema 4, clears the newly added managed running files in this session, and preserves the user product settings. ### 1.4.1\_Reading Position and Title Localization

Markdown links with `#heading` wait for the target file and target tab to be ready, then move the native editor to the target tab, and position the cursor and document content to the title; the directory updates with the target file and selects this title. Other tabs retain their respective paragraphs and internal offsets from when they were left; they are no longer affected by the global delayed anchor point. New windows restore will simultaneously verify the document's height, viewport size, and actual scroll position; host delayed recovery of the selected area's scroll reset does not override the last position, and real scrolling or editing input immediately ends the automatic recovery. The preview tab's relative links are resolved based on the directory of the document in this tab.

When opening and closing tabs normally, and reopening after closing the window, the document's last reading position is restored. Explicitly specified title links and Alt history positions take precedence over 'last position'. Position records use short text fingerprints of visible blocks, internal offsets, and scroll coordinates to avoid applying old files' temporary cursor numbers or expired character offsets to new files; when text changes cause the localization block to disappear, it reverts to the scroll coordinate.

When searching by double-clicking Markdown, use the target source code's line and column mapping to the native document or code fence, and verify the current content with the actual selection. Window history retains these hits with verified line and column numbers and text; when moving forward, it re-maps the current node of the target document, avoiding using invalid temporary numbers after reopening; continuous opening waits for the completion of the previous reading transaction. Already opened Markdown documents directly activate the original tag, including cases where the central current display is source code or tool tags.

Last position is independent of window scrolling history, retains the last 500 used files, stored in Typora's current user configuration's Local Storage; does not create state files in Markdown or repository. Each file is written independently, and rolling writes are merged to 300ms, and pending writes are submitted when the window is closed. Installation, reinstallation, and recovery of the extension do not clear reading records; clearing Typora user data will clear these positions. Positions recorded before the first installation cannot be recovered.

Markdown directory automatically selects the complete and readable viewport title, and if there is no visible title, it will revert to the current section of the document content. The edge has a 12px buffer, and the native delay callback is converged to the same synchronization, avoiding adjacent title flickering. Explicitly clicking the directory still uses native positioning, and the directory is automatically highlighted only when it is scrolled itself. The readable viewport deducts the covered area of the status bar, providing space for the outline and thumbnail to share.

When hovering over a document link for 1 second, the target information is displayed. Internal positions are represented by `/directory/file`, and Chinese file names and titles with percent-encoded characters are displayed as readable text. After moving into the hint, you can choose to select text or copy the original link. A 250ms movement tolerance avoids the floating layer from disappearing too early; displaying and copying do not change the document link, nor do they read the target file.

On the right side of each visible document, there is a **Document Thumbnail**: drawn according to the actual text and position of the document content, with the viewport box representing the current visible range. Clicking the thumbnail jumps to the corresponding position, and dragging the viewport box continuously locates; when focused, you can use the arrow keys, PageUp/PageDown, Home/End. Native reading, other split views' previews, and `Ctrl + /` source code mode all support this. Operations only scroll the corresponding document, without changing the cursor, document content, or scroll history. In source code mode, the complete CodeMirror text is read, and the rendered text in reading mode is displayed. Images and Mermaid graphics themselves are not drawn into the thumbnail. Each document maintains a stable foreground canvas; for long documents, the drawing is first completed in an off-screen canvas frame by frame, and then submitted as a complete image at once. Daily scrolling only moves the viewport box; switching sidebars and other operations that do not change the document content, size, or theme do not redraw, so there is no blank, half-frame, or flicker exposure.

### 1.4.4\_Workspace Search and Replace

Click the **Search** in the activity bar, or press `Ctrl + Shift + F`, to search disk text in the currently opened folder. | Controls | behavior |
| --- | --- |
| Case-sensitive / Whole word match / Regular expression | Controls the matching method; whole word match identifies Unicode letters, numbers, and underscores boundaries, regular expression uses JavaScript syntax |
| Included files / Excluded files | Use `/` to separate paths, comma to separate patterns; supports `*`, `**`, `?`, character classes and `{c,h}`, for example `src/**, *.md`; `./` specifies the root directory starting point |
| Use .gitignore and default exclusion settings | Default enabled, using Git's standard ignore rules and default exclusion settings; disabled, it still retains explicit inclusion/exclusion conditions, and the actual skipped situations are shown in the range description |
| Search only changes in source code management | Acquire files from the current folder's repository, including staged, workspace changes, and untracked files, search their current disk content; it still applies inclusion/exclusion and ignore rules, deleted files have no content to search; non-repository projects give explanations |
| Search only open editors | Limit to files currently open in the current workspace, still read disk versions; it is mutually exclusive with 'search only changes in source code management' |
| Enter／Shift + Enter／Esc | Immediate search / New line in query / Stop current search; input will also delay the search |
| Replace / Keep case | Supports single line, single file, and all results replacement previews; regular expression replacement can reference capture groups, keep case by adjusting the replacement text according to the matched text |

Replacement first displays involved files, match counts, and **Before replacement / After replacement** dual-column preview. Click **Confirm replacement** before writing to disk. Before applying, recheck the original bytes, file identity, and unsaved documents; after search, if disk content changes, path overflow, symbolic links / hard links, or related Markdown / source code tags are not saved, it will refuse to write, requiring processing and re-searching. Only supports UTF-8, UTF-16LE / BE replacement that can maintain original encoding, and retain BOM; other encodings cannot guarantee lossless replacement, so only allow search. If search is canceled or reaches the limit, no full file / all replacement is executed, and can be re-reduced in scope. Multi-file replacement is not an atomic transaction across files, errors will report completed scope, and do not promise transaction isolation when external programs write concurrently.

Default maximum display of 5000 results, single file search limit of 8 MiB, total snapshot of matched files up to 64 MiB. Binary, large, unreadable, links, and excluded items will be counted or provide range explanations; visibility in the file tree does not mean each file is suitable for text search. Current search does not use VS Code extension search providers; it is independent of the code outline's clangd semantic analysis. File name scanning and scoring yield the interface in time slices; content scanning pre-reads up to 4 files, and the sidebar displays matches in batches. Large directories can first use already discovered results, new queries and switching projects will make old tasks invalid; specific limits, baselines, and performance measurements are seen in [Large directory search performance and verification](../docs/search_performance.en.md).

Ordinary text and regular expression matches are executed independently in a Worker, with a budget of 2 seconds per file; clicking stop or pressing Esc will terminate the current Worker, avoiding matching from continuously occupying the interface thread. Timeout will note the corresponding file, and reject all replacements in this round, including individual replacements; simplify the expression or reduce the scope and re-search. Cancellation and timeout will not write to disk.
