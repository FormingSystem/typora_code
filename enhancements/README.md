# 第1章\_Typora\_工作区、阅读导航与代码增强

用户入口见 [Typora 安装与阅读工作区](../README.md#1.1_安装、检查与恢复)；原生偏好设置另见 [配置截图](../typora配置展示.md#第1章_文件)。本页集中说明扩展能力、构建与依赖维护。

工作台布局、交互方式和部分功能设计参考并模仿 VS Code，来源及采用范围见 [界面基线](../docs/vscode_design_baseline.md)。本项目原创代码采用 [GPL-2.0-only](../LICENSE)，原创署名、二次开发、贡献与第三方边界见 [版权、开源与贡献声明](../COPYRIGHT.md)。第三方依赖继续适用各自许可证。

社区扩展从左侧“扩展”（Ctrl+Shift+X）侧栏管理，配置从左下齿轮“插件设置…”或插件行“设置”进入，支持typora-community-plugin v2插件的真实社区市场/本地ZIP安装、启停、设置、更新和卸载；空安装自动加载市场，支持作者筛选、来源和系统兼容提示，设置仍由插件自身注册及持久化；新安装默认停用，先确认信任再启用。复用当前核心和UI，兼容范围见[社区插件接入](../docs/community_plugins.md)。

本扩展补足主题 CSS 无法承担的以下能力：

- 使用由固定 MIT 上游源码裁剪的常驻工作区核心：同一个桌面窗口内使用多文档标签页，[标签右键菜单](../docs/editor_tab_menu.md)支持批量关闭、预览、固定、路径与定位、四方向分屏、相邻组移动及移动／复制到新窗口；
- 标签下的[面包屑导航](../docs/editor_header.md#r034-标题与函数面包屑)显示目录、文件与当前标题／函数；点击打开可过滤的层级列表，选择后定位并继续编辑。`Ctrl+Shift+.` 聚焦并打开，`Ctrl+Shift+;` 聚焦，`Esc` 取消并恢复原焦点；视图菜单或导航右键可开关及配置用户／工作区覆盖；
- 原生 Markdown 选区右键菜单支持[字体颜色](../docs/markdown_text_color.md)：常用色、自定义色、恢复默认、明暗主题适配以及原生撤销和保存；
- 文件树显示全部文件及隐藏项目，目录按需展开；Markdown 保持原生渲染，普通源码在占满编辑组的 Monaco 中编辑，支持保存与编码、换行格式设置；
- C/C++文件与头文件使用本机clangd识别代码大纲，点击符号定位；JavaScript、TypeScript、Python、CMake、YAML使用随包离线语法，Markdown显示标题目录；
- 按文件搜索并展示路径和匹配高亮，悬停查看行列位置，双击精确选中 Markdown 原生正文或其他文本的源码；支持 Git 更改文件等范围筛选与确认后的替换，活动栏支持选中高亮和拖动排序；
- 手动搜索和选中文字后 Ctrl／Cmd 加鼠标左键共用搜索侧栏；单击在下方 Markdown／源码阅读区预览，双击或 Enter 在编辑区打开文件，支持预览收放、缩放和上下分区拖动；
- 顶栏保留 Typora 原生七类菜单，并在帮助前增加终端入口；renderer 调用已核对的宿主功能和共享终端命令，视图勾选读取实际状态；中央提供后退、前进和文件搜索；
- 使用 Ctrl+=／Ctrl+- 缩放当前窗口；非默认比例时底栏显示[缩放图标](../docs/workspace_zoom.md#r014-底栏缩放入口)，点击或悬停可缩小、放大、重置，并进入原生“外观 → 缩放”设置；
- 使用 `Alt + ←` / `Alt + →` 或顶栏箭头后退、前进，通过同一[导航历史](../docs/navigation_history.md)记录文内/跨文件链接起终点、源码定位及编辑组，恢复光标、选区与滚动位置；普通源码近邻移动合并，明确跳转保留位置；
- 带标题的链接在目标栏定位光标、正文和目录，来源栏保留阅读位置；关闭标签或窗口后重新打开文件，继续上次阅读；
- 链接悬停1秒显示可读目标和原始链接并支持复制；底栏恢复单侧0%～24%的正文边距控件，调整时保持阅读段落；
- 在标签和侧栏文件树的右键菜单复制相对路径、绝对路径，并提供 VS Code 风格的复制路径快捷键；
- 在原有主侧栏使用中文源代码管理，在原有编辑标签中查看 Git Graph、文件历史和随编辑组宽度切换的 Monaco 差异；
- 按对象配置 Git 右键菜单，拖动面板分界线；从仓库根目录打开集成终端，先显示面板再检测及启动Shell，等待过程使用共享进度和阶段文字，支持多会话、分栏和管理员入口；
- 使用 VS Code 内置 C/C++ TextMate 语法和 Oniguruma 解析 Typora 的 `c`、`cpp` 等代码围栏，并把识别出的语法角色映射到 GitHub Light 代码配色；
- 对超过响应式阅读高度的普通代码块默认限高，提供 `展开全部代码` / `收起代码` 切换；正文或代码块获焦时都能直接点击，按钮获焦后支持 Enter / 空格，打印时自动完整展开且不修改 Markdown；
- 图片与 Mermaid 共用外侧右上方的悬停全屏按钮；按钮在正文外覆盖显示，不插入工具行或推开正文，随原图滚动并按来源去重；
- 为 Typora 已渲染的 Mermaid SVG 增加独立全屏查看器，默认保持 `100%`，支持按钮缩放、`Ctrl + 滚轮` 指针中心缩放、左键拖动、适应宽度、适应屏幕、恢复 `100%` 和 `Esc` 退出。

扩展不按 `int`、`struct` 或 Linux API 名称写私有规则。VS Code grammar 负责产生 `entity.name.function.c`、`entity.name.type.c`、`variable.*` 等语法作用域，样式只映射作用域颜色。TextMate 是语法级解析，不是编译器或语言服务器；它不会读取项目头文件、宏展开结果和编译数据库，因此不宣称提供 VS Code C/C++ 扩展的完整语义分析。

多行 `#define` 中的 `meta.preprocessor` 表示整个宏体所在的上下文，不能据此把所有内容染成蓝色。指令和宏定义名使用预处理器颜色，宏体内的 `do` / `while`、`unsigned long`、函数调用、注释、字符串和运算符仍按各自语法角色着色。

当前资源管理器包含打开的编辑器、目录树和时间线；关闭最后文件进入真实空编辑区。工作区切换和文件恢复由[共同会话服务](../docs/workspace_switch.md)管理，提交浮层使用[安全 Markdown 渲染](../docs/workspace_interaction.md#r053-提交浮层的-markdown-排版)。

首次展示由静态 head 的就绪状态控制，失败或超时恢复原生操作；语法初始化不阻塞界面挂载。功能区切换只移交侧栏内容，重复显示不重新挂载。开发验证同时检查中间帧、生命周期及长任务，入口见[启动稳定性](../docs/startup_stability.md)，不能只靠最终截图判断。

## 1.1\_普通用户一键配置

从仓库根目录运行 `install_windows.cmd`（Windows）或 `bash ./install.sh`（Linux / MSYS2 UCRT64）。Windows 卸载增强时，保存文档并退出 Typora，双击 `uninstall_windows.cmd`，自动查找兼容安装前备份；没有兼容备份时备份并撤销当前加载入口，保留宿主和个人数据，支持`-check_only`预检及卸载日志。版本回退使用 `restore_windows.ps1`。完整下载安装、环境、离线缓存、升级、卸载与恢复统一见[安装与恢复指南](../docs/installation.md)。普通用户使用随包预构建文件；开发者构建步骤见下一节。

## 1.2\_开发者构建

从 Typora Code 仓库根目录进入 `enhancements` 后执行：

```powershell
cd enhancements
npm ci
npm run build
npm run check
npm run check:ui
```

`vendor/vscode_cpp/` 保存 C/C++ grammar，`vendor/gemoji/` 保存 emoji 数据与许可，`vendor/workspace_core/` 保存固定 `2.10.15` 上游源码裁剪的常驻核心，见 [SOURCE.json](vendor/workspace_core/SOURCE.json) 与 [LICENSE.md](vendor/workspace_core/LICENSE.md)。`scripts/build_workspace_core.mjs` 输出核心脚本、CSS 和三个语言包；总构建输出其余静态样式与工作台脚本。`npm run check` 核对发布摘要、部署入口、核心构建闭包、功能标记、语法及状态逻辑。

需求、用例分类、压力档位与当次证据统一见[稳定性测试架构](../docs/stability_testing.md)。用 `npm run test:quality -- --list` 查看带需求关联的全部套件；原生隔离验收和未具备环境的处理规则也在该文档中。

`npm run check:ui` 使用精确锁定的 Electron `43.2.0`，顺序运行不启动真实 Typora 的隐藏窗口回归；每项在独立 Electron 进程中执行，涉及文件或用户数据的夹具使用隔离临时目录，并在末尾报告逐项耗时及失败。`npm run check:all` 依次执行平台中立检查和隐藏 UI 检查。用 `npm run check:ui -- --list` 查看固定套件，也可在 `--` 后列出一个或多个测试文件进行聚焦验证。runner 会检查全部 `test_*.cjs` 是否已明确纳入或排除，新增测试不会被静默漏过。`test_terminal_interaction.cjs` 会读取 `TYPORA_TEST_USER_DATA` 中的终端运行文件并启动真实 Shell，因此不属于这组隔离测试，仍按终端章节单独执行。

当前以 `59412a2` 为平直布局与功能范围参考，保留已验证的稳定修复，并非整库恢复旧提交。VS Code `1.136.2` 与主题取证用于已明确要求的修复，不授权继续扩充工作台或恢复 Modern 布局。按用户 2026-09-10 的最新要求，Explorer 文件和真实文件标签使用随包提供的 Seti `10.0.0` 原始字形与颜色；文件夹只保留展开箭头。独立大纲保留原生 `fa-list` 图标及原节点，SCM 与 Graph 的图标各按自身语义处理。此调整仅涉及图标，不恢复 Open Editors、底部 Panel 或预览标签行为；普通安装不读取本机 VS Code。详见 [设计基线](../docs/vscode_design_baseline.md) 和 [图标映射](../docs/icon_mapping.md)。

跳转正文预览直接依赖固定版本的 Marked `14.0.0`（MIT）与 DOMPurify `3.4.14`（Apache-2.0 或 MPL-2.0）；清单、锁文件及构建所用版本一致，Monaco 的同名传递依赖也使用锁定版本。构建在 bundle 开头保留完整许可证，普通安装不另行下载这两个包。

搜索面板由 `workspace_search.ts` 统一承担，`workspace_selection_search.ts` 连接选中文字的 Ctrl 加左键动作，`workspace_lookup_preview.ts` 展示下方内容；`workspace_markdown_location.ts` 负责原生 Markdown 行列定位。修改这一入口时，需要核对“单击预览、双击打开”、Markdown 原生渲染、中央位置保持、预览收放、缩放持久化和分界线拖动，并同步预构建及安装功能标记。

`workspace_markdown_preview_render.ts` 负责围栏高亮和隔离的 Mermaid 预览；图表从当前 Typora 安装的 `lib.asar/diagram/mermaid.min.js` 加载到独立 iframe，不调用中央文档共享的 Mermaid 实例，也不需要联网下载图表库。Windows Typora `1.14.9` 的随附库已核对为 Mermaid `11.13.0`。`workspace_editor_status.ts` 将活动源码或差异编辑器的状态控件挂到唯一全局底栏，切换标签、分组或差异左右两侧后更新归属。

Git Graph 开发回归另需 PATH 中的 Git 和 `ssh-keygen`，用于临时仓库及临时密钥签名验证。测试不使用用户密钥和远端账号；普通扩展安装无需这些开发测试依赖。

交互回归由 `npm run check:ui` 调用本包自己的 Electron 可执行文件，并从子进程环境移除 `ELECTRON_RUN_AS_NODE`。其中 `scripts/test_interaction.cjs` 在隐藏的 Chromium 窗口中加载模拟宿主夹具和生产 bundle，发送真实鼠标与键盘输入，检查首次展开/收起、按钮重建、Enter / 空格、空闲 DOM、宏体颜色和 Alt 方向键导航。跨文件夹具包含常驻工作区的延迟锚点步骤，后退一次必须回到来源文档。隐藏窗口夹具不替代 Typora 实窗验收。

Windows 安装当前 bundle 后，可从本目录运行 `powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\test_reading_native.ps1`。脚本通过共享环境助手发现 Typora，生成临时 Markdown，验证预览栏中的中文标题链接、目标光标及目录、来源段落与栏内偏移、Alt 前后导航、关闭标签重开和新窗口续读；比较源文件摘要，确认正文没有被改写。测试入口只对两个临时文档生效，完成后关闭自己的测试窗口并移除入口，不退出其他窗口。结果 JSON 保留在脚本输出的临时目录。

同一命令增加 `-suite paths` 验证复制路径：标签右键菜单、文件树菜单事件、快捷键、非活动标签和活动预览栏的目标识别，以及光标和阅读位置保持。该套件用剪贴板桥接替身核对复制文本，不覆盖系统剪贴板。`npm run check` 另覆盖 Windows、UNC 和 Linux 路径、根目录边界、中文与空格、未保存文档。

增加 `-suite git` 验证 Git Graph：脚本生成临时 Git 仓库，在真实 Typora 中检查提交图、分栏、分支筛选、合并父提交、中文差异、查找、非零阅读位置、菜单预览与执行、评审记录、Ctrl 比较和内嵌详情。只读阶段比较正文与索引字节；写入阶段只操作脚本创建的仓库。`npm run check` 同时覆盖真实 Git 的历史读取、stash、远端同步、提交和冲突流程。`scripts/test_git_graph_interaction.cjs` 使用开发环境的 Electron 执行真实鼠标和键盘测试，第二个命令行参数可指定截图目录；它独立创建临时 Git 仓库与用户数据。

增加 `-suite workspace` 验证新工作区集成：在临时文件中检查选中文字查找、预览与双击打开、源码编辑保存和格式、侧栏收放，以及源码草稿切换、同一标签跨组移动和后台标签关闭；测试前后比较调用工作树的索引字节，测试写入只落在临时目录。关闭函数的先后顺序、真实 `window.close()`、取消与一次性放行另由 `test_workspace_source_lifecycle.cjs` 在隐藏 Electron 中验证：夹具先注册模拟宿主的关闭处理，再加载生产关闭保护，核对执行顺序。

增加 `-suite markdown_location` 验证双击 Markdown 的原生定位：标题、粗体段落、相同词的不同段落、含制表符围栏中同行第二次命中，以及 Alt 后退／前进、快速连续跳转、已有标签复用和源码草稿保护。用临时文件的字节与原生修改计数确认定位没有改写正文。

增加 `-suite rename` 验证文件和目录改名后，原生 Markdown 标签、源码草稿、撤销栈、格式和后续保存路径随之更新；同时检查目录名相同前缀的兄弟目录不受影响。文件系统冲突与名称边界由 `test_workspace_rename.mjs` 检查；F2、已选中文件双击和右键菜单由 `test_workspace_explorer.cjs` 使用 Chromium 指针与键盘事件检查。

`powershell -NoProfile -ExecutionPolicy Bypass -File scripts/test_install_windows.ps1` 在临时副本、含空格路径和隔离的 `APPDATA` 中测试安装、重复安装、摘要检查、恢复、失败回滚与预检拒绝。`bash scripts/test_workspace_install.sh` 测试公共发布资产与迁移事务；仅在兼容 shell 中通过时，不能据此宣称原生 Linux 或 UCRT64 平台验收完成。

在 `enhancements/` 运行 `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/test_uninstall_windows.ps1`，验证 Windows uninstall 的备份发现、排除更新、目标校验、取消和运行进程拒绝，以及 CMD 转交的实际隔离恢复。夹具使用专属临时安装、APPDATA 和 Node 缓存，保留用户真实安装。

`fixtures/visual_test.md` 用于 Typora 实窗验收；可调试的隔离 Typora 实例还可运行 `node scripts/smoke_typora.mjs <端口> <截图路径>`，脚本会先点击正文，再用鼠标按下/松开分别验证展开和收起。

回归套件按运行层检查以下能力；具体项数和结果以每次生成的报告为准，不能把隐藏 Electron 夹具写成全部 Typora 功能已实机通过：

| 验证入口 | 覆盖范围 |
| --- | --- |
| `npm run check:ui` | 精确 Electron `43.2.0`：顺序执行全部自包含隐藏窗口夹具，隔离临时目录并汇总耗时和失败 |
| `test_workspace_startup.cjs` | 真实工作台模块：启动取消／失败清理、草稿保护、文件夹切换不重建及 Explorer／Search／SCM／Graph／大纲／终端联动 |
| `test_workspace_core_smoke.cjs` | 真实核心：一次启动、同实例切目录、全局设置保存且不写打开目录；空占位隐藏、未保存草稿标签保留 |
| `test_workspace_first_frame.cjs` | 静态样式、首帧外观与启动时序 |
| `test_reading_lifecycle.cjs` | 阅读事件、宿主包装、位置恢复取消、卸载与重载清理 |
| `test_git_graph_pull_request.cjs` | PR服务配置、跨fork、非remote目标、自定义地址与标签图标主题 |
| `test_workspace_file_operations.mjs` | 真实文件创建、二进制复制、移动、回收站与冲突／失败回退 |
| `test_workspace_search.mjs` | 临时目录／Git 后端：匹配、范围、忽略规则、编码及替换保护 |

## 1.3\_PowerShell单独安装扩展与备份

安装脚本将 `resources/window.html`、受管运行资产、待迁移旧设置、终端文件与可选主题备份到：

```text
%APPDATA%\Typora\backups\typora_code_configuration\<时间戳与唯一标识>\
```

当前发布清单管理29个资产（含更新服务与社区插件服务），包括 `workspace_core.css`、`workspace.css`、`workspace_core.js`、`workbench.js` 与语言、许可资源，安装到用户数据目录 `typora_code/`。`window.html` 的 head 先加载两份静态 CSS，再 defer 启动核心与工作台。核心等待宿主及样式就绪后只初始化一次，工作台等待其 `ready`，切换文件或文件夹不会重建。当前安装与恢复使用 schema 4 JSON 清单；先预检、备份、复制校验，失败回滚。 安装使用 schema 4 的 `native_profile` 记录完整备份及 SHA：`profile.data` 是 UTF-8 JSON 的小写十六进制文本，只把 `framelessWindow` 设为 `true`；原 profile 不存在时创建仅含该字段的最小 HEX JSON，并记录原文件缺省。恢复只还原该字段原值或缺省，保留安装后其他设置。未知编码、非对象、非布尔窗口设置及写前摘要冲突均拒绝写入，失败按事务回滚。安装不修改 `app.asar`，也不部署主进程菜单桥接。旧业务设置仅在新配置不存在时迁移至 `typora_code/settings/workspace.json`，后续安装保留用户设置，不在打开的文件夹写配置。旧列表仍启用其他插件时拒绝写入，要求先停用，其他插件文件不被覆盖；不保留并行运行的旧插件入口。 Linux 通过 Python 3 执行 JSON 与文件事务。执行：

```powershell
# 在仓库根目录运行
powershell -ExecutionPolicy Bypass -File .\install_windows.ps1
```

该脚本复用 `scripts/lib/typora_environment.ps1`，不维护自己的固定安装目录候选。Typora 更新会替换安装目录，更新后若入口消失，应重新运行安装脚本。不要在文档有未保存修改时强制退出 Typora；安装完成后保存文档并正常重启，扩展才会进入新窗口。

以下命令均在仓库根目录运行。回退时传入安装输出的备份目录：

```powershell
powershell -ExecutionPolicy Bypass -File .\restore_windows.ps1 `
  -backup_root "$env:APPDATA\Typora\backups\typora_code_configuration\<时间戳与唯一标识>"
```

恢复脚本先预检完整备份，在原备份目录保存当前状态的安全快照，再按 schema 4 恢复原入口和受管资产、清除本次新增的受管运行文件，保留用户产品设置；恢复失败会回滚恢复操作。旧入口仅在撤销安装时随备份恢复。

## 1.4\_标签页、分栏与阅读历史

标签可在同窗排序、移入另一编辑组，拖出窗口建立附窗，拖入已有窗口合并。调整分隔线只改变相邻两栏；删除或收回嵌套分栏后保留正确份额。活动标签排序不重开编辑器，同窗移动保留源码模型与撤销历史；跨进程目标建立新的编辑历史。正文边缘自动拆组尚未实现，四向分屏使用标签菜单。详见[拖动设计与压力验证](../docs/drag_and_windows.md#r0051-压力测试与资源清理2026-09-20)。

默认布局采用 VS Code 的 **单窗口、一组多标签页** 形式：在当前窗口打开 Markdown 或源码后保留文件标签；需要并排阅读时再拆分。标签支持关闭、拖动排序和组间移动，标签右键菜单提供分栏操作。标签使用原生拖放，同窗排序、跨窗合并以及窗口外松开建窗；由实际窗口边界判断，缩小、最大化和全屏共用规则。目标恢复并确认后才核对和移除来源；原生Markdown草稿还需宿主确认共享文档持有状态，具体范围见[左键拖动与独立窗口](../docs/drag_and_windows.md)。

顶栏保留 Typora 原生七菜单：文件、编辑、段落、格式、视图、主题、帮助。原生操作使用宿主命令；后续授权已增加终端顶级菜单并调用终端协调器，选择和转到菜单未引入。Ctrl+P 和顶栏中央搜索入口共用文件选择器，2026-09-20的[R058](../docs/quick_open.md)统一采用固定VS Code路径匹配、排序及高亮；阅读历史沿用现有能力。快捷键的物理键盘与原生 accelerator 冲突尚未实证；各层记录见[反馈复查记录](../docs/feedback_review.md)。选择器含边框宽 `min(600px, calc(100vw - 12px))`、最大高 `min(70vh, 560px)`，结果行22px、输入框23px。标签条高35px，使用13px Segoe UI与Light 2026／Dark 2026状态颜色；右侧复用宿主窗口按钮，左中区域由单行顶栏组织。

工作台通过共享宿主组织文件、搜索、终端与 Git Graph；弹窗、右键菜单和基础 DOM 构造由 `workspace_widgets.ts` 提供；Git与更新的任务进度复用 `workspace_progress_view.ts`，业务各自持有阶段、取消和完成状态。关闭事务保留未保存确认与草稿保护；静态样式和常驻脚本不因切换文件夹重新加载。

底栏恢复原有的 Markdown 边距百分比滑块：单侧 0%～24%，默认 0%，沿用之前保存的比例。调整后保留当前阅读段落；只改变活动 Markdown 正文框宽度，主题内边距、字体和渲染、源码与差异页、搜索及其他分栏预览保持原样。该入口直接保存到既有本地设置，不增加外观设置页。百分比、字数、语言、文件/Git操作和源码状态复用[底栏布局契约](../docs/statusbar_layout.md#r0081-统一底栏布局契约)；底栏大纲入口已取消，使用活动栏或视图菜单。

### 1.4.1\_阅读位置与标题定位

带 `#标题` 的 Markdown 链接会等待目标文件及目标栏就绪，再把原生编辑器移到目标栏，将光标和正文定位到标题；目录随目标文件更新并选中该标题。其他栏保留各自离开前的段落与栏内偏移，不再由全局延迟锚点改变来源文档。新窗口恢复会同时核对正文高度、视口尺寸和实际滚动位置；宿主延迟恢复选区造成的滚动重置不会覆盖上次位置，真实滚动或编辑输入会立即结束自动恢复。预览栏的相对链接以该栏文档所在目录解析。

普通打开、关闭标签后重开，以及关闭窗口后重开，都会恢复文件上次的阅读位置。明确指定的标题链接和 Alt 历史位置优先于“上次位置”。位置记录使用可见块的短文本指纹、块内偏移及滚动坐标，避免把旧文件的临时光标编号或过期字符偏移应用到新文件；文本改变导致定位块不存在时回退到滚动坐标。

搜索双击 Markdown 时，用目标源码行列映射到原生正文或代码围栏，并核对当前内容与实际选区。窗口内历史为这类命中保留经校验的行列和文本，前进时重新映射目标文档的当前节点，避免重开后沿用失效的临时编号；连续打开会等待上一轮阅读事务完成。已经打开的 Markdown 直接激活原标签，包括中央当前显示源码或工具标签的情形。

上次位置独立于窗口的前后跳转历史，保留最近使用的 500 个文件，存入 Typora 当前用户配置中的 Local Storage；不在 Markdown 或仓库中创建状态文件。各文件独立写入，滚动写入合并到 300ms，关闭窗口时提交待写记录。安装、重复安装和恢复扩展不清空阅读记录；清除 Typora 用户数据会清除这些位置。首次安装前尚未记录的位置无法补回。

Markdown 目录自动选中完整进入可读视口的标题，没有可见标题时才回退当前正文所属章节；边缘采用12px缓冲，并将原生延迟回调收敛到同一次同步，避免相邻标题闪动。显式点击目录仍使用原生定位，自动高亮只滚动目录自身。可读视口扣除底栏覆盖区域，供大纲与缩略图共同使用。

正文链接悬停1秒显示目标信息，项目内位置以 `/目录/文件` 表示，百分号编码的中文文件名和标题按可读文字展示。移入提示后可选择文字或复制原始链接，250ms移动宽限避免浮层过早消失；显示和复制不改变文档链接，也不读取目标文件。

每个可见文档右侧提供 **文档缩略图**：按实际正文文字与位置绘制，视口框表示当前可见范围。点击缩略图跳到对应位置，拖动视口框连续定位；聚焦后可用方向键、PageUp／PageDown、Home／End。原生阅读、其他分栏的预览和 `Ctrl + /` 源码模式均支持；操作只滚动所属文档，不改变光标、正文或前后跳转历史。源码模式读取完整 CodeMirror 文本，渲染阅读模式显示已渲染文字，图片与 Mermaid 图形本身不绘入缩略图。每个文档保持一个稳定的前台 canvas；长文先在离屏 canvas 中分帧完成绘制，再一次性提交完整画面。日常滚动只移动视口框，切换侧栏等未改变正文、尺寸或主题的操作不会重绘，因此不会露出空白、半帧或闪烁。

### 1.4.2\_复制文件路径

在 **文件标签** 或 **侧栏文件树的文件／文件夹** 上右键，选择“复制绝对路径”或“复制相对路径”。右键操作以被点中的项目为准，不切换标签、不打开文件、不改变正文光标或阅读位置。命令面板也提供这两个命令，作用于当前活动栏的文档。

| Windows 快捷键 | 结果 |
| --- | --- |
| `Ctrl + K`，松开后按 `P` | 复制活动文档的绝对路径 |
| `Shift + Alt + C` | 复制活动文档的绝对路径 |
| `Ctrl + K`，再按 `Ctrl + Shift + C` | 复制活动文档相对当前打开文件夹根目录的路径 |

这些键位对应 [VS Code 默认文件命令](https://github.com/microsoft/vscode/blob/main/src/vs/workbench/contrib/files/browser/fileCommands.ts)。文件身份在工作区内部始终以结构化路径字段传递，不从显示文本、URL 片段或文件名后缀反推；展示和复制时才按当前系统格式输出。Windows 使用反斜杠，Linux 使用正斜杠，保留中文、空格、`#`、`%`、方括号和复合后缀，不额外加入引号或 Markdown 转义。普通 `Ctrl + C` 继续复制正文选区；分栏快捷键仍保留对应实现。原生菜单 accelerator 冲突尚未验证：renderer 目标与隔离原生夹具的合成按键不等于物理键盘验证，不声明这些键位已全部实机通过。

相对路径的基准是 **Typora 当前打开的文件夹**，不是正在编辑的 Markdown 所在子目录。例如根目录为 `notes`，文件为其中的 `rcu/example.md`，Windows 下复制结果为 `rcu\example.md`。未打开文件夹或文件位于根目录之外时返回完整路径；根目录自身的相对路径为空，与 [VS Code 的路径标签规则](https://github.com/microsoft/vscode/blob/main/src/vs/base/common/labels.ts) 一致。切换文件夹后立即使用新的根目录。尚未保存、没有文件路径的文档不执行复制。

### 1.4.3\_全部文件与语言识别

资源管理器的文件夹整行都可单击展开／折叠，名称和行尾空白同样有效；读取中会立即显示展开状态，仍可再次折叠。单击文件立即打开；已经单独选中的文件或文件夹，再双击该行进入重命名，也可使用 **F2** 或右键菜单。首次双击未选中项只打开／展开一次；搜索中的双击仍用于打开文件。详见[文件行交互](../docs/file_operations.md#r028-文件行的单击双击与加载反馈)。根目录标题右侧提供 **新建文件、新建文件夹、刷新、全部折叠**，目录右键也可新建；名称输入按 Enter 确认、Esc 取消；新文件创建后默认打开并渲染。树获得焦点时，Ctrl／Cmd+C、X、V 分别复制、剪切和粘贴文件，Delete 打开移到回收站的确认框；取消不改磁盘。回收站失败会显示错误，不降级为永久删除。Ctrl／Cmd 单击可增减选择，Shift 单击选择连续范围。

资源管理器按普通目录层级展示，不启用紧凑目录链，也不提供追加的 Open Editors 区域。左侧独立 **大纲** 按钮按活动文件显示 Markdown 标题或代码符号，资源管理器底部不复制大纲节。C/C++仅通过clangd分析，其余五种支持语言使用离线语法；可执行文件、项目编译数据库及后备参数从[解析环境设置](../docs/source_outline.md#配置入口)配置，保存到工作台用户数据，不写入工程。

文件操作只作用于当前工作区，拒绝根目录、符号链接路径、非法名称与同名覆盖。当前文件剪贴板只在本工作台内共享；同目录复制不会自动生成副本名称，新建名称也不接受多级路径。复制失败会回退本次创建的条目；若其他进程替换条目或向新目录加入文件，保留无法安全回退的内容并报告路径。Node 路径接口没有跨进程目录句柄锁；回收站批次也不支持原子撤销，部分成功会明确列出已回收项目。跨设备移动失败会保留错误，不偷偷转为复制后删除。

资源管理器中，选中文件或文件夹后按 **F2**，或者右键选择 **重命名**，可直接编辑名称；**Enter** 确认，**Esc** 取消。只允许修改当前父目录下的名称，不将名称输入当作移动路径；同名目标、非法名称、工作区根目录和符号链接路径会明确拒绝。目录改名同步其中已打开标签的路径，保留源码草稿、撤销记录和阅读位置；搜索列表重新刷新。磁盘内容同时变化时保留草稿并提示核对，不能将未保存内容偷偷替换为磁盘版本。

资源管理器显示文件夹中的全部项目，包括点开头的隐藏文件、隐藏目录、无扩展名文件、源码、归档和二进制文件；语言规则只决定打开后的显示方式，不作为文件树过滤条件。文件夹展开时才读取下一层，列表按可见区域绘制。打开文件／文件夹统一使用系统选择窗口。工具栏、右键菜单与快捷键共用文件服务，提供新建、剪切／复制／粘贴、回收站删除、目录搜索、所选目录终端、文件比较和系统定位；具体行为及缩进依据见[文件操作](../docs/file_operations.md)。

普通打开 `.md`、`.markdown`、`.mdown`、`.mkdn`、`.mkd` 进入 Typora 的 Markdown 渲染与编辑；双击搜索结果也使用该视图，并按行列定位及选中命中内容。其他文本在独立的 **单栏 Monaco** 标签中占满所在编辑组，随分栏宽高调整，提供编辑、行号、语法高亮、查找及缩略图。明确打开 Markdown 源码时才使用源码标签，保存后可通过 **打开 Markdown 渲染** 返回原生视图。文件类型只决定解析与渲染方式，文件身份仍使用结构化绝对路径；空格、`#`、`%`、方括号和复合后缀不会参与路径拆分。Git 历史、双栏差异与搜索侧预览保持只读。

| 源码编辑操作 | 行为 |
| --- | --- |
| `Ctrl + S`／macOS `Cmd + S` | 保存当前源码标签；右键也可选择 **保存文件** |
| `Ctrl + F` | 在当前文件内显示查找框；关闭后回到正文，工作区搜索仍使用 `Ctrl + Shift + F` |
| 全局底部行列位置和未保存标记 | 显示当前活动源码标签，随光标、输入与保存更新，标签上的圆点表示有未保存修改 |
| 全局底部语言模式 | 选择当前源码的高亮语言，不改文件名或后缀 |
| 全局底部编码／行尾序列 | 选择当前源码的 UTF-8、带 BOM 的 UTF-8、UTF-16LE／BE，以及 LF、CRLF 或 CR；按保存后才写入磁盘 |
| 右键 **从磁盘重新加载** | 有草稿时先确认丢弃；没有草稿时重新读取磁盘 |
| 关闭未保存标签或窗口 | 选择保存后关闭、不保存关闭或取消，保存失败时保留编辑内容 |

每个源码标签保存自己的语言模式、编码和行尾选择，切换文件不会沿用另一份文档的格式。切到其他标签再回来保留草稿；拖动到其他编辑组、通过标签右键分栏移动时，原编辑模型及其草稿、撤销栈和选区随标签移动。关闭非活动源码标签同样处理未保存修改，实际关闭后释放该标签，避免已丢弃的草稿继续阻挡其他文件操作。

行列、编码、换行和语言控件只显示在窗口唯一的全局底栏，点击另一个编辑组后随活动源码切换；各分屏不再分别占一条底栏。Git Diff 显示最后聚焦一侧的行列、语言、换行及只读状态，不提供历史版本的格式写入。切到原生 Markdown、提交图或终端时撤下此前源码的控件，避免把后台文件状态误认为当前文档。若 Markdown 的源码标签仍有未保存修改，先处理该草稿再打开原生渲染，不能把磁盘旧内容当成新草稿。

关窗时先处理源码草稿，再交给 Typora 处理原生 Markdown 的保存确认；任一环节取消都保留窗口，下次关窗仍重新检查。保存进行中暂时禁用“不保存并关闭”，可以关闭确认对话框取消后续自动关闭；已经开始的保存完成后不会因此继续关闭标签或窗口。

保存前核对读取时的磁盘字节、文件身份与实际路径；外部修改、替换或移动后拒绝覆盖，保留当前草稿供比较。保存用同目录临时文件替换目标，检查与替换之间仍有外部进程竞争窗口，不承诺跨进程原子比较交换。保存过程中继续输入的文字仍留在编辑器，并保持未保存标记。混合换行默认按原分隔序列保留，新增加的分隔采用原文占比最高的格式；也可明确选定一种行尾格式统一保存。搜索替换会拒绝改写已有未保存源码草稿的文件。

重新加载使用新的候选快照，读取期间暂时禁止输入与修改格式，成功后才一起替换文本和保存基线；读取失败保留已有内容。底部编码菜单另提供 **以编码重新打开**，支持 UTF-8、UTF-16LE／BE、GB18030、Big5 与 Windows-1252；有未保存修改时先处理草稿。非 Unicode 编码可读取，写回前需明确选择支持的 Unicode 编码。

识别顺序是 **特殊文件名／前缀 → 最长复合后缀 → 普通后缀 → 首行解释器 → 纯文本**。例如 `types.d.ts` 先命中 `.d.ts`，`archive.tar.gz` 先命中 `.tar.gz`，`.env.local` 使用环境变量规则，`.C`／`.H` 保留 C++ 的大小写区别。常用映射如下；完整可执行规则集中在 [`src/file_language.ts`](./src/file_language.ts)，不依赖本机 VS Code 文件关联。

### 1.4.4\_工作区搜索与替换

点击活动栏 **搜索**，或按 `Ctrl + Shift + F`，在当前打开的文件夹中搜索磁盘文本。搜索面板使用独立输入区，顶部不会叠加原生“查找”框；紧凑工具栏提供刷新、清除、在编辑器中打开和全部折叠，查询框内切换匹配选项，包含／排除框右侧切换搜索范围与忽略规则，图标均有中文提示。

结果按文件分组，显示文件图标、名称、相对目录、匹配数、Git 状态与高亮片段；行列位置放在悬停提示和可访问标签中，不再单独占一列。每条结果同时保留结构化绝对路径、相对路径和精确起止行列，显示名称只用于界面呈现，不再参与文件解析。文件分组和目录整行单击可折叠／展开，移除按钮独立，可切换列表／树形显示，按路径／结果数排序，也可通过结果统计旁的 **在编辑器中打开** 展示完整结果。单击文件或片段在搜索结果下方预览；双击或 Enter 在编辑区打开文件，使用结构化路径和起止行列定位精确匹配，Markdown 使用原生渲染。右键可在右侧打开、复制匹配行或路径。文件组悬停时可 **从结果中移除**，它只更新本轮结果，不删除磁盘文件。

| 控件 | 行为 |
| --- | --- |
| 区分大小写／全字匹配／正则表达式 | 控制匹配方式；全字匹配识别 Unicode 字母、数字与下划线边界，正则使用 JavaScript 语法 |
| 包含的文件／排除的文件 | 使用 `/` 分隔路径，逗号分隔模式；支持 `*`、`**`、`?`、字符类及 `{c,h}`，例如 `src/**, *.md`；`./` 指定根目录起点 |
| 使用 .gitignore 和默认排除设置 | 默认开启，使用 Git 的标准忽略规则及默认排除设置；关闭后仍保留显式包含／排除条件，实际跳过情况在范围说明中展示 |
| 仅搜索源代码管理中的更改文件 | 从当前文件夹所属仓库取得已暂存、工作区更改及未跟踪文件，搜索其当前磁盘内容；仍应用包含／排除及忽略规则，已删除文件没有正文可搜索；非仓库给出说明 |
| 仅搜索已打开的编辑器 | 限定为当前工作区已打开的文件，仍读取磁盘版本；与“仅搜索源代码管理中的更改文件”互斥 |
| Enter／Shift + Enter／Esc | 立即搜索／在查询中换行／停止当前搜索；输入后也会延迟搜索 |
| 替换／保留大小写 | 支持单条、单文件和全部结果的替换预览；正则替换可引用捕获组，保留大小写按匹配文字调整替换文本 |

替换先显示涉及文件、匹配数和 **替换前／替换后** 双栏预览，点击 **确认替换** 才写磁盘。应用前重新核对原始字节、文件身份和未保存文档；搜索后磁盘内容变化、路径越界、符号链接／硬链接或相关 Markdown／源码标签尚未保存时拒绝写入，要求处理后重新搜索。仅支持能够保持原编码的 UTF-8、UTF-16LE／BE 替换，并保留 BOM；其他编码不能保证无损时只允许搜索。搜索取消或达到上限后，不执行整文件／全部替换，可重新缩小范围。多文件替换不是跨文件原子事务，错误会报告已完成范围，不承诺外部程序并发写入时的事务隔离。

默认最多显示 5000 个结果，单文件搜索上限为 8 MiB，匹配文件快照总量上限为 64 MiB。二进制、过大、不可读、链接及被排除的项目会计数或提供范围说明；文件树中可见不表示每个文件都适合文本搜索。当前搜索不使用 VS Code 扩展搜索提供器；它与代码大纲的 clangd 语义分析独立。文件名扫描和评分按时间片让出界面；内容扫描最多预读4个文件，侧栏随匹配分批显示。大目录可先使用已发现的结果，新查询和切换工程会使旧任务失效；具体限制、基线和性能测量见[大目录搜索性能与验证](../docs/search_performance.md)。

普通文本与正则匹配均在独立 Worker 中执行，单文件预算为 2 秒；点击停止或按 Esc 会终止当前 Worker，避免匹配持续占用界面线程。超时会注明对应文件，并拒绝这一轮的全部替换，包括单条替换；简化表达式或缩小范围后重新搜索。取消与超时均不会写磁盘。

### 1.4.5\_活动栏与侧栏布局

本轮按用户新要求恢复35px单行顶栏：左侧保留 Typora 七类菜单并在帮助之前增加终端菜单，中间为后退、前进和文件搜索，右侧复用宿主窗口按钮。菜单由本地 renderer 组织，只调用已核对的 Typora API，不使用整棵 `Menu.popup` 或修改 ASAR；能力与动态状态以实际接线为界，不声称完整原生菜单等价。菜单在顶栏下方按可用高度滚动，支持 Shift+滚轮。 保存文档并正常重启后加载窗口模式，安装不强制关闭现有窗口。

活动栏为 **48×48px 连续项目**，不使用 Modern 的36px胶囊和项间8px留白；文件、搜索和 SCM 官方图标使用24px画布，大纲保留原生 `fa-list` 字体图标。选中状态跟随当前展开的文件、搜索、大纲或源代码管理；点击当前入口收起，再次点击打开。

主侧栏正文最小宽度为 **170 CSS px**，48px 连续活动栏另外计算。继续向左拖动，鼠标请求宽度低于 85px 时自动收起；拖回 85px 及以上展开，松手后再次点击功能图标恢复拖动前的有效宽度。最大宽度会为中央编辑区保留 220px，并扣除当前活动栏和右侧面板；窗口缩放不覆盖已记住的用户宽度。文件、搜索、大纲和源代码管理使用相同分界线，搜索预览位于搜索面板内部。

聚焦侧栏分界线后，左右键每次调整 10px，按住 Shift 调整 50px；Home 调到最小宽度，End 调到当前最大宽度，Enter 收起／展开，收起时右方向键恢复。

按住上方功能图标纵向拖动可以排序，顺序保存在当前 Typora 用户的 Local Storage；设置及底部终端保持固定区域。右键 **上移／下移** 或聚焦图标后按 `Alt + ↑ / ↓` 可用键盘调整，方向键移动焦点、Enter 激活。拖动排序和颜色变化具有过渡效果，系统启用“减少动态效果”时关闭这些动画。

原生文件树底部工具条移到全局右下状态栏，保留原有菜单事件，并清理与活动栏重复的入口；侧栏不再为它占位，搜索结果和预览可以使用完整高度。Git 状态保留在左下，当前活动源码的行列、编码、换行和语言设置显示在同一条全局底栏。提交图收起后保留完整标题行，小窗口、界面缩放、长提交消息与多文件列表使用各分区内部滚动，不把标题挤到侧栏底部之外。

大纲移除最外层重复的 18px 左右留白，保留标题自身逐级缩进、折叠和点击跳转；悬停也不把行挤出侧栏。打开大纲或宿主重建标题列表后，会立即根据当前正文可见位置选中对应标题、展开其祖先并把该项滚入大纲视口；同步大纲时不改变正文滚动位置。大纲上方不再提供原生过滤框及其关闭按钮，进入工作区时清理旧过滤状态，恢复被过滤的标题；搜索集中到搜索面板，切换侧栏不会把原生“查找”框带到那里。正文目录弹层的布局保持原样。

### 1.4.6\_选中文字的跳转预览

选中文字后，按住 **Ctrl 并点击鼠标左键**；macOS 使用 **Cmd 加鼠标左键**。选区文字填入同一个 **搜索** 面板，与手动输入共用范围、结果和下方预览；活动栏不再提供单独的预览图标。无论命中一个还是多个文件，都先保留结果列表，不自动打开文件；没有结果时显示查找状态。

| 操作 | 结果 |
| --- | --- |
| 单击文件或匹配片段 | 在搜索结果下方预览，不切换中央文档 |
| 双击匹配片段 | 打开对应文件，定位起止行列并选中匹配内容 |
| 双击文件 | 打开该文件的当前命中；尚未选择命中时使用首条 |
| 单击预览标题的折叠按钮 | 收起／展开下方预览，收起后结果列表使用释放的高度 |
| 拖动结果与预览之间的分界线 | 调整上下区域高度，结果和预览分别滚动 |
| 直接拖动预览栏右侧的百分比滑块 | 以 50%～150% 调整预览内容大小，默认 80%，在当前用户本地持久化，无需打开设置 |
| 预览内容内 Ctrl／Cmd 加鼠标滚轮 | 每次调整 5%，与栏内滑块共用范围及持久化比例，不缩放中央文档 |

搜索标题只出现在侧栏顶部。下方预览使用一行独立标题栏：左侧的 **预览** 文字本身就是收起／展开按钮，不再放置重复的预览功能图标；右侧直接显示缩小、比例滑块、百分比和放大控件。滑块、按钮和 Ctrl／Cmd 加滚轮同步更新同一个比例。

预览中，Markdown 按当前主题渲染标题、段落、列表和表格，代码围栏按语言着色，其他文本按语言映射显示只读 Monaco 源码；特殊文件名、复合后缀与解释器规则见 [全部文件与语言识别](#1.4.3_全部文件与语言识别)。预览读取搜索结果携带的结构化文件路径，不把空格、`#`、`%`、方括号或多段后缀解释为分隔符。命中映射统一处理 CRLF 与解析器展开的行首制表符，避免前面的代码块使后续位置偏移；改变侧栏状态也不会重置预览滚动。缩放以当前正文的实际字号为基准，同时调整 Markdown 和源码内容，不改变面板宽高或中央文档字号。预览自身可以上下、左右滚动，滚动与缩放不会移动中央文档。

侧预览只读取 2 MiB 以内的文本，过大或二进制文件显示原因，仍可双击结果打开完整文件。Markdown 预览净化 HTML，不加载文档中的图片或其他媒体，链接只显示文字。Mermaid 使用 Typora 随附的本地库，在预览独有的 iframe 内渲染；图表主题与指令不改变中央正文的实例配置。不支持或错误的图表保留源码，命中图表源码时额外显示对应源码选区，以便准确定位。

双击打开前会复查磁盘上的命中位置；Markdown 再核对原生编辑器内存中的文本，其他源码核对 Monaco 当前缓冲区。内容变化时明确要求刷新，避免选中错误位置。Markdown 原生标题、普通段落和围栏均保留对应显示方式；无法安全表示的跨编辑区选区会报告原因。

面板复用工作区搜索的包含／排除 glob、区分大小写、全字匹配、正则及忽略规则；文件范围与资源上限见 [工作区搜索与替换](#1.4.4_工作区搜索与替换)。改变查找范围后重新显示结果，文件类型继续使用同一套映射。单击更新下方阅读预览，双击或 Enter 在编辑区打开文件；已有同名文本的不同文件都作为候选展示。

这里查找的是 **工作区磁盘文本的出现位置**，不是编译器或语言服务器解析出的定义、声明或引用关系；例如同名函数、注释与说明文字都可能命中，需要读者通过预览判断。该面板用于阅读定位，不接入聊天或生成内容。

普通安装已包含预构建实现，无需额外 Node.js。Git 默认从 Typora 进程的 PATH 查找，也可在图内本地设置中指定可执行文件。安装器不写固定路径、不修改系统 PATH。配置检查报告 `git_graph_features` 和 `git_graph_runtime`，并要求主侧栏、Monaco 差异等完整功能标记、发布摘要和常驻核心资产均一致。缺少 Git 时图内提供提示，其他阅读增强仍可使用。

中央提交图按经典 Git Graph 的密度和信息顺序排布：单行工具栏含边框高 **41px**，五列表头高 **31px**，提交行与图轨道高 **24px**；顶端使用一行分支筛选、远端分支开关与右侧图标操作，正文固定为 **Graph、Description、Date、Author、Commit** 五列，引用标签放在说明之前。单击提交后，详情紧跟在所选行下方，左半显示提交信息，右半显示更改文件，最右侧使用 32px 图标栏切换文件树／列表及执行相关操作。详情默认跟随提交行，可在设置中改为底部停靠；表头列宽仍可拖动并按仓库保存。工具栏20px动作、18px普通图标与详情24px按钮、20px图标按角色区分；中央Graph采用扩展的专属几何，SCM侧栏仍为22px行高。


### 1.5.1\_主侧栏与中文菜单

源代码管理与文件树、大纲共用左侧原有区域。点击当前展开功能的图标收起侧栏，再点打开；点击其他功能直接切换内容。底部不再显示重复的“显示／隐藏侧边栏”按钮，拖动原有侧栏分界线调整宽度。

源代码管理标题区高 **35px**，提交消息框高 **30px**，提交按钮高 **26px**；按钮下直接排列暂存与更改分组，不保留额外文件筛选框。视图标题与文件行高 **22px**；两个资源分组使用13px常规字重和各自16px官方折叠箭头，空组同样可切换。整体更改与提交图标题箭头同列，提交按钮图标继承白色。文件采用官方通用图标，状态列16px；行内操作在悬停、选中或聚焦时显示；独立占列并使用不透明行背景，名称省略不穿透图标。

Git Graph 界面文案通过受类型约束的键成对提供简体中文和英文；根据显式工作台语言或 Typora 的 appLocale选择界面语言，面板、源代码管理、提示、菜单、设置、确认框与错误消息一起切换。分支名、提交号、路径、Git 参数和用户输入保持原值，不进行翻译。

文件只分为 **暂存的更改** 和 **更改** 两组，新文件与冲突文件放在“更改”中，通过行内状态区分。同一文件同时存在已暂存和未暂存修改时，会出现在两个对应分组中：点击暂存文件比较 HEAD 与暂存区，点击普通更改比较暂存区与磁盘工作区。首次提交和新文件使用空文件作为左侧基准。

文件行上的 `+` / `−` 和右键的暂存／取消暂存直接执行；分组按钮只处理本组文件，重命名操作同时处理原路径和新路径。提交消息框中 `Enter` 换行，`Ctrl + Enter` 与点击 **提交** 一样，只提交已暂存内容；空暂存区不会自动暂存文件。成功后清空消息，失败时保留消息并显示错误。消息框随内容增高，右侧下拉提供提交选项和修改上一次提交。

“更改”分组的回退按钮打开 **放弃所有更改**，先列出本组的精确文件，确认后将已跟踪文件恢复为暂存区版本；未跟踪文件默认移入系统回收站，也可取消勾选、只放弃已跟踪文件。文件右键 **放弃更改** 使用同样流程，但只处理所选文件。暂存内容不变，预览后文件发生变化则要求重新预览；回收站失败不会转成永久删除。

新文件在“更改”中显示 `U`，点击 `+` 或右键 **暂存更改** 后进入暂存区。右键 **添加到 .gitignore** 在仓库根文件中追加该文件的精确路径规则，保留原有规则和磁盘文件，不自动暂存 `.gitignore`。已跟踪文件不提供这一忽略入口，避免把“忽略”变成暗中移除索引。

源代码管理下半区默认展开 **提交图**，直接显示真实提交连线、引用和历史；点击提交展开该次修改的文件，点击文件在中央打开差异，提交与文件均支持右键操作。拖动上下分区之间的分界线调整高度。提交图标题栏的打开按钮可进入中央完整提交图标签，提供筛选、比较和详情布局；中央图不再复制活动栏和源代码管理栏。

侧栏历史使用 11px 轨道间距、22px 行高；每行按当前仍存在的轨道计算图形宽度，较早的多分支不会给后续单线提交留下大块空白。提交前不再另占展开箭头列，展开后直接列文件，不增加一行文件总数。文件行有文件图标和对齐的状态；提交说明优先显示，引用使用带图标的彩色圆角标签，当前引用突出显示，过长名称省略。

顶部省略号勾选 **仓库／更改／提交图** 的显示；“更改”标题旁省略号提供 Git 操作。提交图标题栏提供分支范围、定位当前提交、获取、拉取、推送、刷新与更多，窄栏把网络动作收进更多菜单。提交图文件可切换 **以列表显示／以树形显示**，目录可折叠；更改列表支持按名称、路径或状态排序。文件行的操作槽、状态列固定，悬停不改变列位置。SCM 文件提供打开、丢弃和暂存操作；差异视图可通过打开文件按钮回到文件。

底部左侧状态栏显示当前分支、未提交标记 `*`、上游领先／落后计数和提交图入口。点击分支选择检出目标，右键管理当前分支；点击同步由共同命令解析当前分支与上游，唯一目标直接先拉取、再推送，拉取失败或冲突时停止，没有待推送提交则跳过推送。无上游时显示发布图标，按已配置远端解析发布目标；存在多个候选时选择一次。同步入口右键另提供获取、拉取、推送和远端配置。状态刷新只访问本地 Git。Git Graph 标签使用分支图标，入口复用已经打开的仓库标签。

省略号与侧栏右键菜单使用中文，按 **视图与排序、提交、更改、拉取与推送、分支、远端、贮藏、标签** 分组，提供克隆、检出、Git 输出、提交图、仓库终端及管理员终端入口。分支、远端、贮藏和标签子菜单使用仓库真实对象。鼠标悬停或 `→` 展开子菜单，`←` 返回，`↑` / `↓` 移动，`Esc` 关闭。文件右键提供打开更改、打开文件、时间线、路径复制、文件资源管理器定位、暂存和放弃更改；文件树中的普通文件也可直接打开所属仓库历史与更改。

### 1.5.2\_中央差异编辑器与文件时间线

单击变更文件直接在原有编辑标签栏打开 **Monaco 0.56.0 差异编辑器**。前后改动、打开版本／文件、查找和更多使用16px图标、24px按钮，放在所属编辑组的标签行右侧；切换标签时同步该组动作。标签下方只保留26px高、13px字体的版本路径行。左右并排时分别显示旧、新版本；内联时同一行显示旧版与新版及模式入口，正文使用单列差异。

默认启用 **空间不足时使用内联视图**：实际差异编辑器宽度不超过900 CSS px时内联，超过900 CSS px时恢复左右并排；拖动所在编辑组的分界线即可触发，不按整个窗口宽度或百分比判断。**内联视图** 是独立的手动选项，选中后即使组变宽也保持内联；自动窄幅选项可以单独开关。左右分栏的默认比例0.5仅决定两版各占一半空间，中间分界线仍可拖动。模式切换保留选择与滚动位置。来源见[VS Code设计基线](../docs/vscode_design_baseline.md)。

两种模式都显示完整源码、行号和语法高亮，删除、新增及行内变化分别标色。左右并排时空缺行自动对齐，两栏各保留8px窄竖向滚动条并同步纵向滚动，横向滚动独立。Monaco原生差异概览占30px，两个15px区域分别标记删除和新增，点击可定位改动。Git差异关闭全文缩略图；普通单文件源码及单版本查看继续提供可点击、拖动的缩略图。

标签行 **更多** 菜单集中内联模式、空间不足时内联、隐藏未修改区域、显示移动代码块、忽略首尾空白和无障碍差异查看器；前后文件、刷新差异、切换主侧栏也在此处保留原操作。`F7`／`Shift + F7`进入并向后／向前阅读无障碍差异，普通前后改动使用标签行箭头。差异右键另提供复制、全选、查找、自动换行和所选文件的Git操作。`Ctrl + F`由差异编辑器处理，Monaco查找提示使用中文。相同文件及版本组合复用标签，刷新内容保留查看位置；分栏、关闭与拖动使用工作区原有标签菜单。各层验证结果统一见[反馈复查记录](../docs/feedback_review.md)。

**文件历史（时间线）** 是单独的编辑标签。它按文件显示提交，沿重命名前的路径继续追踪；单击历史记录比较该次提交前后的文件。首次添加与删除分别显示为空左侧、空右侧。历史源文件保持只读，当前工作区差异也用于审阅；修改正文请用 **打开文件** 返回 Typora。当前未提供选中行暂存、三方合并编辑器或在差异右侧直接保存文件。

Monaco 的代码、简体中文界面、图标和浏览器 Worker 全部内嵌在预构建 bundle，运行时无需 CDN，也不要求另装 Node。它与 Typora 正文中的 TextMate C/C++ 代码围栏高亮属于两个独立编辑表面。

## 1.6\_集成终端、管理员入口与分界线

点击底部终端图标或按 **Ctrl+`** 显示／隐藏底部面板，隐藏保留 Shell 与输出；**Ctrl+Shift+`** 新建终端。普通新建使用当前工作区目录，Explorer 右键入口使用所选目录，明确标注“仓库根目录”的 Git／原生文件入口才查询 Git 根目录。

面板具有紧凑图标工具栏、会话列表、拆分／合并、重命名、颜色／图标、查找、清屏、重启和终止。拖动上边界调整高度，支持最大化／还原；可以将同一会话移动到编辑器再移回，保持原 PTY 与 xterm。主题变更只更新显示，不清空输出或重启进程。

**Ctrl+Shift+C / V / F** 分别复制、粘贴和查找；普通 Ctrl+C 无选区时发送中断。粘贴多行前展示内容确认，终端焦点中的正文快捷键交给 Shell。设置支持自定义 Shell 参数、项目相对工作目录、环境变量，以及字体、光标、滚动、列表位置和输入行为。完整入口、配置示例和未实现差异见[终端操作与配置](../docs/terminal_operations.md)。

终端使用 [xterm.js](https://github.com/xtermjs/xterm.js) 和 [node-pty](https://github.com/microsoft/node-pty/tree/1.1.0)。终止会话或真正关闭宿主窗口时回收进程，关闭 Typora 后不恢复旧进程及缓冲。**管理员终端（UAC）** 通过系统提权启动独立 PowerShell，普通集成终端和 Typora 本身不提权；自动验证不执行管理员授权。

只读历史双栏、源代码管理侧栏的更改／提交图分区，以及工作区编辑组继续使用各自的可拖动分界线。中央 Git Graph 默认将详情放在所选提交行下，保留已有可选底部停靠；五列表头边缘可直接调整各列宽度，表头右键提供 **重置五列宽度** 和完整设置入口。

Git Graph 的提交、分支、远端、标签、stash、未提交行、变更文件和空白处菜单均提供 **配置此右键菜单**。勾选决定显示项，修改立即保存在当前仓库配置中；`hidden_actions` 中 `commit:branch_create` 表示只在提交菜单隐藏该项，单独的 `branch_create` 表示全局隐藏。配置入口始终保留，避免隐藏全部操作后无法恢复。

## 1.7\_终端运行文件、安装与验证

Windows 集成终端要求 Windows 10 1903 或更新版本、x64 或 ARM64。已在 x64 Typora `1.14.9` 实测，ARM64 运行文件来自上游预构建，尚未完成 ARM64 实机验证。

安装器通过系统环境发现 Typora 和用户目录。前端依赖锁定为 xterm.js `6.0.0`、FitAddon `0.11.0`、SearchAddon `0.16.0`；node-pty `1.1.0` 的原始 JavaScript、MIT 许可证与 Windows Node-API 模块保存于 `dist/terminal_runtime/`，由 `scripts/build_terminal_assets.mjs` 从锁定 npm 包生成并附 SHA-256 清单。安装器不编译本机模块，不下载或复制已安装 VS Code 的私有文件。

独立后台运行时固定为 Node `24.20.0`，官方来源与 x64 / ARM64 ZIP、可执行文件摘要见 [运行时清单](./node_runtime.json)；来源为 [Node 官方发行目录](https://nodejs.org/dist/v24.20.0/)。首次配置下载约 38 MB 的架构对应 ZIP，校验后只提取 `node.exe` 和 `LICENSE`。运行文件安装到 Typora 用户数据中的 `linux_note_enhancements/terminal_runtime/`，不依赖系统 Node，不修改 PATH。离线环境可把相同官方 ZIP 放进 `TYPORA_TERMINAL_CACHE` 指向的目录；默认缓存通过系统本地应用数据目录发现。缓存和提取文件仍须通过摘要校验。

Typora 编辑页不支持 node-pty 的后台排空线程，因此每个会话使用独立的 Node 后台进程，通过 IPC 传递输入、输出和尺寸；输出采用确认与暂停机制限制积压。标签切换不销毁进程；进程断开 IPC 或收到关闭命令后清理伪终端。运行文件与 bundle、工作区核心一起校验、备份、安装和回滚。安装保留阅读位置、Git 评审与已有产品设置；旧插件冲突在写入前预检，不承诺并行运行。

`test_terminal.mjs` 验证真实后台进程、特殊字符工作目录、输入输出、尺寸、退出、环境隔离和 UAC 命令编码。`test_terminal_interaction.cjs` 用隐藏 Electron 发送真实鼠标与键盘，验证输入、方向键历史、Ctrl+C、复制、查找、菜单及窗口缩放。`test_reading_native.ps1 -suite terminal` 则在临时仓库的真实 Typora 窗口中检查会话、切换、分栏与回收；`-suite git`、`-suite reading` 和 `-suite paths` 继续检查原有功能。管理员 UAC 的人工交互和 ARM64、原生 Linux 环境不在已通过的自动验收范围内。


部署验证入口：`scripts/test_install_windows.ps1` 在假安装树与隔离 APPDATA 检查安装、重装、摘要损坏拒绝、迁移、恢复及失败回滚；`bash scripts/test_workspace_install.sh` 检查 Bash／Python 事务与模拟 Linux 分支。schema 4 覆盖 native_profile 编码拒绝、字段恢复、并发摘要冲突、退休资产备份恢复与失败回滚。Windows 上执行的 Python 测试不能替代原生 Linux 的权限与发现验证。

当前结果、安装核验和历次基线统一见[反馈复查记录](../docs/feedback_review.md)。物理键盘与原生菜单 accelerator 的冲突仍需独立验证；隐藏 Electron 或私有原生实例中的合成按键不证明这一层已通过。完整平台与交付信息见[开发交接](../docs/development_handoff.md)。

工作台菜单、活动入口、文件标签、Git、文件管理、搜索和终端共用默认悬停及键盘焦点反馈，特殊控件保留自己的大小、形状和业务状态。Git侧栏提交信息使用可移入、可复制提交号的卡片。开发接入与独立覆写见[交互设计](../docs/workspace_interaction.md)。

提交图的操作在悬停或聚焦该行时立即出现；Graph设置中的“提交图行操作始终显示”可改为常显。详情卡片放在完整列表和滚动条之外，采用紧凑排版与指示角。与VS Code内置Graph的默认配置及其余差异见[配置核对](../docs/git_graph_configuration.md)。搜索下方预览在手动滚动后，重选同一结果会回到原匹配位置，不重新打开中央文档。


## 图片与图表放大查看

Markdown正文及历史阅读中已显示的图片，鼠标悬停时在图像外侧右上方显示“全屏查看”，小图显示同一全屏图标。按钮不占正文行高，挂载与悬停均保持图片和前后段落的原有间距；移出后隐藏，键盘聚焦时也显示。浮层随原图定位并滚动，图片与Mermaid采用相同的入口布局和样式。也可直接双击图片打开大图，单击仍用于选中图片。打开后可放大、缩小、拖动、适应宽度／屏幕或恢复100%；Ctrl+滚轮缩放、Esc退出并恢复打开前的光标／选区，可直接继续编辑；从键盘入口打开则返回入口。图片默认完整适应屏幕，小图保持自然大小。Mermaid与图片共用查看器。

`reading_image_viewer.ts`负责图片来源，`reading_media_entry.ts`与`.css`统一管理图片和Mermaid的入口；按钮保存在正文外，不插入流内占位或图片包装。`reading_media_viewer.ts`统一管理副本、缩放、焦点、主题和关闭。图片格式及来源遵循现有阅读器，搜索预览仍不加载图片。设计和回归见[图片与图表放大查看](../docs/reading_media_viewer.md)。

最近项目：文件菜单的“打开最近”按目录/文件分组显示完整路径，Ctrl+R筛选和移除单项；清空前确认，仅清历史。确定已失效的项目在选择时移除，离线或权限失败保留，详见[最近打开设计](../docs/recent_open.md)。

## 按提交更新与安装权限

当前本机候选2026.09.21.4（未推送）；代码块按各自宽度和可见性更新原生高度测量，避免展开长代码后短代码保留大块留白；路径搜索不再等待显式路径stat后才显示已枚举结果，扫描增量和迟到请求按查询隔离；终端末行留白纳入行数计算，面板/分屏/编辑器统一避免缩放后裁切；共享弹窗右上角×关闭，底部操作统一右对齐；帮助菜单检查、下载、校验和安装更新使用共享进度条；已知下载总量时显示百分比，未知总量持续活动并显示实际下载量。检查可取消重试，关闭安装进度后可再次查看；后台检查复用同一请求，完成后展示结果或失败原因。Windows更新使用GitHub提交API与固定SHA的ZIP，不要求本地Git、`.git`或仓库历史。下载/解压放在Typora用户数据的`temp`，成功后才记录提交身份，同序号新提交仍可更新；立即安装后手动重启。安装按实际待写目标检查权限，可写目标不提权，受保护入口解释原因并请求一次系统授权，取消保留原安装。配置和备份仍由标准安装事务管理，详见[更新设计](../docs/workspace_update.md)及[安装权限](../docs/installation_design.md#r063-windows权限预检与按需授权)。

提交详情浮层与菜单共用GitHub/Gitee/GitLab/Bitbucket网页识别，多候选一次选择；无远端、本地或未知托管平台不生成猜测的提交URL，详见[提交网页](../docs/git_commit_web.md)。

跨窗口移交验收使用 `scripts/test_drag_windows_native.ps1`：独立原始宿主显式启用恢复上次文件，已保存/未保存源码与Markdown各20轮拖出/合并，每类10轮合并到已有同文件目标、10轮回到空目标；检查附窗仅有指定文件、无模态/失败通知、源磁盘不变及空附窗实际退出。普通重开恢复单独使用 `scripts/test_workspace_sessions_native.ps1` 验证第二进程读取磁盘记录。原生输入为renderer事件，物理跨屏输入仍需现场复核。详见[拖动设计](../docs/drag_and_windows.md#r0052-拖放直接执行与非模态反馈2026-09-20)。

终端往上翻阅时旧输出消失通常涉及滚动历史容量：代码默认1000行，可在终端设置调整到100000行；调大不能恢复已淘汰内容。它由xterm缓冲管理，不是面板高度限制，资源影响与已核对边界见[终端滚动历史说明](../docs/terminal_operations.md#r006-滚动历史容量与旧日志消失2026-09-21)。
