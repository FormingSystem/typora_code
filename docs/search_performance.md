## 当前行为

2026-09-20由 [R058文件快速打开](quick_open.md) 替代文件名匹配部分：固定VS Code评分/排序与高亮，最多4目录并行、约8ms分片，完整枚举不再以50000文件截断；只保留前512项匹配并绘制可见行。关闭、切库或新查询使旧计算失效。以下2026-09-10的100项与50000候选记录是历史对照，当前行为以R058为准。

内容搜索最多预读4个文件，保持原来的确定遍历顺序和逐文件身份检查。浏览器中，普通查询与正则均由每轮复用的一个 Worker 建立行索引、计算位置与匹配；文件系统异步读取可与此 Worker 并行。文件解码、范围规则和替换授权仍在宿主。没有匹配的文件不再预先建立完整行索引。每文件匹配超过2秒或取消时终止 Worker；超时结果保持不完整状态，不能据此执行替换。

侧栏随匹配逐文件增加结果，约80ms更新一次进度；大批量 DOM 创建每64条或约8ms让出事件循环。普通搜索的 Git 装饰与内容扫描并行；只有“仅更改文件”的搜索范围必须等待 Git 状态。`.gitignore` 所需的 Git 文件清单仍须先取得，不能为提速跳过忽略规则。新查询、停止、目录变化和卸载保留异步结果的身份隔离；未完成搜索不能预览替换。搜索、结果预览和本次性能测试均不写正文。

比较基线为 `56222589f2997a6ee2ea0a6ae87d5015f43af63b`。以下为同一台 Windows 机器的一次记录，不是跨硬件性能保证。

最后一行显式插入 `setTimeout(3)`，Windows 定时器粒度会放大实际等待；它验证串行等待被有界并发重叠，不能称为真实硬盘或网络盘测量。暖缓存小文件总耗时基本持平；普通匹配进入 Worker 存在消息和线程启动成本。本次主要改善输入停顿、等待首屏结果以及高延迟读取的吞吐，不声称所有查询都按同一倍数加速。

## 回归与边界

目标回归覆盖真实 Worker 的正则超时／取消、普通查询进入 Worker、Unicode与多行位置、忽略规则、替换私有快照、最多4个读取并发、取消后无新读取或迟到回调，以及50000候选的最新输入胜出、筛选中按 Enter 和关闭恢复焦点。目录边界测试确保已读文件的匹配不会为填满预读队列而等待下一个慢目录。侧栏还验证慢 Git 状态和后半扫描未完成时前半结果可预览、5000条 DOM 创建中改换查询不会残留旧结果，以及列表搜索完成后保留已选结果的 DOM 节点和焦点。

默认5000条内容匹配、单文件8MiB、匹配文件快照总计64MiB的限制保持。预读内存另受并发文件数和单文件上限约束；本次没有改成无限任务队列、全工程正文缓存或持久文件索引。目录树枚举、主线程解码和最终可见节点的浏览器布局仍有成本；计时器与8ms让出点不是实时调度保证，也不代表完整移植 VS Code 搜索后端。
