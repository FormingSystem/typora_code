## Upstream Dependencies and Configuration

- `src/vs/workbench/browser/parts/editor/editorActions.ts` : Windows Alt + Left/Right respectively execute `workbench.action.navigateBack` / `navigateForward`, using unfiltered history, not the recent files list or undo main content.
- `src/vs/workbench/browser/workbench.contribution.ts` : `workbench.editor.navigationScope` defaults to `default`, cross-editor and editor group; there is also `editorGroup` and `editor`. - `src/vs/workbench/services/history/browser/historyService.ts` : The navigation stack has a maximum of 50 items, and recovery does not add new records. New jumps truncate the forward branch, and nearby cursor movements replace the current item. Explicit navigation retains nearby positions.
- `src/vs/workbench/browser/parts/editor/textEditor.ts` : The same source code line is considered the same position. Ordinary movements less than 10 lines are considered nearby; explicit navigation across lines still enters the stack. Rendering Markdown does not have a one-to-one correspondence with screen lines. It uses native block cursors and reading anchors to save positions, and does not guess screen pixels as source code lines.

All the above files are located in the fixed commit's [VS Code source code](https://github.com/microsoft/vscode/tree/645f29cc3176500b4b5762ba887cf2a7f0ffdf2c/src/vs/workbench). No VS Code private code is introduced; it is independently implemented to adapt to the host's capabilities.

## Transactions and Responsibilities

`reading_history` manages records, deduplication, capacity, forward branches, and recovery index. `reading_navigation` manages unique navigation commands, native Markdown entry, lifecycle, and cancellation. The source code editor provides capture and recovery through a public port, saving line numbers, selections, scrolling, and editor group identities, without accessing Markdown cache to impersonate source code state.

Links must capture the source before native changes to the selection or opening the target. The same file title, cross-file title are recorded once after the target is located. Do not use the file opening intermediate state to replace the target. Do not use only listening to cursor changes to infer all jumps. Compatible with the host's real link methods and internal entry, preserving the original behavior of external URLs. Outline clicks use the same starting point protection.

Ordinary source code cursor movements are merged by 10-line threshold. Explicit API localization retains nearby cross-line positions; Markdown selections are distinguished by native blocks, with block internal movements updating the current position, and pure wheel scrolling does not feed into history. During backward/forward, the selection and file events triggered by recovery are shielded. Failed files, canceled opening or localization failures do not submit new history; switching workspaces interrupts old transactions and clears old positions. Returning allows new jumps to clear old forward items; renaming migration paths, closing tabs allow re-opening disk targets.

## View Classification and New Access Agreement

2026-09-23 User requested unified categorization to prevent subsequent functionality from maintaining themes and navigation separately. Categorization is based on the interaction container and resource identity of the view, not on writability, file suffix, or rendering technology.

| Categorization | Instance | History and shortcut owner | The view must provide |
| --- | --- | --- | --- |
| Main editing area resource view | Native Markdown, source code, Git single version, difference comparison | Window unique navigation service, default across editing groups; Alt left and right shared with main top bar | Resource and version identity, group instance, capture/recovery location, necessary to be reopened by the original service |
| Independent preview session | Search, selected links, directory preview and internal web pages | Preview session's own forward and backward history; focus on preview handles Alt left and right | Current target and location, session start/clear, preview internal jump; open original file to main file service |
| Function panel | Settings, Git commit graph, terminal, search result list | Own business choice/input, not fabricating file navigation records | Command parsing resource to file/editor service; do not reuse document content position |

Before adding a new resource view to the main editing area, registration of navigation port and declaration of held resource, version, group, and mode are required; navigation stack only has order, capacity, cancel, and command; domain view has selection/scrolling/presentation status and reopening method. Read-only, Shadow DOM and Monaco do not change categorization. Recovery failure retains index, switch workspaces release old identity, destroy port; prohibit adding another set of global Alt listener or bypassing service by path suffix.

The visual skin of all Markdown reading views is uniformly adapted by `workspace_markdown_theme`, theme/style failure notification is uniformly subscribed, layout and difference/hit color still belong to domain; [R034.3](git_markdown_diff.en.md#section_f1c2e4af19b5) defines actual attribute mapping.
