## 历史处理方案

范围为当前三个本地分支可达的86条提交：64条补充缺失正文，3条将原说明按段落整理成列表，19条已有合规列表原文保留。依据每条提交的实际差量、同次设计/反馈记录补充，迁移前历史仅描述本仓库保留的文件，不将原知识库标题推断为本仓库全量改动。历史标题、tree、作者/提交者身份和日期、父节点顺序均保留，仅消息及因祖先变化而必需的parent OID改变；当前代码与已安装资产不变。

先创建并校验包含全部引用的Git bundle，生成可审查的消息计划；离线生成新对象，逐条核对tree/元数据/消息/拓扑，再以带旧值比较的update-ref事务一次更新三个分支。失败不更新分支；引用在期间变化则事务拒绝，先重新审计。远端及remote-tracking、工具内部引用保持事实状态，不为了图形整洁改写它们。没有签名提交或标签；若后续范围包含签名，不静默删除签名。

重写范围经本次用户明确授权，远端强制发布仍需独立授权。bundle保存在忽略的`.cache/issue_tracking/git_history_20260919/`；正式新旧OID映射及核验证据版本化保存，原文档中旧提交号仍表示原验证时点，通过映射定位新提交，不批量改写历史证据。恢复时先检查后续工作，再从bundle导入到隔离仓库审查，不能用恢复操作覆盖新的提交。

## 检查与交付

`scripts/check_commit_messages.py --all`检查所有本地分支的标题和正文列表；`--message-file`在提交前检查UTF-8消息文件。AI提交使用消息文件及`git commit -F`保留真实换行，提交后核对`git log -1 --format=%B`。不自动替换全局Git配置或现有hooks。

本轮按格式的失败/通过样例、86条逐一不变量、bundle可读性、三个分支、工作树/索引和已安装资产验证，无产品逻辑修改，不重复构建或安装。历史重写不等于历史功能被重新测试，旧测试与跨平台缺口继续保持。
