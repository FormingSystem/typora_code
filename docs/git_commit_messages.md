# Git提交说明与历史补全

## R051 标题与列表正文

2026-09-19用户明确每次提交都要有换行的`- 详情`，并补全现有历史。本约定替代AGENTS先前“只有标题不足时补正文”的例外。标题继续中文结果的Conventional Commits，空一行后每项独立一行，以`- `开头；简单改动也至少一条具体说明，复杂改动按结果分项。描述行为、原因、范围和有依据的验证；不能只重复标题、列文件名或补造历史测试通过。

同日用户进一步纠正：明细要概括实际修改，让读者无需展开diff也能理解问题与效果。文件名、模块名和“同步文档/新增测试”不能代替总结；例如列宽修复应写“拖动日期/作者边界时，两侧列宽此增彼减，分界线跟随鼠标同向移动”，而不是“新增列宽模块并更新测试”。语法检查与逐条内容复核独立，前者通过不代表后者合格。文档提交说明读者能据此做什么，规则提交说明新增了什么约束。

```text
fix(workspace): 恢复面包屑与正文的主题分界线

- 在面包屑与正文之间恢复贯穿整行的1px分界线，明暗主题使用各自边框颜色，使路径区域与内容区域有清晰边界
- 分界线不增加路径栏高度、不遮挡路径及编辑器类型选择，隐藏面包屑后也不留下空白或残余线条
```

## 历史处理方案

首轮覆盖三个本地分支可达的86条提交：64条补充缺失正文，3条整理原段落，19条已有列表保留。首轮格式合格，但用户指出部分正文仍是文件及交付清单，因此内容验收未通过。同日第二轮连同新增的规则提交逐条复核87条，重写68条修改总结，保留19条已有实质说明。依据每条提交的实际差量、同次设计/反馈记录补充，迁移前历史仅描述本仓库保留的改动，不将原知识库标题推断为本仓库全量改动。历史标题、tree、作者/提交者身份和日期、父节点顺序均保留，仅消息及因祖先变化而必需的parent OID改变；当前代码与已安装资产不变。

先创建并校验包含全部引用的Git bundle，生成可审查的消息计划；离线生成新对象，逐条核对tree/元数据/消息/拓扑，再以带旧值比较的update-ref事务一次更新三个分支。失败不更新分支；引用在期间变化则事务拒绝，先重新审计。远端及remote-tracking、工具内部引用保持事实状态，不为了图形整洁改写它们。没有签名提交或标签；若后续范围包含签名，不静默删除签名。

重写范围经本次用户明确授权，远端强制发布仍需独立授权。两轮完整bundle分别保存在忽略的`.cache/issue_tracking/git_history_20260919/`和`.cache/issue_tracking/git_history_summary_20260919/`；正式新旧OID映射及核验证据版本化保存，原文档中旧提交号仍表示原验证时点，通过映射定位新提交，不批量改写历史证据。恢复时先检查后续工作，再从bundle导入到隔离仓库审查，不能用恢复操作覆盖新的提交。

## 检查与交付

`scripts/check_commit_messages.py --all`检查所有本地分支的标题和正文列表；`--message-file`在提交前检查UTF-8消息文件。AI提交使用消息文件及`git commit -F`保留真实换行，提交后核对`git log -1 --format=%B`。不自动替换全局Git配置或现有hooks。

本轮按格式的失败/通过样例、87条逐一不变量、bundle恢复、三个分支、工作树/索引和已安装资产验证，无产品逻辑修改，不重复构建或安装。另行逐条审阅正文是否讲清具体行为、问题与效果；格式检查无法判断语义。历史重写不等于历史功能被重新测试，旧测试与跨平台缺口继续保持。
