# 标签拖放与多窗口

文件标签使用浏览器原生拖放：左键按住标签，同窗拖动调整顺序，拖到另一窗口的标签栏按插入线合并，拖到当前窗口之外松开新建 Typora 窗口。缩小、最大化和全屏共用实际窗口边界，不再用编辑区或侧栏边缘判定新窗口。

侧栏工具仍沿用已有的左键按住排序和持久化，使用原有图标与名称。它们调整工具顺序，不会变成文件标签。分界线、文字选区和缩略图维持各自操作。

## 同窗与跨窗落点

标签在同组排序时同步更新布局模型和 DOM，快捷键切换遵循新顺序；跨组时移动原叶子对象。标签过多时，拖到标签栏边缘自动横向滚动。同一路径已在目标窗口打开时拒绝跨窗重复移入，避免覆盖另一份草稿。

标签使用原节点作为原生拖动图像，只有实际落下才提交。跨窗口获得焦点不会当作取消；来源被移除、页面卸载、已收到的 Escape 取消事件会终止移交。Chromium 的 dragend.buttons 不是可靠的物理按键证据，不以此判断取消。真实取消覆盖范围见验证记录。

## 文档移交与原生新窗

原生入口为在 Typora 1.14.9 核对的 `JSBridge.invoke("app.openFile", null, {mountFolder, anchor})`。初始化锚点只使用 `#typora-code-window-<随机UUID>` 文内片段；宿主延迟再次消费也不会跳到系统外部协议。匹配时同时清理宿主两个初始化锚点入口。

原生 Drag Data 仅含专属 MIME `application/x-typora-code-tab` 和一次性 UUID，没有正文、文件 URL 或自定义外部协议。实际落到另一窗口后，双方经内存频道握手，目标在指定编辑组和序号恢复正文、格式与位置，再确认接收。来源复查快照、磁盘基线和原叶子身份，一致才移除。新窗沿用来源项目，已有目标窗口保持自己的项目根目录。

没有修改 ASAR、注册 Windows 协议、写临时正文或写工程配置。来源是本功能新建的窗口，且移走最后一个真实标签时，才通过宿主关闭入口关闭空附窗。关闭前再次核对原生加载、保存和草稿状态；原主窗口保持打开。

### 文档与草稿边界

| 情况 | 行为 |
| --- | --- |
| 已保存 Markdown，包括后台预览标签 | 打开该文件并恢复阅读位置；确认后移除来源标签 |
| 已保存或未保存源码 | 交接当前正文、语言、编码／BOM／行尾、选区与滚动位置，保留保存基线；确认后移除来源 |
| 未保存原生 Markdown、自动保存关闭 | 核对宿主共享文档状态、完整正文和保存基线；目标确认后，宿主也确认另一窗口持有同文档时移除来源 |
| 原生 Markdown 自动保存开启，或目标已有另一份未保存 Markdown | 拒绝覆盖，保留来源并明确提示；不通过伪装已保存绕过宿主 |
| Untitled、目录、符号链接、Graph、diff、终端等虚拟标签 | 不作为普通文档跨窗移交；未命名文档先保存 |
| 来源又被编辑、磁盘变化、目标有新操作、超时／失败／取消 | 保留来源和已恢复的内容，拒绝继续覆盖或删除 |

读取磁盘上限为 16 MiB，超大草稿也会拒绝移交。读取和摘要异步执行；实际开始跨窗接收或创建窗口后，捕获、接收和来源释放共用 25 秒期限。纯同窗排序不读取文件。取消后不再启动排队导航。

源码显式保存仍执行原有冲突检查。跨进程不迁移完整撤销历史，目标建立新的编辑历史；两个窗口不做实时协同。来源还有不能安全切换的原生 Markdown 草稿时，可能保留来源副本并提示，不擅自丢弃或保存。

## 验证入口

在 `enhancements/` 执行：

```sh
npm run check:ui -- test_workspace_drag.cjs test_workspace_activity.cjs test_workspace_detached_window.cjs test_workspace_document_transfer.cjs
```

拖放夹具同时覆盖真实 Chromium dragIntercepted／Drag Data、本地原生拖放和真实工作区模型；多 renderer 测试覆盖已有窗口落点、随机频道、确认、取消、超时、构造失败与空附窗关闭。文档夹具使用真实 Monaco、临时磁盘文件和原生 Markdown 契约验证正文与保存基线。

原生 Typora 集成结果单列在 [反馈复查记录](feedback_review.md)。私有桌面的程序化 DragEvent 和真实原生窗口协议，不冒称物理鼠标跨窗口手工验收。

## R005.1 压力测试与资源清理（2026-09-20）

本轮用户要求对分屏、拖出建窗和拖入合并做压测，并修复发现的性能/逻辑问题。现有同窗分栏命令、拖放排序/移动和跨窗协议为验收对象，保留宿主Markdown单活动编辑器及草稿保护边界。暂不以压力测试扩展为任意控件拖动或完整VS Code扩展宿主。

对照固定VS Code 1.137.0（645f29cc3176500b4b5762ba887cf2a7f0ffdf2c）的multiEditorTabsControl.ts及editorDropTarget.ts：实际drop才移动/合并，拖出按窗口边界和dragToOpenWindow判定；移除空编辑组后保持其余组有效。对应源码为微软官方仓库src/vs/workbench/browser/parts/editor目录，研究缓存不作运行依赖。正文边缘拆分与修饰键配置需分别核对，不能把当前支持的标签栏合并称为完整拖放配置移植。

已复现：拖放适配器在不需要边缘滚动时仍安排每帧循环，240ms观测到14～15次空闲回调；分栏移除后求索引得到-1，错误移除最后权重，50/30/20三栏删除首栏得到60/40而非55/45；活动标签1000次排序触发1000次关闭/重开。修复由共同拖放、分栏和叶子移动层持有，未在各面板加补偿。

同窗层按20/100/1000轮验证真实布局模型、DOM顺序、固定标签、分栏比例、编辑器/草稿身份及销毁；传输层使用两个独立renderer的真实BroadcastChannel，同一批窗口复用，以20/100/1000次握手和取消检测频道/定时器残留，而不是同时打开1000窗口。统计轮次耗时、最长单次任务和空闲帧调用；不能把异步总耗时直接当成主线程卡顿。文件层用真实Monaco、临时文件和宿主契约核对格式、保存基线、取消及目标草稿；原始宿主独立副本覆盖实际分栏和交接入口。测试取消/迟到不得保存、覆盖或关闭用户真实文档。

反馈或取消后及时撤销落点与动画；只在标签栏边缘且可继续滚动时运行rAF，落点变化重启。移除组先捕获索引/权重，再修改树与DOM；无效移除零写入。若测量发现其他瓶颈，继续追踪真正状态所有者，并在本节更新事实。修复后按原负载复跑、build/check、本机安装并记录仍未实测的物理跨窗口输入。


### 本轮实现与对照边界

- 动画只在24px既有标签栏边缘且仍有可滚动距离时运行；中央、正文、滚动尽头、取消和销毁均不留下循环。移除先隐藏落点再读取几何的写读交错；drop仍重新核对实际落点。
- 删除分栏先取所属权重；重复删除不影响存活节点。嵌套分栏替换后重新应用父份额。分隔线仅修改相邻两栏，保持两栏总份额及其余栏；继承120px最小尺寸，小容器按可用两栏尺寸夹紧，不产生负权重。
- 活动标签排序保持编辑器打开；跨组插入已完成激活，不再重复toggle；同一活动叶跨组时同步活动组标记。文件内容及保存/草稿仍由原文件服务管理。
- 固定VS Code的`splitview.ts`中`onSashChange`、`resize`按相邻索引和最小/最大尺寸约束分配变化；本工作台保留自己的120px约束，不宣称实现其Alt对称调整、吸附、跨多栏递推与全部编辑组设置。当前拖入标签栏/正文为合并，正文四边拖放自动创建组仍未实现；四向分屏使用已有菜单命令。本次没有改变这一操作范围。

验证分层：真实core模型/DOM为20、100、1000轮四向拆分合并；两个renderer真实频道为20、100、1000次交接及2000次取消；原始Typora独立副本另有20次真实Monaco拆分合并/撤销，以及20次真实建窗→草稿接收→合并→空附窗renderer退出。原生建窗合并使用renderer事件驱动实际入口，尚非物理鼠标跨屏测试。首次附窗退出夹具依赖unload回调而超时，改为检查该专属renderer PID退出；未据此修改生产关闭逻辑。

执行原生建窗压力：设置`TYPORA_NATIVE_TEST_ROOT`为已核对宿主后运行`enhancements/scripts/test_drag_windows_native.ps1`，它复用唯一复制/私有桌面流程。总耗时含宿主启动、轮询和IPC，不能当作主线程阻塞。阶段证据见`enhancements/tests/evidence/drag_stress_20260920.json`。


## R005.2 拖放直接执行与非模态反馈（2026-09-20）

用户反馈拖出/合并出现标题“移动标签”的按钮弹窗。落下本身即授权移动，协议accepted/committed是窗口间回执，不应要求用户再次点击。当前控制器把失败或保留副本信息交给workspace_dialog，造成阻塞感；改为复用核心Notice，不抢焦点、不加确认动作，成功不提示。源/目标控制器仍分别管理事务和清理；通知展示归共享核心，不能用隐藏提示掩盖交接失败。

核对固定VS Code的multiEditorTabsControl.ts与editorDropTarget.ts，drop路径直接moveEditor/moveEditors。本轮保留现有布局与拖放范围；正常移交需检查真实源码和Markdown，出现错误先定位原因，失败/取消不保存或丢弃正文，不绕过真实脏文档关闭保护。验收增加无模态框、焦点保留、共享通知以及已保存/未保存Markdown原生双窗往返；此前只测源码的20轮不替代本项。

用户追加反馈：新窗把原窗口其他文件一并恢复。已在真实宿主开启restoreWhenLaunch=2时复现接收与会话恢复竞争，并出现“文件正在读取、切换、保存或重命名”的移动标签框。启动意图由同一安全锚点解析函数判定；会话服务在移交方清理锚点之前同步捕获。附窗不做初始目录恢复，也不将自己的局部/空布局写入该目录会话，避免覆盖主窗口记录。用户之后主动切换目录成功时转入正常会话所有权；普通启动、显式文件与无效锚点沿用原配置。

连续移出后立即移回的原生压力还复现宿主上一轮切换尚未结束，接收在创建标签前被busy保护拒绝。文件服务仅在捕获/接收事务开始前等待实际读取、切换、解析状态结束，最长5秒；取消、销毁、根目录或原目标变化即停止。保存/重命名不在这里自动重试；开始读取快照后的指纹与草稿校验仍严格失败，不重放已插入的文档。验收覆盖短暂busy、超时、取消及等待期间目标变化，并保留发现问题的失败证据。
