# 标签拖放与多窗口

文件标签使用浏览器原生拖放：左键按住标签，同窗拖动调整顺序，拖到另一窗口的标签栏按插入线合并，拖到当前窗口之外松开新建 Typora 窗口。缩小、最大化和全屏共用实际窗口边界，不再用编辑区或侧栏边缘判定新窗口。

侧栏工具仍沿用已有的左键按住排序和持久化，使用原有图标与名称。它们调整工具顺序，不会变成文件标签。分界线、文字选区和缩略图维持各自操作。

## 同窗与跨窗落点

标签在同组排序时同步更新布局模型和 DOM，快捷键切换遵循新顺序；跨组时移动原叶子对象。标签过多时，拖到标签栏边缘自动横向滚动。同一路径已在目标窗口打开时拒绝跨窗重复移入，避免覆盖另一份草稿。

标签使用原节点作为原生拖动图像，只有实际落下才提交。跨窗口获得焦点不会当作取消；来源被移除、页面卸载、已收到的 Escape 取消事件会终止移交。Chromium 的 dragend.buttons 不是可靠的物理按键证据，不以此判断取消。真实取消覆盖范围见验证记录。

## 文档移交与原生新窗

原生入口为在 Typora 1.14.9 核对的 `JSBridge.invoke("app.openFile", null, {mountFolder, anchor})`。初始化锚点只使用 `#typora-code-window-<随机UUID>` 文内片段；宿主延迟再次消费也不会跳到系统外部协议。匹配时同时清理宿主两个初始化锚点入口。

原生 Drag Data 仅含专属 MIME `application/x-typora-code-tab` 和一次性 UUID，没有正文、文件 URL 或自定义外部协议。实际落到另一窗口后，双方经内存频道握手，目标在指定编辑组和序号恢复正文、格式与位置，再确认接收。来源复查快照、磁盘基线和原叶子身份，一致才移除。新窗沿用来源项目，已有目标窗口保持自己的项目根目录。

没有修改 ASAR、注册 Windows 协议、写临时正文或写工程配置。来源是本功能新建的窗口，且移走最后一个真实标签时，才通过宿主关闭入口关闭空附窗。关闭前再次核对原生加载、保存和草稿状态；原主窗口保持打开。

### 文档与草稿边界

| 情况 | 行为 |
| --- | --- |
| 已保存 Markdown，包括后台预览标签 | 打开该文件并恢复阅读位置；确认后移除来源标签 |
| 已保存或未保存源码 | 交接当前正文、语言、编码／BOM／行尾、选区与滚动位置，保留保存基线；确认后移除来源 |
| 未保存原生 Markdown、自动保存关闭 | 核对宿主共享文档状态、完整正文和保存基线；目标确认后，宿主也确认另一窗口持有同文档时移除来源 |
| 原生 Markdown 自动保存开启，或目标已有另一份未保存 Markdown | 拒绝覆盖，保留来源并明确提示；不通过伪装已保存绕过宿主 |
| Untitled、目录、符号链接、Graph、diff、终端等虚拟标签 | 不作为普通文档跨窗移交；未命名文档先保存 |
| 来源又被编辑、磁盘变化、目标有新操作、超时／失败／取消 | 保留来源和已恢复的内容，拒绝继续覆盖或删除 |

读取磁盘上限为 16 MiB，超大草稿也会拒绝移交。读取和摘要异步执行；实际开始跨窗接收或创建窗口后，捕获、接收和来源释放共用 25 秒期限。纯同窗排序不读取文件。取消后不再启动排队导航。

源码显式保存仍执行原有冲突检查。跨进程不迁移完整撤销历史，目标建立新的编辑历史；两个窗口不做实时协同。来源还有不能安全切换的原生 Markdown 草稿时，可能保留来源副本并提示，不擅自丢弃或保存。

## 验证入口

在 `enhancements/` 执行：

```sh
npm run check:ui -- test_workspace_drag.cjs test_workspace_activity.cjs test_workspace_detached_window.cjs test_workspace_document_transfer.cjs
```

拖放夹具同时覆盖真实 Chromium dragIntercepted／Drag Data、本地原生拖放和真实工作区模型；多 renderer 测试覆盖已有窗口落点、随机频道、确认、取消、超时、构造失败与空附窗关闭。文档夹具使用真实 Monaco、临时磁盘文件和原生 Markdown 契约验证正文与保存基线。

原生 Typora 集成结果单列在 [反馈复查记录](feedback_review.md)。私有桌面的程序化 DragEvent 和真实原生窗口协议，不冒称物理鼠标跨窗口手工验收。
