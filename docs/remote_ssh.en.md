## Owner and failure behavior

- OpenSSH is the sole owner of authentication, host key, and SSH configuration, retaining user `~/.ssh/config`, proxy, and key configurations. The first host confirmation clearly displays the authentication prompt; changing the host key does not bypass it. Passwords/passwords are only passed through short-lived authentication pipelines and do not enter the command line, persistent configuration, remote source code, or logs.
- The connection service has one SSH process and request generation, timeout, and cancellation; the UI only subscribes to the status. The remote Python process handles JSON request paths, does not concatenate filenames into Shell commands; it does not install or start background persistent services.
- Remote resources include connection identity and POSIX paths, which cannot be passed to the local fs/Git/host to open. The editor has current document content and read summary; write failure or disconnection does not clear the document content, nor does it pretend to have been saved.
- Save first checks the baseline summary and real file identity, writes a temporary file exclusively in the same directory and atomically replaces it; retains permissions and cleans up failed temporary files. External changes are explicitly rejected to overwrite. There is still a non-cooperative write race between check and replace, and it is not claimed that there is cross-process CAS.
- Closing, switching connections, exiting, and workspace switching first protect unsaved content; remote tools cannot bypass the existing unified save/close service. Stale results are not written to new connections or new tabs.
- Connection parameters only save non-secret parts. After disconnection, it is possible to reconnect, and the authentication dialog is not automatically repeated.
