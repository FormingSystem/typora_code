# 文件操作与资源管理器

## 统一入口

打开文件、打开文件夹由 `workspace_open_dialog` 统一调用 Typora 的 `dialog.showOpenDialog`。顶部文件菜单、Ctrl+O、Ctrl+K Ctrl+O 和资源管理器按钮共用该入口，显示系统文件／文件夹选择窗口。取消不改变文档、目录或未保存内容；同一时间只允许一个选择窗口。文件选择后经过已有文件路由，Markdown 使用原生编辑器，其他文本使用源码编辑器。

选择文件夹只改变宿主挂载目录，不先关闭当前文档。各面板读取同一个宿主目录并更新，不自行保存第二份目录状态。正在打开的窗口在工作台卸载后返回结果时，不再修改状态。

## 文件管理

顶部菜单和快捷键由 `workspace_file_commands` 注册，继续保留 Typora 的新建、原生 Markdown 保存、导入、导出、打印和偏好设置。共享命令补充保存全部、代码另存为、重新加载与关闭目录，既有功能不因菜单统一而重做。总体职责见 [工作台架构](workspace_architecture.md)。

| 入口 | 操作 |
| --- | --- |
| Ctrl+O／Ctrl+K Ctrl+O | 系统选择文件／文件夹 |
| Ctrl+S／Ctrl+K S | 保存当前文档／全部文档 |
| Ctrl+Shift+S | 系统另存为窗口；Markdown 使用原生保存，代码保留编码、BOM 和换行 |
| 从磁盘重新加载 | 代码有未保存内容时确认，取消保留草稿；原生文档调用宿主操作 |
| Ctrl+W／Ctrl+F4 | 关闭活动标签，共用既有草稿检查 |
| Ctrl+K F | 关闭挂载目录，保留已经打开的文档 |

代码另存为保留同一 Monaco 模型和撤销记录，成功后保存基线跟随新路径；源文件不变。目标已在另一标签打开时拒绝覆盖。已有目标经过冲突检查，新目标使用完整临时文件和不覆盖目标的硬链接发布；不支持硬链接的文件系统会报告失败并保留草稿。取消选择或选择期间活动文档改变时不写文件。

VS Code 的多根工作区、`.code-workspace` 导入／保存、配置新窗口和扩展分享未接入，不以无动作菜单伪装可用。

资源管理器菜单按选中文件或文件夹提供实际操作：

| 操作 | 行为 |
| --- | --- |
| 新建文件／文件夹 | 在所选文件夹内输入名称；选择文件时使用其父目录 |
| 在系统资源管理器中显示 | 使用系统定位接口显示选中项 |
| 在集成终端中打开 | 使用所选目录；选中文件时使用其父目录 |
| 在文件夹中查找 | 以该目录限制搜索，支持含 `[]`、`{}` 的真实目录名称，不将路径当作 glob；搜索面板可清除范围 |
| 剪切、复制、粘贴 | 接入系统文件列表；工作区内剪切复用文档移动事务，外部来源复制并保留源文件；当前验收边界见下文R009 |
| 重命名、删除 | 已单独选中文件双击、F2 或菜单重命名；文件夹用 F2 或菜单；删除确认后移至回收站 |
| 复制路径／相对路径 | 分别复制系统绝对路径或当前根目录相对路径 |
| 选择以进行比较／与所选项目比较 | 读取两个文件的当前内容；已打开源码的未保存内容参与比较，磁盘内容不被修改 |

菜单不直接修改磁盘。`workspace_files` 管理保存、草稿、文件模型及写入操作；搜索服务管理搜索范围和取消；Git 差异编辑器负责比较呈现。右键菜单只组织可用动作，切换目录后旧菜单不能继续操作旧选择。

## R009 系统文件剪贴板

2026-09-13，接通系统文件列表与资源管理器复制/粘贴，保留原有工作区内剪切和文档事务。Windows通过原生 `CF_HDROP` 交换多文件/文件夹，Linux通过文件URI列表交换，正文路径文字与文件列表分开。Windows采用系统PowerShell的STA剪贴板适配器，固定程序通过标准输入接收JSON，路径不进入可执行命令；不依赖额外安装的PowerShell7。Linux由宿主Electron提供剪贴板，原生桌面互通仍需对应平台实测。

固定VS Code提交 `88e44fa0e00b08f7758b4f6d05632e4fd5e4df6f` 的 [NativeClipboardService](https://github.com/microsoft/vscode/blob/88e44fa0e00b08f7758b4f6d05632e4fd5e4df6f/src/vs/workbench/services/clipboard/electron-browser/clipboardService.ts) 以 `code/file-list` 保存资源，[fileActions.ts](https://github.com/microsoft/vscode/blob/88e44fa0e00b08f7758b4f6d05632e4fd5e4df6f/src/vs/workbench/contrib/files/browser/fileActions.ts) 的 `pasteShouldMove` 属于当前窗口文件操作。这里采用相同的职责划分，另接系统文件格式满足跨应用交换。Windows格式依据[微软Shell剪贴板说明](https://learn.microsoft.com/en-us/windows/win32/shell/clipboard)，不把字符串路径冒充文件。

`workspace_file_clipboard` 是文件剪贴动作的唯一所有者，平台适配器只读写文件列表和版本。剪切意图绑定写入后版本、源目录及原路径；其他应用改写剪贴板后旧意图失效，不能把后来复制的文件当作待移动项。仅当前窗口、同一工作区且版本相符的剪切执行移动，跨窗口/系统来源采用复制并保留来源；对外发送的文件列表也使用复制效果，避免外部应用移动正在编辑的文件却绕过文档事务。用户粘贴外部剪切列表时提示“源文件保留”，不冒充跨应用剪切删除协议。

文件复制在选中目录内落地。外部路径只在用户粘贴时成为本次源条目；源目录和目标工作区分别校验，仍拒绝符号链接、设备、相对路径和目录复制入自身。整批先预检同名冲突，默认拒绝覆盖，失败只回退本批创建且身份未变的文件，不递归删除外部新增内容。复制磁盘字节，不自动保存未保存文档；内部移动仍经原重命名事务保留模型、标签路径和草稿。剪切在本窗口内粘贴成功后取消本地意图。Windows在持有剪贴板锁时核对版本并清除；Linux的Electron接口不提供原子版本核对与清空，因此保留系统文件列表，只取消本地意图，避免误清其他应用的新复制。后续粘贴按新的文件来源校验，已移动的旧路径不会被当作仍有效的剪切。

UI只展示服务的剪切标记并调用复制/粘贴动作。快捷键限资源管理器焦点，正文编辑器保留原生文本剪贴板。读取失败、剪贴板锁定、空文件列表与目标冲突显示明确错误；异步读返回时若根或目标改变/界面销毁，停止落盘。文件操作期间不允许卸载所有者，完成后刷新当前树；取消或失败不丢原文件与草稿。宿主失焦后重新聚焦时刷新剪切标记，不持续轮询剪贴板。刷新成功或失败都只能取消该请求开始时的剪切意图，旧请求不能取消后来建立的新剪切。平台写入返回本次写入自身的快照：Windows在释放锁之前读取，Linux按写入的唯一标识与内容计算版本；写入后不另读系统剪贴板来认领其他应用的版本。

验收覆盖真实系统格式读写、中文/空格/多文件/文件夹、二进制、外部复制进入与反向读取、内部剪切、外部剪切保留源、重新复制取消旧意图、同名拒绝与失败回滚、切根/卸载取消、正文焦点与草稿保持。系统剪贴板实测使用独立Windows窗口站，其剪贴板独立于用户当前桌面；其余平台明确记录未实测，不能以Windows结果外推。

### 本轮验收边界

文件操作引擎、剪贴板版本与异步生命周期、真实资源管理器键盘/菜单接线及文档主机已通过本轮回归。复制保留磁盘UTF-16与二进制字节，不保存草稿；内部剪切保留模型、撤销记录、编码和后续保存路径。Windows PowerShell 5.1 已编译完整原生适配器。

真实Windows剪贴板交换仍待隔离实测，不能把端口替身的UI通过当作系统互通通过。独立启动器为 `enhancements/scripts/run_file_clipboard_windows.ps1`，在管理员PowerShell中运行；它只创建全新的命名窗口站，子进程确认窗口站身份后才读写测试剪贴板，退出后释放资源，不接管已有窗口站。权限要求来自[Windows CreateWindowStation](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-createwindowstationw)，普通用户不能指定新窗口站名称。该权限仅用于隔离测试，正常使用文件剪贴板不要求管理员。Linux文件URI适配尚未经过原生桌面互通验证。


## R028 文件行的单击、双击与加载反馈

2026-09-13：用户反馈搜索文件分组只能点箭头折叠，资源管理器连续点击偶尔反应慢，并要求已选中项双击重命名。随后同日用户纠正文件夹行为：文件夹不使用双击重命名，单击只切换展开状态。本节以此次纠正为准；已选中文件双击改名和搜索结果双击打开仍保留。

搜索文件分组的箭头、文件图标、名称、路径和行内空白都属于同一展开／折叠目标；移除按钮独立。单击立即切换一次，同时保留名称行选择与下方预览定位；匹配行仍只选择／预览，双击或 Enter 打开；文件分组双击恢复该手势前的开关状态，再打开记住的匹配。分组支持 Space、左右方向键，按钮键盘操作不得冒泡为另一动作。

资源管理器目录的箭头、名称和行内空白单击立即展开／折叠，包括已选中目录；连续快速点击逐次切换，不因浏览器将第二次点击标为双击序列而丢弃。目录不参与双击改名判定，也不保存或恢复双击前的展开状态；文件夹通过 F2 或右键菜单重命名。读取中可再次折叠，重开复用同一请求，迟到结果不能重新展开。文件保持单击打开，已单独选中的文件在下一次双击时进入行内重命名；未选中文件的首次双击只打开一次。修饰键多选、拖动、重命名输入、右键与独立操作按钮不触发目录开关。使用浏览器的文件双击序列，不查询系统阈值或为单击加入等待定时器。Esc／失焦取消重命名不写磁盘，Enter 继续共享重命名事务和冲突保护。

本次核对 VS Code 1.137.0 固定提交 `645f29cc3176500b4b5762ba887cf2a7f0ffdf2c`：[树指针处理](https://github.com/microsoft/vscode/blob/645f29cc3176500b4b5762ba887cf2a7f0ffdf2c/src/vs/base/browser/ui/tree/abstractTree.ts#L2525)在每次指针点击上切换可折叠节点；[Explorer 配置与打开处理](https://github.com/microsoft/vscode/blob/645f29cc3176500b4b5762ba887cf2a7f0ffdf2c/src/vs/workbench/contrib/files/browser/views/explorerView.ts#L564)默认允许整行展开，目录不进入文件打开路径；[展开模式配置](https://github.com/microsoft/vscode/blob/645f29cc3176500b4b5762ba887cf2a7f0ffdf2c/src/vs/platform/list/browser/listService.ts#L1478)默认为 `singleClick`。采用此目录交互策略；本次不增加设置项或改变文件打开约定。原实现把所有 `detail >= 2` 点击丢弃，又在目录双击时恢复展开状态，是快速点击看似失效的两处原因。

`workspace_search` 仍拥有分组和命中选择。`workspace_explorer` 拥有目录节点、唯一展开状态与请求；可见行按节点身份复用，仅更新属性和实际变化的子内容，滚动时回收离屏节点，避免展开／监视刷新替换鼠标下的节点而丢失双击。每次请求的目录层级读取完成即展示；请求动画帧合并更新，不再持续取消重排导致绘制推迟。切换根目录／销毁后丢弃旧结果；隐藏时停止监视，读取完成不重新打开侧栏或折叠目录。文件写入继续由已有服务承担，新增交互不直接执行磁盘重命名。
