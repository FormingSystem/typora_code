# Terminal Operations and Configuration

2026-09-29 R014.3: Panel visibility, maximization and geometry survive restarts. Visible panels start a fresh default Shell; old processes are not resumed. Appearance reset hides the panel without terminating the current Shell. See the [design](workspace_zoom.en.md#appearance-persistence).

The terminal is by default located as an independent panel below the document content. Press **Ctrl+`** shows or hides the panel while retaining the shell and output; press **Alt+Shift+`** to create a new terminal. The top of the panel uses compact icons, and the right side displays the session list; full operations can be accessed from 'More' or the right-click menu of the session.

## Action

| Action | behavior |
| --- | --- |
| Create and Select Configuration | `+` uses the default Shell; a dropdown menu is used to create sessions based on the selected configuration, and existing sessions are not replaced |
| Split, Unsplit, Merge | Display multiple sessions side by side in the same panel; unsplit them into independent groups, merge by selecting another group; sessions retain their respective processes |
| Switch, Rename, Color and Icon | Click the list to switch; double-click or F2 to rename; right-click to modify identity; long names can be viewed in full by hovering over them, showing the complete name, directory, and status |
| Move to Editor / Panel | Move the same xterm and PTY; retain the process and buffer, without re-running the Shell |
| Height and Maximize | Drag the upper boundary to adjust the height, which can also be focused on the dividing line by pressing the up and down keys; maximize or restore in the top right corner, and hide it to recover the space of the document content |
| Find | Ctrl+Shift+F; supports case sensitivity, whole word, regular expression, and prefix/suffix matching; Escape to close the search |
| Copy, Paste, Select All | Ctrl+Shift+C/V; Windows also supports Ctrl+V paste (R079.1); Ctrl+C copies when there is a selection, otherwise sends an interrupt; right-click and system paste share multi-line confirmation |
| Clear Screen, Restart, Terminate | Clearing the screen only clears the display; restarting uses the latest startup configuration; terminating releases the corresponding process; when the process exits, the status is displayed, which can be restarted again |
| Keyboard Operations for the List | Use the up and down arrows to switch, press Enter to activate, F2 to rename, and Delete to terminate the selected session |
| Administrator Terminal | Windows UAC starts an independent PowerShell to locate the selected directory; the integrated terminal and Typora itself do not elevate privileges |

Normal new creation uses the current open workspace directory; when there is no mounted directory, it uses the active file context, and if the window is empty, it uses the user's home directory. Explorer's 'Open in Integrated Terminal' uses the selected folder, and when a file is selected, it uses its parent directory. The clearly marked 'Repository Root Directory' native menu / Git entry only queries the Git root directory.

## Configuration

Enter from 'More → Terminal Settings'. Settings can be searched; all fields are validated before saving; errors do not overwrite previous valid configurations. The appearance is immediately applied to existing terminals; working directory, environment variables, and Shell parameters take effect after new or restart.

| Configuration scope | Available Settings |
| --- | --- |
| Shell | Default Configuration; Custom Configuration's `id`, `title`, `executable`, `args`, as well as Independent Environments, Directories, Icons, and Colors |
| Directories and Environments | Workspace-relative path, `${workspaceFolder}`, `${env:variable_name}`; environment variable string settings, `null` delete value |
| Font | Font Family, Font Size, Font Weight, Line Height Multiplier, Character Spacing |
| Cursor | Block/Vertical Line/Underline, Blink, Vertical Line Width |
| Scrolling and Display | Buffer line count, smooth scrolling, normal and Alt wheel speed, minimum contrast, tab width |
| Action | Right-Click Menu or Copy/Paste, Select and Copy, Multi-line Paste Confirmation |
| Layout | Default panel/editor, session list left/right, hide when single terminal or single group, use initial directory/workspace directory when split |

Custom Configuration Example:

```json
[
  {
    "id": "project_pwsh",
    "title": "project PowerShell",
    "executable": "pwsh.exe",
    "args": ["-NoLogo"],
    "cwd": "${workspaceFolder}",
    "env": {"PROJECT_MODE": "development"},
    "icon": "terminal",
    "color": "#007ACC"
  }
]
```

Parameters are passed as an array, not concatenated with Shell commands. Configuration and panel height are saved in Typora User Data, and no native path or configuration file is written to the opened project. The theme reads Typora's current actual colors; switching themes updates existing xterm without restarting Shell.

## R006 Scroll history capacity and old log disappearance (2026-09-21)

User feedback indicates that earlier outputs disappear when scrolling up, not that a line is cut off by the panel width. The current `scrollback` code defaults to 1000 lines, accepting integers from 0 to 100000; this represents the scrolling history capacity above the visible area, not the total amount of Shell output or the number of command history lines. Once the capacity is reached, xterm discards the oldest history; line wrapping consumes buffer lines. This is consistent with the default 1000 lines for the fixed VS Code terminal configuration, see [Interface baseline](vscode_design_baseline.en.md) and [official buffer explanation](https://code.visualstudio.com/docs/terminal/basics#_navigating-the-buffer).

Configuration is adjusted from 'Terminal More Menu → Terminal Settings → Scroll Buffer Lines'; it is managed solely by `terminal_settings`, and `terminal_surface` applies the value to xterm. Increasing this value only affects content that is still retained and subsequent outputs, and cannot restore already discarded logs; decreasing it may immediately reduce existing history. History recovery after closing a process/window is not provided by this setting. Previous user session effective settings were not read, so the code's default value cannot be considered a on-site measured value.

The Shell is responsible for executing commands, the PTY transmits output, and xterm saves and draws the terminal screen. The current document content is fully passed to `term.write(data, done)` by `terminal_session`, and no other UI log array clipping was found. The broker handles consumed output using pause/confirm/recover flow control, which is to limit backlog, not to delete scroll history; the PTY client retains the last 4000 characters of stderr only for assisting process error diagnosis, and it does not affect the document content of the Shell.

Increasing the history capacity mainly affects memory, search, and reordering when changing width, but it does not mean that all history is created as simultaneously displayed ordinary web lines.
