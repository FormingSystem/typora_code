# 已提出问题的复查记录

本表对应用户截至 2026-09-10 的截图和反馈，覆盖顶栏、活动栏、Git、文件识别、链接与大纲。检查以当前实现及本轮重新运行的场景为准；此前通过的计数不能替代本轮验收。

## 本次发现的遗漏

- 活动栏实际位于宿主 `header` 内，旧样式限定为 `body` 的直接子节点，因此没有应用固定定位；第一槽被顶栏遮挡。此前测试只检查 Explorer 没有越过顶栏，没有验证整个活动栏的起点和连续槽位。
- Git Graph 的“未提交改动”详情没有复用 SCM 的默认打开分流，新文件仍进入空基线差异视图。
- 搜索结果和快速打开列表仍使用通用文件图标，没有调用 Explorer 使用的同一 Seti 图标函数。
- 快捷键切换标签按全局路径查找，同一文件在多个编辑组打开时可能取错标签位置；系统空页也未按真实 URI 排除。
- 快速打开未忽略输入法组字期间的 Enter，可能在中文选词时提前打开文件。
- 菜单与快捷键打开文件夹使用不同根目录来源，顶部搜索标签、Explorer 与文件操作可能不同步。删除局部 `chosen_root` 覆盖，统一使用已核对的宿主挂载目录接口及其变化通知。
- 更换根目录时，快速打开仍可能展示旧目录的异步扫描结果；现在关闭旧选择器并使旧扫描失效，盘符根目录也能显示有效标签。
- 保留的旧仓库差异页可能在切库后调用新仓库上下文；现在刷新、上下文件、打开及已生成菜单中的暂存／丢弃均在执行时校验原仓库身份。

## 相邻 Markdown 标题的后续修复

用户继续报告在两个相邻标题间滚动时闪聚焦。原修复只关闭 `blink`，没有消除两个标题判定的竞争：工作台选择当前阅读章节，Typora 原生默认高亮却可能选择下一个可见标题；原生延迟回调还会再次改选。

现在自动回调与工作台共用一次判定，调用原生接口时传入已选定的标题。相邻边界使用 12 CSS px 双向滞回，小幅往返不改选；跨多章节跳转立即跟随。显式点击标题和手动高亮保留原生语义，非标题／旧文档延迟目标不锁住旧章节。显示当前大纲行只调整大纲自身滚动位置，卸载恢复原生接口。

本次构建与 `check` 通过，outline、启动、阅读生命周期及源码大纲共 4 个目标通过。新增 outline 回归用旧版源码红测，确实复现同章节延迟回调反复重写选中样式，再以修复源码通过同一行为检查。

独立原生对照各执行 58 次边界采样及 10 次真实宿主 `post-wheel` 高亮。旧版 6 组微滚动均出现选中往返，其中 5 个采样在正文位置未变时两次改选；修复版重复改选为 0，6 组微滚动抖动为 0，正文位置漂移为 0。证据保存在 `.cache/native_single_row_compare/outline_boundary_baseline_observed/` 和 `outline_boundary_fixed/`，不沿用前次 80 项计数作为本次证据。

## 可见标题定位、边距与链接显示的后续修复

上一轮 `36aef2d` 消除了高亮竞争，但按“越过视口顶边”判断章节，导致新标题已经位于屏幕中间时仍高亮上一节。现在优先选择完整进入可读视口的标题；当前标题顶端仍在上沿 12px 缓冲内时保持选择，向上滚动时更早的标题完整进入后可重新接管。长段落或表格中没有可读标题时，回退到正文所属章节。原生自动／延迟回调仍共用同一判定；点击后的旧目标已滚离阅读区域时，延迟回调不能再把它选回并锁住新的位置。有效显式点击与手动高亮保留原生语义，不移动正文或焦点。

Word 官方说明导航窗格随文档滚动高亮当前标题，但未公布具体像素阈值。核对本机原始 Typora 1.14.9 实现，原生规则会考虑视口内标题，且含文末标题优先分支。这里明确采用上述可读视口与边缘缓冲规则，不声称复制 Word、WPS 或 Typora 的全部内部算法。参考：[Word 导航窗格说明](https://support.microsoft.com/en-us/word/use-the-navigation-pane-in-word)。

正文边距恢复原有底栏控件和单侧百分比含义，不恢复无关外观设置。链接提示将编码的中文路径与锚点转换为可读文字；文件路径已解析的部分不再次解码，复制按钮仍保留原始链接，悬停展示不会修改 Markdown 或触发打开文件。

本轮首次原生验证发现：已移入底栏的原生新建按钮也带有 `.footer-item-right`，普通后代选择器误把该嵌套节点作为 `insertBefore` 参照，导致边距及后续大纲初始化中断。两处插入入口已限定为底栏直接子节点，并在 margin、footer 夹具中加入真实嵌套类名，先复现失败后通过修复。失败实例 `outline_visible_fixed/` 保留，不计入通过结果，也未安装到用户实例。

原生截图还发现缩略图遮住字数。冻结旧版本使用相同窗口几何也能复现：content 的底边比可见底栏顶边更低。共享 `reading_viewport_bounds` 现在扣除这个覆盖区，缩略图不越过底栏，大纲也不把被底栏遮住的标题当成完整可读。验收同时检查矩形、截图和 `elementFromPoint` 实际命中，不能只凭控件矩形未重叠判定可见。
