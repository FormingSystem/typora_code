# 文档标签右键菜单

## R030：目标与参考

2026-09-13，用户要求按 VS Code 完善已打开文档的标签右键菜单。菜单作用于右键目标及其所在组，打开菜单不切换后台标签。此前关闭后等待 167ms 再打开的分屏路径取消，文档状态交给文件服务管理。

固定参考为 VS Code 1.137.0，提交 `645f29cc3176500b4b5762ba887cf2a7f0ffdf2c`：

- [标签菜单及分屏子菜单](https://github.com/microsoft/vscode/blob/645f29cc3176500b4b5762ba887cf2a7f0ffdf2c/src/vs/workbench/browser/parts/editor/editor.contribution.ts#L394)：关闭、复制、预览、固定与分屏分组；可用条件取自目标编辑器。
- [关闭命令](https://github.com/microsoft/vscode/blob/645f29cc3176500b4b5762ba887cf2a7f0ffdf2c/src/vs/workbench/browser/parts/editor/editorCommands.ts#L853)：批量关闭排除 sticky 标签；显式关闭单个标签允许关闭固定项。
- [文件动作](https://github.com/microsoft/vscode/blob/645f29cc3176500b4b5762ba887cf2a7f0ffdf2c/src/vs/workbench/contrib/files/browser/fileActions.contribution.ts#L163)：路径复制、保存与资源管理器定位依据实际文件能力显示。

## 使用方式

在已打开文档的标签上单击右键。菜单始终针对该标签，后台标签不会仅因右键而切换正文；灰色项表示当前文档或编辑组不支持该操作。

| 菜单 | 操作 |
| --- | --- |
| 关闭标签／其他／右侧／已保存／全部 | 在该标签所在组内关闭，未保存文档先处理保存或取消；批量关闭保留固定项 |
| 复制绝对路径／相对路径／面包屑路径 | 分别复制完整文件路径、相对打开目录的路径、按层级分隔的路径 |
| 打开预览／重新打开方式 | Markdown 可切回原生阅读或源码编辑；未保存时先保存或取消 |
| 在系统文件管理器中显示／在资源管理器中显示 | 分别在操作系统和工作台侧栏定位该文件 |
| 保持打开 | 结束临时预览状态，保留普通标签 |
| 固定／取消固定 | 固定到组首；固定图标占用原关闭按钮位置，点击图标取消固定，右键“关闭标签”仍可关闭 |
| 向右分屏／分屏到 | 在右、左、上、下创建副本，同窗源码共享当前草稿 |
| 移动到 | 将原标签移动到已有的相邻编辑组；没有相邻组时禁用 |
| 移动到新窗口／复制到新窗口 | 使用现有文档移交通道，前者确认接收后移除来源，后者保留来源 |

Windows 快捷键：`Alt+K` 后按 `U` 关闭已保存，按 `W` 关闭全部，按 `Enter` 保持打开，按 `Shift+Enter` 固定／取消固定，按 `O` 复制到新窗口。`Alt+\` 向右分屏，`Alt+K` 后按 `Alt+\` 向下分屏；`Shift+Alt+R` 在系统文件管理器定位。快捷键对当前标签生效，菜单对右键目标生效。

## 交互与状态

关闭、关闭其他、关闭右侧、关闭已保存、关闭全部只作用于目标组。批量关闭固定项除外；逐个等待未保存对话框，取消或保存失败停止后续关闭。关闭已保存执行前再次检查脏状态。异步动作重新核对叶子身份和所属组，不凭路径删除另一个标签。

路径组提供绝对路径、相对路径及面包屑路径；文件定位分别进入系统文件管理器和工作台资源管理器。Markdown 提供原生阅读预览和“重新打开方式”的 Markdown／源码编辑器选择。切换编辑方式前保存或取消未保存内容，不能用磁盘内容替换草稿。

“保持打开”结束临时预览状态；“固定”将标签保留在组首并排除批量关闭，两者独立。固定状态由叶子 state 持有并随既有布局保存。分屏复制到指定方向的新组；“移动到”只进入现有相邻组。源码分屏共享同一个文本模型、保存基线和格式，光标／滚动位置各视图独立；移动保留原叶子和撤销栈。保存或另存为更新全部副本的状态与路径，关闭最后一个副本才释放模型。Markdown 的原生编辑器与分屏阅读视图读取同一内存正文，编辑事件更新预览，不为分屏强制写盘。

移动／复制到新窗口复用已验证的文档移交通道。只有移动在目标确认并复查来源后释放原标签；复制保留原标签。失败、取消与超时保留来源，不写临时正文。

原生 Markdown 保存等待 `File.saveUseNode` 的实际结果；切换路径时仍等待目标文件加载，重新激活已经加载的同一文档不再等待不会重复触发的加载事件。已命名文档放弃修改调用宿主重新加载已保存正文；未命名原生草稿目前只提供保存／取消，不伪造清洁状态。

本轮覆盖文档操作。Share、Chat／Codex、语言服务引用等扩展提供者没有等价宿主服务，不添加无效菜单项；保留为扩展能力差异。虚拟、只读或未命名文档根据实际能力禁用不支持的文件动作。

## 职责与呈现

工作台编辑动作服务拥有目标解析、批量操作与命令；菜单只根据服务能力组织分组和禁用状态。文件服务拥有正文与保存，核心布局提供相邻分屏和叶子移动，跨窗口模块拥有移交生命周期。移除旧标签菜单及其临时补丁，保留原生文件菜单的既有路径动作。

菜单复用公共 workspace_menu：圆角、主题、快捷键列、禁用状态、方向键、子菜单翻边、窗口高度内滚动。标签尺寸保持现有基线。右键目标、窗口销毁及菜单关闭的事件资源都按绑定生命周期清理。

## 验收

覆盖后台标签目标、首尾／单标签禁用条件、组隔离、固定排序与批量保留；源码和 Markdown 的保存／取消／失败；同窗分屏共享草稿和撤销、相邻移动；新窗复制不释放及移动确认；中文长路径、明暗、窄窗口、缩放、键盘与菜单边界。构建与检查通过情况、目标 UI 和隔离原生宿主证据统一记录在[反馈复查记录](feedback_review.md#2026-09-13-文档标签右键菜单)。Electron 覆盖真实 Chromium 指针和键盘，原生 Typora 检查使用隔离文档、宿主 API 与 DOM 动作，两者不混称物理设备人工验收。

## R080：资源管理器预览与常驻打开（2026-09-27）

问题是资源树单击未传递已有的预览意图，导致每次阅读都留下常驻文档。默认单击文件立即在主编辑区显示完整原生Markdown或源码，每组只保留一个可替换预览标签；再次单击其他文件替换该预览，编辑后自动保持打开。预览文件名采用斜体（固定上游singleeditortabscontrol.css的预览标题语义），常驻恢复普通字形。Alt+左键显式常驻打开，已有常驻文件只激活，不降级为预览。关闭“启用预览编辑器”后仍尊重用户设置，普通单击也常驻。不限制常驻数量或文件大小。

固定VS Code 6807068：`platform/list/browser/listService.ts`单击pinned=false、双击pinned=true，`contrib/files/browser/views/explorerView.ts`传递编辑器选项，`browser/parts/editor/editorGroupView.ts`按enablePreview/dirty/pinned决定保留，`common/editor/editorGroupModel.ts`持有每组preview身份。采用其预览生命周期；本产品Alt+左键改为常驻，保留现有目录展开、Ctrl/Shift多选、F2和已选文件双击重命名，标签双击/“保持打开”仍可常驻。此授权覆盖旧冻结中预览标签限制，不扩展侧栏布局。

树只提交preview意图，workspace_files管理每组预览及编辑提升，既有编辑器/文档生命周期管理关闭与释放。失败或取消不得先移除旧预览；常驻、固定、未保存和正在保存的文档不自动关闭。替换只处理目标编辑组，分屏副本保留，最后一个源码视图关闭释放共享模型，并立即移除该视图的detach补丁闭包，避免关闭后仍被全局恢复列表强引用。原生Markdown继续用宿主编辑/渲染及文档清理适配，不创建第二个渲染器；导航历史只保留定位信息，不要求永久保留所有标签。视图关闭、切库和卸载清理预览引用及迟到请求。

回归覆盖普通点击20轮、Alt常驻、编辑后保留、同文件重选不降级、关闭预览设置、多个编辑组、失败/取消及快速点击、目录/多选/重命名；检查叶子/源码模型/原生缓存实际释放及监听器清理。原始Typora验证Markdown即时显示、输入提升和未保存内容，记录真实结果与合成/物理输入边界；构建和同候选隔离卸载/本机安装后交付。

## R080.1：预览替换的显示事务（2026-09-27）

问题是旧预览与新文件先后作为两个标签显示，随后关闭旧预览造成跳位。目标是读取成功后在同一显示事务完成身份、顺序和活动视图交接；加载失败、取消以及脏文档仍遵守R080保护。文件服务拥有预览意图与可替换判定，编辑组拥有标签位置和生命周期，原生宿主拥有正文加载。不得以延时、动画或隐藏整个工作台掩盖中间态。

参考固定VS Code 6807068 `workbench/common/editor/editorGroupModel.ts`的openEditor/replaceEditor：预览使用原索引替换，关闭旧项不激活邻居。实现前核对原生file:open与leaf:open事件时序；验收记录每次requestAnimationFrame中的标签身份、位置和正文身份，覆盖20轮、快速选择、常驻标签夹在两侧、源码与Markdown、读取失败及跨组。保留原生保存取消，运行窗口与候选安装状态分别记录。

实现：原生file:open在core完成叶子挂载后，由本次文件服务请求立即提交预览身份，不再等待导航定位完成；监听在成功、失败和取消的finally中释放。源码在离屏候选视图准备内容，仍复用已有共享模型；仅当前请求及原活动叶子未变时才挂载，迟到候选立即释放。读取失败继续展示已有错误入口并保留可读旧预览。替换通过既有move_workspace_leaf排序端口占用旧索引，再关闭已失活的旧叶子，不切换到邻居。
