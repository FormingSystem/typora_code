# 在 VS Code 中打开（R078）

## 目标与入口

2026-09-27：资源管理器的文件、文件夹（含工作区根）、文件标签及正文右键提供“在 VS Code 中打开”。文件夹以目录打开；文件传递实际完整文件路径，不能只启动应用。复用现有菜单的列布局，不增加专属样式。

## 环境发现与执行

每次执行从当前系统环境发现 VS Code，不保存开发者机器路径，也不依赖本仓库的上游研究副本。先检查 PATH；Windows 同时读取系统／用户登记的 PATH 和 App Paths（支持安装到其他盘、用户安装和系统安装），通过环境变量定位标准安装目录作为后备。Windows 官方 `bin/code.cmd` 转到同一安装目录的 `Code.exe`，不经过命令解释器拼接用户路径。macOS 后备使用 系统 Spotlight 索引查询正式 bundle ID；Linux 使用 PATH 中的 `code`。

上游依据：固定 VS Code `6807068` 的 `build/win32/code.iss` 注册 `App Paths/code.exe` 与安装目录的 `bin`；`src/vs/platform/environment/node/argv.ts` 定义 `--reuse-window` 和路径参数。本工具使用相同命令语义，独立发现安装，不共享 VS Code 配置。

共享服务持有发现、路径校验与异步启动，菜单仅提交目标。参数以数组传入、`shell:false`，支持中文、空格及特殊字符。以文件参数打开现存文件，以目录参数打开目录；不强制复用窗口，由 VS Code 自身设置决定。移除继承的 `ELECTRON_RUN_AS_NODE`，避免把 VS Code 作为 Node 进程启动。启动失败显示实际错误；未发现安装时提示安装 VS Code 并启用 PATH，不自动下载安装。

## 文档与生命周期边界

打开磁盘版本，不自动保存未保存编辑。无磁盘路径的草稿禁用，并说明需要先保存。SSH 资源和历史／差异缓存不是本地原文件，暂不交给本地 VS Code；远端打开需独立核对 Remote SSH 协议。原生 Markdown 仅追加菜单项，保留原生编辑菜单；绑定时快照真实文件身份，切文档后过期操作不执行。销毁时撤销节点、事件及适配包装。

## 验收

测试使用独立临时安装树及注入平台环境：PATH、用户／机器注册、非默认安装盘、便携目录、安装后再次发现、缺失程序、文件／目录、中文空格与 shell 字符、启动错误及环境隔离。UI 覆盖资源树、根目录、源码菜单、标签和原生正文菜单，未保存／远端禁用、重复绑定及销毁。外部进程替身用于检查启动参数，不等同于用户实际 VS Code 加载验收；Windows 实际安装位置只读发现另行记录。交付复用标准构建、隔离安装卸载与本机安装。

## R078.1 工程身份与跳转目标

所有入口文案统一为“VS Code 打开工程”；文件或目录只决定定位目标。

2026-09-27用户纠正此前“选择目录就作为工作区”的行为。共享文件服务context_root是当前工程所有者，菜单生成时捕获工程根与目标；服务向VS Code一次传递工程根和文件两个参数，子目录不再缩小工作区。单独文件无工作区时才用父目录。当前工程根失效时显示错误，不静默改成子工程。

文件直接打开实际文件；目录读取直属普通文件，优先README，其余按名称排序取首个，以VS Code默认explorer.autoReveal定位到该文件及父目录。空目录或仅有子目录时只打开原工程，不生成临时文件、不递归扫描或冒称目录已被选中；VS Code CLI没有公开的任意目录选中参数，不注入扩展或改写用户VS Code设置。用户关闭autoReveal时尊重其配置。原生菜单保持单次启动、草稿不隐式保存，目录读取失败反馈真实错误。

验收嵌套目录/文件始终携带相同工程根、README优先、空目录、根失效及中文路径；原生菜单使用启动参数替身，实际外部窗口仍单列验收边界。本节替代前文目录单路径启动约定。
