# R083 编辑器呈现与共同工作台边界

2026-10-01用户反馈：Markdown源码模式隐藏功能侧栏和大纲、底栏源码图标裁切，切换位置与当前阅读不一致。用户明确要求真实共有职责统一管理，内容领域仍独立拥有自己的行为。

## 所有者与范围

编辑组拥有标签、工具栏和内容矩形；原生Markdown的`content.typ-workspace-binding`是该矩形的唯一宿主适配。渲染正文与原生源码层都在这个容器中呈现，源码层填满容器，不再使用独立的全窗口固定定位。各编辑器继续拥有正文、撤销、光标、滚动及语法；不新建第二个Markdown模型。

工作台核心拥有活动栏、侧栏当前面板和显隐。呈现模式切换不改变侧栏；用户主动收起、展开和切换仍沿用同一入口。偏好页临时隐藏侧栏仍由宿主拥有，不把其状态推广到编辑模式。源码/渲染共用活动栏与分隔线布局，不能新增一套源码专用尺寸补偿。

底栏公共图标角色拥有内容居中和水平内边距，源码激活只表达状态，不改变盒模型；沿用22px操作槽与16px官方`edit-code`图标。原节点与点击事件保留。共同规则也回归文件、菜单、列表切换和Git操作，业务隐藏规则仍由原所有者决定。

## 宿主与上游依据

Typora 1.14.10的`File.toggleSourceMode`调用`library.tmpHideSidebar/recoverSidebar`、`sourceView.show/hide`与`freshMenuWithDelay`。工作台宿主适配集中调整该命令的侧栏边界，底栏、原生快捷键与工作台视图菜单均调用已核对的`File.toggleSourceMode`；内容切换仍调用原生源码视图。移除适配时恢复原方法。原生`window.css`在源码激活时对按钮增加10px左内距，`base-control.css`对源码层使用固定定位，均须纳入共同框架约束。

固定VS Code `68070681e87284e2f22728f15fe3f3651fbf932b`的`editorGroupView.ts#layout`先布局标题再传递内容矩形，`editorPanes.ts#layout`转交活动编辑器；本项目采用职责分工，保留本机现有尺寸。`statusbarpart.css`操作容器使用flex居中，状态与内容几何分离。本轮不扩充布局、菜单或编辑器种类。

## 定位、失败与清理

阅读视口与编辑光标是独立状态。模式切换应转换当前可见内容位置；明确的输入或导航仍允许定位光标。R071.5调查与取消契约见[响应性设计](workspace_responsiveness.md#r0715-阅读视口被旧光标覆盖)。未核对的宿主能力不得猜测；原生内容方法失败时沿用原生错误，不通过重新打开文档掩盖问题。所有方法适配、观察器与监听随工作台生命周期恢复和释放。

## 位置与源码服务适配

`native_markdown_position`以原生节点的序列化结果与同一份内存Markdown顺序匹配；代码块用CodeMirror可见行，普通块用块内比例。模式适配在原生show/hide前捕获视口中心，结束后及下一帧恢复对应行，不移动编辑光标。新可信输入、换文件和销毁取消未执行帧；不匹配的节点不猜测其他重复正文。

`native_markdown_editor`只适配现有CodeMirror，统一提供内存内容、版本、选区和导航位置，不创建第二模型。源码大纲复用现有Markdown标题解析与源码树呈现，编辑事件更新，取消过期订阅；渲染模式仍由原生标题大纲管理。共享导航端口登记native_markdown身份及编辑组，后退/前进沿共同历史，不建立另一条快捷键链。隐藏渲染层不采样或覆盖阅读位置。公共布局与状态栏几何不因模式复制，行号、撤销和编辑仍归原生。

## 验收

使用原始Typora隔离副本验证源码/渲染往返、原生菜单/快捷键/底栏同义入口、文件/大纲/其他功能面板及用户主动收栏。验证源码实际命中区域与编辑组一致、标签与底栏不被覆盖、分屏和终端改变可用矩形时仍一致。明暗、100%/125%缩放检查真实SVG边界与非悬停几何。源码编辑、撤销、保存、大纲定位、切文档、卸载恢复分别验收，不能以CSS替身或安装检查替代原生功能结果。
