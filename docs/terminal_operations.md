# 终端操作与配置

终端默认位于正文下方的独立面板。按 **Ctrl+`** 显示或隐藏，隐藏保留 Shell 与输出；按 **Ctrl+Shift+`** 新建终端。面板顶部使用紧凑图标，右侧显示会话列表；完整操作可从“更多”或会话右键菜单进入。

## 操作

| 操作 | 行为 |
| --- | --- |
| 新建与选择配置 | `+` 使用默认 Shell；旁边下拉菜单按所选配置新建，已有会话不被替换 |
| 拆分、取消拆分、合并 | 在同一面板中并排显示多个会话；取消拆分成为独立组，合并选择另一个组；会话保持各自进程 |
| 切换、重命名、颜色和图标 | 点击列表切换；双击或 F2 重命名；右键修改身份；长名称可悬停查看完整名称、目录和状态 |
| 移动到编辑器／面板 | 搬移同一 xterm 与 PTY；保留进程和缓冲，不重新运行 Shell |
| 高度与最大化 | 拖动上边界调整高度，也可聚焦分界线按上下键；右上角最大化／还原，隐藏后恢复正文空间 |
| 查找 | Ctrl+Shift+F；支持大小写、整词、正则与前后匹配；Escape 关闭查找 |
| 复制、粘贴、全选 | Ctrl+Shift+C/V；Ctrl+C 有选区时复制，否则发送中断；右键及系统粘贴共用多行确认 |
| 清屏、重启、终止 | 清屏仅清理显示；重启使用最新启动配置；终止释放对应进程；进程退出显示状态，可重新启动 |
| 列表键盘操作 | 上下键切换，Enter 激活，F2 重命名，Delete 终止所选会话 |
| 管理员终端 | Windows UAC 启动独立 PowerShell，定位所选目录；集成终端及 Typora 本身不提权 |

普通新建使用当前打开的工作区目录；无挂载目录时使用活动文件上下文，空窗口再使用用户主目录。Explorer 的“在集成终端中打开”使用选中文件夹，选中文件时使用其父目录。明确标注“仓库根目录”的原生菜单／Git 入口才查询 Git 根目录。

## 配置

从“更多 → 终端设置”进入。设置可搜索；所有字段通过校验后一起保存，错误不覆盖之前的有效配置。外观立即应用于已有终端；工作目录、环境变量和 Shell 参数在新建或重启后生效。

| 配置范围 | 可用设置 |
| --- | --- |
| Shell | 默认配置；自定义配置的 `id`、`title`、`executable`、`args`，以及独立的环境、目录、图标和颜色 |
| 目录与环境 | 工作区相对路径、`${workspaceFolder}`、`${env:变量名}`；环境变量字符串设置值、`null` 删除值 |
| 字体 | 字体系列、字号、字重、行高倍数、字符间距 |
| 光标 | 方块／竖线／下划线、闪烁、竖线宽度 |
| 滚动与显示 | 缓冲行数、平滑滚动、普通与 Alt 滚轮速度、最小对比度、制表符宽度 |
| 操作 | 右键菜单或复制／粘贴、选中即复制、粘贴多行确认 |
| 布局 | 默认面板／编辑器、会话列表左／右、单终端或单组时隐藏、拆分后使用初始目录／工作区目录 |

自定义配置示例：

```json
[
  {
    "id": "project_pwsh",
    "title": "工程 PowerShell",
    "executable": "pwsh.exe",
    "args": ["-NoLogo"],
    "cwd": "${workspaceFolder}",
    "env": {"PROJECT_MODE": "development"},
    "icon": "terminal",
    "color": "#007ACC"
  }
]
```

参数作为数组传入，不拼接 Shell 命令。配置和面板高度保存在 Typora 用户数据中，不向打开的项目写入本机路径或配置文件。主题读取 Typora 当前实际颜色；切换主题更新已有 xterm，不重新启动 Shell。

## Shell 自动识别设计

需求 R006.3.1，2026-09-12：用户截图指出新建菜单只显示四项固定名称，不能像 VS Code 一样识别本机已安装 Shell。修复前 `terminal_runtime` 的静态列表不检查可执行文件，把不存在的 PowerShell 7、Bash 当成可用配置；Git Bash、MSYS2 和 WSL 等安装没有进入同一发现流程。

目标是由一个异步探测服务生成真实可用配置，新建菜单、默认选择、设置和会话启动共用它。Windows 探测系统 PowerShell/CMD、PATH、标准安装目录及注册表中的 PowerShell、Git、MSYS2/Cygwin 安装；WSL 按已注册发行版区分配置，排除内部 Docker 发行版。注册表和 PATH 未覆盖的非标准位置仍可通过用户自定义配置表达。自动发现只核对候选，不遍历全盘，也不启动用户 Shell 配置脚本；终端模拟器自身不作为 Shell 启动。

探测结果是运行时缓存，不写入项目；用户自定义配置仍归 `terminal_settings` 所有，相同编号覆盖自动配置。按规范化路径、参数及必要环境去重，保留不同 MSYS 环境和 WSL 发行版。自动默认优先可用的新版 PowerShell，再回退系统 PowerShell/CMD；已保存的默认编号失效时保留设置并明确提示重新选择，不能把编号当可执行命令启动。

文件与注册表查询异步、有界并发，外部枚举设超时和输出上限，全扫描截止点为 6 秒；同时请求共享进行中的扫描。首次打开先展示终端会话与检测状态，进程启动等候扫描；后续读取缓存，菜单和设置提供重新检测，并显示局部查询失败提示；设置刷新保留等待期间用户的新选择。卸载取消正在运行的查询，迟到结果不再更新 UI；刷新不影响已运行会话。不可用候选不进入自动列表，局部探测失败不抹去其他有效结果。启动参数以数组交给 PTY，WSL 发行版和工作目录保持独立参数。

验证包括候选存在性、非默认安装路径、去重与环境差异、WSL 编号/参数、局部失败/超时/取消、默认配置保留和自定义覆盖；再以本机实际发现清单及真实 PTY 启动验证。UI 核对新建菜单和默认配置来源一致，刷新不清空运行会话，关闭界面/卸载无迟到更新。Linux 原生运行包、Shell 命令装饰与跨窗口进程不属于这次识别修复，继续保留 R006.3 的其他缺口。

实现参照 [VS Code 终端配置](https://code.visualstudio.com/docs/terminal/profiles) 的发现与自定义分工，并核对固定提交 `88e44fa0e00b08f7758b4f6d05632e4fd5e4df6f` 的 [terminalProfiles.ts](https://github.com/microsoft/vscode/blob/88e44fa0e00b08f7758b4f6d05632e4fd5e4df6f/src/vs/platform/terminal/node/terminalProfiles.ts) 和 [powershell.ts](https://github.com/microsoft/vscode/blob/88e44fa0e00b08f7758b4f6d05632e4fd5e4df6f/src/vs/base/node/powershell.ts)：Git Bash 使用 `bash.exe --login -i`，PowerShell 检查多版本与常见分发位置，WSL 使用 UTF-16 枚举及独立发行版参数。MSYS2 各环境按官方 [MSYSTEM 规则](https://www.msys2.org/docs/environments/) 区分，并设置 `CHERE_INVOKING` 保留初始目录。安装注册表与有限固定盘目录的补充探测是针对实际安装问题的独立实现，不宣称逐字复制 VS Code。

2026-09-12 验证：探测单元回归 14 项、设置回归 12 组通过；本机按真实机器／用户 PATH 扫描用时 672ms，发现 Git Bash、Cygwin、系统 PowerShell、CMD 和 6 个 MSYS2 环境。10 个配置经真实 ConPTY 验证标记输出、工作目录、MSYSTEM 与正常退出。启动验证禁用用户配置脚本，不证明各环境工具链或登录脚本完整；本机没有独立安装的 PowerShell 7 或 WSL 发行版，相关发现逻辑仅由夹具覆盖。完整检查、UI 与原生宿主结果见[反馈记录](feedback_review.md)。

## 职责与边界

`terminal_workspace` 统一编排操作，`terminal_profile_detection` 管异步发现与查询取消，`terminal_settings` 合并发现结果并管理配置，`terminal_session` 管 PTY，`terminal_surface` 管显示和输入，`terminal_panel` 管占用空间。创建失败、迟到的进程启动、重启与卸载均按生命周期取消；源码与 Markdown 编辑器不持有终端进程。

目前集成运行包支持 Windows 10 1903+ x64／ARM64，其中本轮真实运行验证为 Windows x64；Linux 原生终端运行包尚未提供。关闭 Typora 后不恢复旧进程及缓冲。列表宽度、组内分隔条和同窗拖放按下文R006.1管理；跨窗口进程移交尚未实现；Shell 集成命令装饰、远端终端、任务、调试器和扩展 API 也未实现。这些差异已记入需求台账，不能把当前面板与设置称为完整 VS Code 终端移植。

采用值及固定上游来源见 [设计基线](vscode_design_baseline.md)；配置、真实 PTY、界面及原生宿主验证各自的范围见 [反馈记录](feedback_review.md)。

## R006.1 分隔条与列表拖放

2026-09-13，用户在安装文档后优先推进日常操作。目标是在当前窗口调整终端列表宽度、组内分屏宽度，以及拖动列表排序；现有 PTY、xterm 缓冲、选区和活动会话继续由领域协调器持有，不通过重新创建终端实现移动。跨窗口 PTY 转移仍归 R006.2。

依据固定 VS Code 1.136.2（88e44fa0e00b08f7758b4f6d05632e4fd5e4df6f）的 `terminalTabbedView.ts`、`terminalTabsList.ts` 和 `terminalGroup.ts`：列表默认120px、窄图标模式46px、完整文字最小80px、最大500px；主终端最小120px，分屏最小80px。当前产品继续保留22px列表行、左右位置设置和单终端/单组隐藏设置。窄窗口按可用宽度收敛，不撑出横向溢出；用户设定的列表宽度保存在独立几何状态中，不改动终端配置或字体。

`terminal_layout` 管理列表分隔条和各组的会话宽度权重，容器变宽、换组、增减分屏时重新分配。权重以会话身份关联，排序后跟随同一会话；关闭后清理。`terminal_sash` 只拥有拖动与键盘生命周期：拖动实时布局，松开提交，Esc、指针取消、失焦或捕获丢失恢复本次开始值；方向键调节，双击恢复默认宽度或组内均分。所有变化触发原有 xterm resize，隐藏或移到编辑器不会终止 PTY。

列表复用原生 HTML 拖放。同组内拖动改变分屏和列表的相对顺序；跨组拖动移动整个源组到目标组前后，保留组成员；空白处放到末尾。落点用插入线即时显示，拖动结束才修改领域顺序；Esc/离开无有效落点不改变顺序。只接受当前窗口由该列表开始的拖动，拒绝外部文本、文件及其他窗口伪造的数据；合并/取消拆分继续使用已有菜单。重排期间保持活动会话身份，列表更新不能提前销毁正在拖动的行。

验收：真实指针拖动列表和分屏，左右位置/宽窄/缩放/明暗、键盘、取消、均分、增删/隐藏/编辑器搬移、同组/跨组/空白落点排序；核对 PTY 启动与终止次数、缓冲内容、会话身份、目标命中和卸载清理。公开环境没有物理跨窗口验证时不声称完成该能力。

## R006.7 输入法与按键所有权

2026-09-14，用户反馈搜狗中文选词正常，Shift 切换英文后无法继续输入。终端的键盘与组合输入由 `terminal_surface` 内的 xterm 持有；`terminal_session` 只接收 xterm 已提交的数据，不读取候选文本，也不补发字符。面板和编辑器中的终端复用该输入边界。

此前表面只隔离 `keydown`，其他按键与文本事件仍可冒泡到宿主编辑器。统一在终端容器的冒泡阶段隔离 `keydown`、`keypress`、`keyup`、`beforeinput`、`input`、`compositionstart/update/end`；不调用 `preventDefault`，也不强制重新聚焦。文本事件与普通按键继续交给 xterm；纯 Shift 的后续明确例外见下方“Markdown输入契约与Shift直接提交”。终端查找框同属此边界；其 Enter/Esc 与终端复制/粘贴/查找快捷键在 `isComposing` 或 keyCode 229 时交还输入法。事件监听随表面销毁释放。

依据当前固定依赖 xterm 6.0.0 的 `CompositionHelper.keydown/compositionend` 和 `CoreBrowserTerminal._keyUp/_inputEvent`：修饰键交给输入法，keyup 清理按键状态，组合结果与直接输入沿原生路径提交。[xterm 搜狗事件说明](https://github.com/xtermjs/xterm.js/pull/3680)还覆盖没有 compositionend 的直接 insertText 路径。本修复不改第三方内部字段、不维护第二套组合状态、不修改用户输入法配置或 Typora 原生文件。

验收使用隔离 Electron 的真实 xterm、Chromium 组合输入和按键，检查中文上屏、Shift 提交英文、继续 ASCII/大写/数字、取消候选、重复切换时数据恰好发送一次；检查候选期间快捷键与 Enter/Esc 不抢焦点、普通查找/退出可用、事件不泄漏到宿主以及销毁清理。搜狗实际安装版本和物理按键交互须单独说明验证状态，不能用合成事件替代实机结论。

### 2026-09-14 Shift候选拼音丢失复查

范围为本地终端表面已提交组合文本的完整传递，不改变输入法切换快捷键、系统配置或Shell协议。真实Chromium的追加式组合路径正常；按上游整值替换事件顺序回放时，已发送`中文pin`之后的第二次`pin`完全丢失，确认旧起点截断。

### 2026-09-14 Markdown输入契约与Shift直接提交

用户要求采用文档编辑时正常工作的输入法逻辑。核对原始 Typora 1.14.10：正文 Editor 使用 `#write`，组合开始后保护选区和 DOM，结束后读取实际节点并刷新；纯 Shift 不自行提交或删除候选。源码模式 CodeMirror 5.26.0 使用 textarea，组合期间不重置输入框，结束后轮询实际文本。这些行为确立共同契约：浏览器和输入法拥有候选及确认文字，应用不因修饰键抢焦点、清空候选或猜测补发。原生编辑函数绑定正文节点、文档模型与撤销，不能用于终端的 PTY 字节流。

本轮真实 Chromium 对照发现另一条已确认缺口：Shift keydown → `input(insertText, composed=true, data=pin)` → Shift keyup → 后续 `x`，没有 composition 事件；textarea 与 contenteditable 均保留 `pinx`，终端 textarea 也是 `pinx`，但 xterm onData 只有 `x`。固定 xterm 6.0.0 的 `CoreBrowserTerminal._keyDown` 在公开自定义按键回调之前设 `_keyDownSeen=true`，`_inputEvent` 因而过滤 Shift 尚未抬起时的确认文本。此前组合结束偏移与全局快捷键测试均未覆盖这条直接提交路径。[xterm 6054 提案](https://github.com/xtermjs/xterm.js/pull/6054)记录相同修饰键问题；[Tabby 11650](https://github.com/Eugeny/tabby/pull/11650)已于2026-09-11合并并报告 Windows 搜狗 Shift 实测，但 xterm 提案仍未合并，不声称 VS Code 已使用它。

由现有 `terminal_composition` 输入适配器在 xterm textarea 的父节点捕获纯 Shift keydown，只停止到 xterm 的传播，不取消浏览器默认行为。限定实际 textarea 目标、Shift 键或旧式 keyCode 16、没有 Ctrl/Alt/Meta/AltGraph，且不处于已登记组合或 isComposing/keyCode 229 状态。已开始的组合继续由 xterm 管理，避免直接 input 与组合结束重复发送。Shift 本身不生成终端字节，浏览器后续 input 与全部 keyup 照常进入 xterm，由原有输入路径发送一次。Ctrl/Alt/Meta 组合、Shift＋字符／方向键、终端查找和其他输入框不进入此例外。复用表面生命周期，搬移保留，销毁移除；不访问 xterm 私有字段，不引入第二套候选缓存、PTY补发、输入法配置或文档编辑器。

验收先保留同序列旧版红证据，再对照普通 textarea、contenteditable 与终端：左右 Shift、直接拼音提交、后续英文、无 composition、默认行为和焦点、Ctrl+Shift+F 与 Escape，以及既有组合开始／结束、整值替换、取消、正常终端字节和销毁。浏览器可信输入、原生宿主 renderer 回放与物理搜狗分别记录；不把上游他人的实测当成本机验收。并发 CDP 连续提交与0ms组合结束队列竞争另记调查项，不能据此扩展为改写终端输入引擎。

## R006 滚动历史容量与旧日志消失（2026-09-21）

用户反馈是向上翻阅时较早输出已经消失，而非一行被面板宽度裁掉。当前`scrollback`代码默认1000行，设置接受0至100000的整数；表示可视区域以上的滚动历史容量，不是Shell输出总量或命令历史条数。达到容量后，xterm淘汰最旧历史；折行会消耗缓冲行数。这与固定VS Code终端配置的默认1000行一致，见[界面基线](vscode_design_baseline.md)和[官方缓冲说明](https://code.visualstudio.com/docs/terminal/basics#_navigating-the-buffer)。

配置从“终端更多菜单 → 终端设置 → 滚动缓冲行数”调整；由`terminal_settings`唯一管理，`terminal_surface`将值应用于xterm。调大只影响仍保留的内容及后续输出，不能恢复已经淘汰的日志；调小可能立即缩减已有历史。关闭进程/窗口后的历史恢复不由此设置提供。此前用户会话的有效设置未读取，因此不能把代码默认值称为现场实测值。

Shell负责执行命令，PTY传输输出，xterm保存并绘制终端屏幕。当前正文经`terminal_session`完整交给`term.write(data, done)`，未发现另一份UI日志数组裁剪。broker对待消费输出使用暂停/确认/恢复流控，作用是限制积压，不是删除滚动历史；PTY客户端保留最后4000字符的stderr仅用于辅助进程错误诊断，不作用于Shell正文。

历史容量增加主要影响内存、查找及改变宽度时的重排，不等于把全部历史创建为同时显示的普通网页行。无限保留会持续增加资源需求；需要完整长期日志时应另行选择命令写入日志文件或独立记录能力，当前没有新增自动落盘。未经过压力验证，不给出容量与内存/卡顿之间的具体指标，也不把1000行称为唯一合理选择。

本轮仅核对配置、传输与渲染调用链并补充说明，不改变默认值、用户配置或发行资产。核对依据为`terminal_settings.ts`、`terminal_settings_view.ts`、`terminal_surface.ts`、`terminal_workspace.ts`、`terminal_session.ts`、`terminal_pty_client.ts`、`terminal_broker.cjs`及固定上游终端配置；未运行性能压测、未声称消除了用户现场所有日志丢失原因。后续若调整容量或增加落盘，应另行覆盖连续输出、查找、缩放/重排、隐藏/搬移和多会话的内存及延迟，并遵守成对安装卸载验证。
