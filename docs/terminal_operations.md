# 终端操作与配置

终端默认位于正文下方的独立面板。按 **Ctrl+`** 显示或隐藏，隐藏保留 Shell 与输出；按 **Ctrl+Shift+`** 新建终端。面板顶部使用紧凑图标，右侧显示会话列表；完整操作可从“更多”或会话右键菜单进入。

## 操作

| 操作 | 行为 |
| --- | --- |
| 新建与选择配置 | `+` 使用默认 Shell；旁边下拉菜单按所选配置新建，已有会话不被替换 |
| 拆分、取消拆分、合并 | 在同一面板中并排显示多个会话；取消拆分成为独立组，合并选择另一个组；会话保持各自进程 |
| 切换、重命名、颜色和图标 | 点击列表切换；双击或 F2 重命名；右键修改身份；长名称可悬停查看完整名称、目录和状态 |
| 移动到编辑器／面板 | 搬移同一 xterm 与 PTY；保留进程和缓冲，不重新运行 Shell |
| 高度与最大化 | 拖动上边界调整高度，也可聚焦分界线按上下键；右上角最大化／还原，隐藏后恢复正文空间 |
| 查找 | Ctrl+Shift+F；支持大小写、整词、正则与前后匹配；Escape 关闭查找 |
| 复制、粘贴、全选 | Ctrl+Shift+C/V；Ctrl+C 有选区时复制，否则发送中断；右键及系统粘贴共用多行确认 |
| 清屏、重启、终止 | 清屏仅清理显示；重启使用最新启动配置；终止释放对应进程；进程退出显示状态，可重新启动 |
| 列表键盘操作 | 上下键切换，Enter 激活，F2 重命名，Delete 终止所选会话 |
| 管理员终端 | Windows UAC 启动独立 PowerShell，定位所选目录；集成终端及 Typora 本身不提权 |

普通新建使用当前打开的工作区目录；无挂载目录时使用活动文件上下文，空窗口再使用用户主目录。Explorer 的“在集成终端中打开”使用选中文件夹，选中文件时使用其父目录。明确标注“仓库根目录”的原生菜单／Git 入口才查询 Git 根目录。

## 配置

从“更多 → 终端设置”进入。设置可搜索；所有字段通过校验后一起保存，错误不覆盖之前的有效配置。外观立即应用于已有终端；工作目录、环境变量和 Shell 参数在新建或重启后生效。

| 配置范围 | 可用设置 |
| --- | --- |
| Shell | 默认配置；自定义配置的 `id`、`title`、`executable`、`args`，以及独立的环境、目录、图标和颜色 |
| 目录与环境 | 工作区相对路径、`${workspaceFolder}`、`${env:变量名}`；环境变量字符串设置值、`null` 删除值 |
| 字体 | 字体系列、字号、字重、行高倍数、字符间距 |
| 光标 | 方块／竖线／下划线、闪烁、竖线宽度 |
| 滚动与显示 | 缓冲行数、平滑滚动、普通与 Alt 滚轮速度、最小对比度、制表符宽度 |
| 操作 | 右键菜单或复制／粘贴、选中即复制、粘贴多行确认 |
| 布局 | 默认面板／编辑器、会话列表左／右、单终端或单组时隐藏、拆分后使用初始目录／工作区目录 |

自定义配置示例：

```json
[
  {
    "id": "project_pwsh",
    "title": "工程 PowerShell",
    "executable": "pwsh.exe",
    "args": ["-NoLogo"],
    "cwd": "${workspaceFolder}",
    "env": {"PROJECT_MODE": "development"},
    "icon": "terminal",
    "color": "#007ACC"
  }
]
```

参数作为数组传入，不拼接 Shell 命令。配置和面板高度保存在 Typora 用户数据中，不向打开的项目写入本机路径或配置文件。主题读取 Typora 当前实际颜色；切换主题更新已有 xterm，不重新启动 Shell。

## 职责与边界

`terminal_workspace` 统一编排操作，`terminal_settings` 管配置，`terminal_session` 管 PTY，`terminal_surface` 管显示和输入，`terminal_panel` 管占用空间。创建失败、迟到的进程启动、重启与卸载均按生命周期取消；源码与 Markdown 编辑器不持有终端进程。

目前集成运行包支持 Windows 10 1903+ x64／ARM64，其中本轮真实运行验证为 Windows x64；Linux 原生终端运行包尚未提供。关闭 Typora 后不恢复旧进程及缓冲。当前拆分为等宽，会话列表没有拖放排序、拖动宽度和跨窗口进程移交；Shell 集成命令装饰、远端终端、任务、调试器和扩展 API 也未实现。这些差异已记入需求台账，不能把当前面板与设置称为完整 VS Code 终端移植。

采用值及固定上游来源见 [设计基线](vscode_design_baseline.md)；配置、真实 PTY、界面及原生宿主验证各自的范围见 [反馈记录](feedback_review.md)。
