## Responsibilities and Implementation

Shared theme services determine the light/dark based on the host's actual background, merge existing theme events frame by frame, and do not depend on the theme filename or system color. The color table centrally declares VS Code semantic variables and workbench roles, and existing controls read the same role; the domain only maps the root panel, title, input, and content areas, and does not generate color palettes individually. File icons and terminal share light/dark determination, but cannot use the terminal background to infer the host theme. The terminal screen uses the xterm theme API with the panel background, and cannot just change the outer layer to cause screen color blocks. Do not recreate the terminal, editor, or panel, and do not write user preferences.

Document content, code highlighting, media, web sandbox, native preferences and community settings are independent owners, and do not overwrite `--bg-color`, `--text-color` and other native theme variables on document/body. Theme switching only changes variables and existing terminal themes, and does not clear selection, scroll, expand states. Uninstalling releases theme subscriptions and restores original markings; loading failure retains the original readable interface.
