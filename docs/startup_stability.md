# R054 启动与功能区切换稳定性

2026-09-20：用户报告启动先显示 Typora 原样式再切换工作台，以及功能区切换闪现、覆盖和卡顿。目标是验证全过程并修复已证实的调用错误，不能用最终截图替代过程证据。

## 范围、判定与职责

- 启动、资源管理器／大纲／搜索／源码管理切换、侧栏关闭重开是本轮范围；既有文件保护、工作区恢复和主题功能必须回归，不扩充布局。
- 正常：宿主尚未可用时保留窗口控制和明确的启动状态；同一面板内异步加载数据，完成后更新内容。文件恢复和 Git 扫描耗时单独统计。
- 缺陷：启动把可操作的旧布局显示后再整体替换；可见侧栏换面板时先收起再展开；旧、新面板同时显示；迟到回调恢复旧状态；重复监听、节点增长和主线程长任务。单次耗时不能直接推出算法错误，必须记录阶段、输入规模和调用原因。
- 入口与静态 head 负责首次展示时序；核心 Sidebar 负责面板及宿主侧栏的显隐事务；业务模块只负责自己的数据和取消；语法初始化不得成为文件管理界面的无关前置依赖。

## 实现方案与失败行为

先用原始宿主隔离副本在 head 阶段采集 rAF、布局状态和 Long Tasks，再决定首次展示边界。不修改 ASAR，不隐藏正文来伪造加载速度，不增加固定等待或过渡动画。若必须延迟工作区展示，应明确标注启动状态、保留窗口关闭能力，并在初始化失败或超时时恢复原生操作，避免永久空白。

切换前解析有效目标；不同面板只移交内容所有权，已经打开的宿主侧栏不关闭。重复 show 不重复挂载和执行 onshow，同一活动按钮保留收起语义；无效目标保持原面板。真实内部大纲节点保持连接。独立高亮初始化在界面挂载后继续，取消及错误仍归常驻入口统一处理。

## 分层测试与证据

原始宿主基线已复现：head 采样 253.7ms 时旧正文可见，681.9ms 才出现工作台标题；20 次切换触发 20 次宿主 hideSidebar。首次展示采用 head 内独立就绪标志：仅在浏览器编排就绪时释放内容区域；窗口按钮始终保留，明确显示“正在加载工作台…”。上限沿用核心初始化的 15 秒，失败即恢复原生操作。这个上限是故障恢复，不是正常启动等待。它解决布局替换暴露，不表示启动计算本身已被消除。

加载提示沿用既有启动错误提示的13px/1.4字体、文件通知的16px留白和已定稿35px顶栏边界；颜色读取当前主题变量。这里没有新增VS Code布局取值，也不改正文或窗口缩放。明暗夹具分别验证就绪、失败和超时状态。

阶段测量进一步确认一次 73ms 长任务串联了 Git 注册（33.1ms）与浏览器注册（33.8ms）。在这两个独立注册阶段之间交还一次事件循环并复查取消代际，避免把可拆分任务连续执行；没有增加固定等待时间或动画。语法异步耗时不是主线程阻塞时长，单独记录。Performance 标记仅保留最新初始化的三个阶段，避免重载累积。

| 层级 | 实现测试 | 压力／性能 |
| --- | --- | --- |
| 单元 | 核心真实 Sidebar，目标校验、显隐调用次序、重复 show、关闭重开 | 20/100/1000 次切换，调用数线性且内容单一 |
| 功能 | Electron 真实编排，延迟语法初始化、取消与重启；静态样式首帧及失败恢复 | 逐帧检查而非固定 sleep 后截图，记录阶段耗时 |
| 系统 | 原始 Typora 1.14.10 隔离安装，head 提前采样，真实命令和原生侧栏 | 默认 20 轮跨面板切换，记录长任务、分位耗时、正文哈希与面板数量；100/1000 留给低成本层 |

时序样本保存到忽略的运行目录，正式报告保留候选摘要、环境、用例和结果。不可见私有桌面的 PrintWindow 可能返回旧画面，不把它作为首次合成帧证据；rAF/DOM 状态也不等同于显示器视频。耗时超过 50ms 的任务记录供归因，不用宽松全局超时冒充性能通过。不能在当前环境复现的场景保留未决项。

在 `enhancements/` 中复验：

```sh
npm run test:quality -- --id TC-sidebar-transitions
npm run test:quality -- --id TC-sidebar-stress --tier 1000
npm run test:quality -- --id TC-startup-presentation
npm run check:ui -- test_workspace_startup.cjs
npm run test:quality -- --id TC-startup-native
```

原生用例先把 `TYPORA_NATIVE_TEST_ROOT` 设为已核对的宿主安装目录。20和100档替换压力命令中的档位即可；单独执行原生测试用于测量，不与全套检查争用资源。原生夹具从复制的宿主启动新进程，结束仅关闭测试副本；生产窗口由用户保存后手动重启。
