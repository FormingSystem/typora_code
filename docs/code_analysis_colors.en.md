# R068.4 Code Analysis and Color Consistency (2026-09-27)

The source code editor and search source code preview originally used Monaco's built-in Monarch and vs/vs-dark, and the main content panel had already used the official TextMate; due to different tokenizers and themes, the same C code showed differences in macros, functions, types, and background colors. The goal is to unify the lexical and theme sources, and use the existing clangd to supplement the true dependency on the engineering context, not to guess the type based on the identifier name.

Without clangd or service failure, retain lexical coloring, cannot consider color visibility as compilation correctness. Do not execute query-driver, PCH only memory and do not execute engineering scripts. R068.6 has expanded engineering backend index, cross-file navigation/references and source code diagnostic markers; still does not increase completion, refactoring and independent diagnostic panel; Markdown example fence has no complete engineering context, only lexical coloring.

Python installation python-lsp-server after can be used:

```json
{
  "python": {
    "provider": "lsp",
    "command": "python",
    "args": ["-m", "pylsp"],
    "settings": {"pylsp": {"plugins": {"pycodestyle": {"enabled": false}}}}
  }
}
```

command uses the system PATH or the absolute path entered by the user; when installed to different Python, the interpreter path should be filled in.
