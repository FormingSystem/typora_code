# R040.1 工作区切换与状态隔离

2026-09-19用户反馈：打开文件夹或最近目录后，文件树、已打开文件及Git仍停在上一目录，可能误改旧工程。本需求替代此前“仅挂载新目录并保留旧文档”的设计。关联R007文件入口、R040最近目录、R027 Git刷新、R006终端、R037时间线和搜索/导航。

## 行为与边界

打开文件夹、最近目录、Git工作树的当前窗口打开和关闭文件夹共用切换流程。先校验目标，检查进行中的保存、文件写入和Git写操作，再处理未保存文档。取消或保存失败保留原工作区；成功后关闭旧编辑器及工具标签，清理旧搜索、导航、固定时间线和Git控制器，文件树及底栏从新根目录重新读取。当前窗口的终端属于旧工作区，切换前明确提示会结束这些会话；独立管理员窗口不在本窗口管理范围内。

普通打开文件继续作为当前工作区的文件操作，不暗中把根目录改成文件父目录。显式“在新窗口打开”保持独立窗口，原窗口不变化。同一目录重开刷新所属资源与Git，不关闭当前文档。新目录以空编辑区开始，用户再打开目标文件；本轮不新增多根工作区、工作区文件、VS Code扩展宿主或完整跨重启布局恢复。

未保存文档通过已有保存服务处理，允许全部保存后切换或取消；不自动保存、丢弃或把旧草稿带入新工作区。本工程没有VS Code的完整热退出备份体系，因此不用静默热退出冒充草稿已安全保存。已保存到磁盘的内容不会因后来取消回滚。目标校验和关闭前复核必须完成后才能提交切换，旧读取结果通过工作区代次失效。切换期间重复请求不交错执行。

## 上游与宿主依据

固定VS Code 1.137.0提交`645f29cc3176500b4b5762ba887cf2a7f0ffdf2c`：`src/vs/platform/windows/electron-main/windowsMainService.ts`的`shouldOpenNewWindow`读取`window.openFoldersInNewWindow`及显式窗口选项；`doOpenInBrowserWindow`在复用窗口前通过`lifecycleMainService.unload(..., UnloadReason.LOAD)`处理否决，再加载目标工作区。`src/vs/workbench/services/host/electron-browser/nativeHostService.ts`把文件夹身份交给窗口服务。本工程采用其“切换工作区生命周期、先保护未保存内容”的行为，保留现有当前窗口/新窗口入口，不声称读取用户VS Code私有配置。

原始Typora 1.14.10的`File.setMountFolder`只赋值挂载路径，不关闭标签或发布完整工作区生命周期。现有Git`context_path`优先活动标签，且只订阅活动标签变化，造成切根后旧文档和旧仓库继续有效。新增共同切换协调，宿主仍只负责原生路径与最近目录存储；不修改ASAR，不重新初始化整个工作台。

## 实现职责与影响

- 文件服务：检查全部编辑组、保存草稿、关闭已确认安全的叶子，旧打开请求在代次变化后不得创建标签。
- 目录入口：系统选择/路径验证/串行切换/最近目录写入；目标身份变更仅在预检通过后提交。
- 公共工作区生命周期：统一代次、写操作否决和切换通知；共享临时界面退出，旧菜单不跨工作区执行。
- 文件树/搜索/快速打开/导航/时间线：取消旧读取，清除旧选择、固定目标及历史跳转，重新读取新目录。
- Git：切换时释放旧控制器与读任务，重新创建当前根对应状态；无Git目录显示无仓库，不借旧活动文件兜底。
- 终端：取消等待启动的旧请求，按已确认的切换结束当前窗口旧会话；新会话使用新工作区根。

## 验收方案

单元覆盖切换代次、取消、重复请求和迟到结果；功能覆盖A→B→A、最近目录/系统选择/关闭/同目录、脏Markdown与源码、多分栏、搜索、固定时间线、Git与非Git目录、写操作阻止切换。压力以20次完整切换及100/1000次低成本代次/迟到请求组合检查旧标签和监听器残留。隔离原始Typora使用专属临时双仓库验证真实宿主挂载、资源树、Git底栏与旧文件隔离，比较测试文件字节与索引；不操作用户真实仓库。最终候选构建、相关回归、安装校验和运行窗口是否重启分别留证。

## 实现与验证记录

2026-09-19实现：`workspace_open_dialog`协调当前窗口切换，`workspace_files.prepare_workspace_switch`负责草稿与编辑组关闭；`workspace_context`只持有切换代次和写操作否决，不复制根目录。文件树、搜索、时间线、导航、Git和终端订阅同一完成通知。旧Git控制器及其订阅一起释放，延迟文件历史入口复核控制器存活；旧导航完成不能恢复已清空的历史索引。Windows路径大小写及末尾分隔符按同目录处理。

原生路径已提交但缓存刷新异常时仍发布领域切换通知并反馈错误，避免出现新根目录配旧Git状态。底层宿主挂载异常不会被宣称为成功；关闭前已保存的数据保留。工作区根和普通文件打开是两种操作，不拦截用户明确再次打开旧目录文件的行为，也不删除跨工作区保存的本地历史记录。

新增`TC-workspace-switch-ui`、`ui-stress`、`context`、`history-stress`和`native`分类用例，统一见`enhancements/tests/test_catalog.json`。功能用例能在修复前版本的旧标签残留处失败；新版覆盖目录切换、保存失败与取消、Git写操作否决、搜索与固定时间线、终端、原生刷新异常及20次连续切换。单元压力为20/100/1000次拒绝/取消/提交与迟到导航结果。系统用例通过原始Typora 1.14.10副本验证Markdown与分栏、草稿保存和取消、宿主最近目录以及20次切换；输入为renderer事件/宿主API，不冒充物理鼠标或跨平台验收。

## R040.2 按工作区恢复上次打开的文件

2026-09-19用户补充：上一版清理旧目录状态正确，但启用恢复配置后重新进入目录应继续打开该目录上次的文件。本节替代“新根目录总是空编辑区”的约定；不改变草稿保护及领域隔离。

配置沿用Typora原生`restoreWhenLaunch`：偏好设置中2为“恢复上次关闭的文件和文件夹”，0/1/3不自动恢复文件。每次恢复读取当前原生选项，不新建同义开关。固定VS Code 1.137.0提交645f29cc3176500b4b5762ba887cf2a7f0ffdf2c的`src/vs/workbench/browser/parts/editor/editorPart.ts`以`StorageScope.WORKSPACE`保存编辑组；本次采用按工作区隔离的文件会话语义，不移植完整编辑组网格和热退出备份。

会话服务唯一持有打开文件记录：以规范化绝对根目录的摘要作为用户数据目录中的独立记录键，Windows大小写和尾分隔符归一；保存文件顺序、原生Markdown/源码方式、固定状态及活动文件。空编辑区写空列表，不能退回全局最近文件；工具、差异、终端、空占位和未命名草稿不序列化。多个分栏中的同一文件/编辑方式去重，恢复到现有主组，不声明恢复分栏几何。目录外由用户明确打开的文件属于该会话，不能把目录外文件一概过滤。

切换前完成保存/取消预检，再同步原子保存旧会话；持久化失败中止切换并反馈。切换期间暂停会话采样，旧编辑组关闭与Git/搜索/时间线清理完成后再恢复目标会话。逐文件经共同文件服务打开；丢失或无法读取的文件跳过并汇总提示，保留其他可恢复文件。恢复期间切换入口串行；销毁取消未完成打开，不让旧恢复任务污染新工作区。打开、关闭及活动文件变化去抖持久化，退出前同步补存；每个根独立原子替换，多个窗口不覆盖其他根的记录，同根最后一次记录为准。

启动时等待工作台常驻模块就绪后恢复当前挂载根；已由宿主明确打开的文件优先保留为活动文件，未保存原生草稿不被恢复任务替换。没有历史记录的目录保持现有文件或空状态。正常退出重开使用磁盘记录；不恢复未保存正文，草稿继续由既有保护机制处理。

验证：纯存储单元检查20/100/1000次写读、根隔离、空列表、损坏/超限输入及原子失败；真实Electron验证A→B→A顺序/活动文件、关闭最后文件、配置关闭、缺失文件、取消及保存失败、生命周期释放。原始Typora隔离副本验证Markdown与源码、实际原生配置、切换后的Git身份及持久记录；重启恢复须有新进程证据，不能拿内存往返冒充。构建、安装、运行窗口加载分别记录。

实现调查补充：原生核心eachLeaves将truthy回调结果视为提前停止。原切换代码直接返回Array.push长度，单个组实际只检查/关闭一项；测试替身forEach未暴露该差异。本轮改为显式void回调，原生夹具同样修正遍历，验证多文件全部参与草稿保护、快照及关闭。核心遍历为逆序，持久化顺序按标签DOM顺序采集，不能直接保存遍历序。配置读接口经原生验证为偏好页setting.getExtraOption；setting.loadAll不包含restoreWhenLaunch。
