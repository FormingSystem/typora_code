## R038 保存与历史恢复

统一设置入口采用VS Code键名和语义，存入现有工作台用户设置。桌面自动保存默认`off`，支持`afterDelay`、`onFocusChange`、`onWindowChange`；延迟默认1000毫秒。支持`files.autoSaveWorkspaceFilesOnly`和`files.autoSaveWhenNoErrors`，诊断错误来自现有Monaco模型。设置更改立即应用。自动保存不创建未命名文件，不切换标签、不弹保存位置选择框；源码继续使用文件服务的冲突检查和实际成功结果。保存失败保留草稿，并停止对同一失败内容反复重试，下一次编辑或显式保存可重试。当前配置落在工作台用户级设置，未移植VS Code的完整工作区和语言覆盖体系。

原生Markdown通过已经核对的`File.updateChangeCount`取得修改信号，成功写盘的`app.sendEvent/didSave`取得结果路径，覆盖另存为；不把保存前事件当作成功。运行期间由统一服务接管`File.option.enableAutoSave`，宿主草稿备份继续保留，原生自动保存菜单写入转交统一配置。自动写回调用`File.saveUseNode(false, true)`的静默路径；窗口失焦时只在同步调用入口临时允许当前宿主文档保存，返回后立即恢复真实前台状态。真实冲突处理、编码和错误结果仍属于Typora的保存实现，本工程不替换宿主写盘算法。

本地历史与自动保存各自负责一件事：自动保存触发写回，本地历史在成功保存后保存实际落盘字节。历史独立于Git、项目目录和当前打开的文件，放入应用用户数据目录`typora_code/History`。历史默认开启，每个文件256 KB、50条记录、相邻10秒保存可合并；大小、条数、合并窗口和glob排除规则可配置，不扫描VS Code或其他应用的私人备份。每条快照独立原子发布并验证摘要；同一文件的串行保存使用单调时间戳排序，避免同一毫秒的记录颠倒。

“查找要恢复的条目”先列出本应用历史中的文件，选择后列出保存时间；选版本打开与当前文件的比较，已删除文件可直接查看旧版本。选择版本本身不恢复文件。恢复动作先核对当前草稿及磁盘身份，并保留恢复前内容；与上游一样在真正恢复时明确提示。本工程选择先保存未保存草稿并留存快照，再恢复版本；这比上游直接放弃未保存草稿多了一步保护，保存冲突会中止恢复。恢复失败不能标为保存成功。关闭历史记录或排除当前文件时，需先允许保留恢复前版本才可覆盖。文件及目录重命名后，已有历史迁往新路径。

## R052 空编辑区与最后一个文件

2026-09-19用户对照VS Code反馈：无打开文件仍显示New tab，最后文件难以关闭或更换。根因分为三处：core.empty布局占位被当成文档；已关闭的原生Markdown仍有缓存，同路径打开跳过磁盘读取；回收当前Markdown后宿主将旧正文变成隐藏dirty草稿，后续打开受到拦截。

### 范围与行为

空列表保留“打开的编辑器”分区标题，默认minVisible为0，无假行；真实空路径未命名草稿、工具编辑器保留，原有显示/排序/可见行设置不变。不新增面板或导入完整VS Code配置体系。固定VS Code 1.137.0提交`645f29cc3176500b4b5762ba887cf2a7f0ffdf2c`的`src/vs/workbench/contrib/files/browser/views/openEditorsView.ts`以`g.editors`生成行、`g.count`计算真实条目，不统计空组占位；默认最小可见项为0。

关闭最后文档后，空占位关闭为幂等无操作；未固定时间线清除旧目标，固定时间线仍遵守用户选择；底栏不再显示缓存文档字数/拼写，真实Markdown重开时恢复。布局、未命名草稿与宿主缓存的身份不得混用。

### 实现与状态所有者

- `workspace_file_uri`提供唯一空叶子判定；Explorer只消费真实叶子，文件关闭服务拒绝移除空占位，底栏复用相同判定；时间线仍拥有固定状态与请求代次。
- 阅读导航在串行打开事务中处理“目标等于宿主缓存、但已无该Markdown叶子”：非dirty时await宿主`File.reloadFromDisk()`，不传强制丢弃，再打开。已打开的分栏/后台草稿不重载。失败、取消或身份变化停止导航。
- 文件回收事务执行前捕获原生路径和正文，拒绝dirty或忙状态；原生适配`prepare_deleted_native_document`在回收成功且身份/正文保持时，通过`File.loadFile("", true)`切到新空文档。该宿主接口会把新空文档标dirty，因此只有实际路径与正文皆空才调用`NSChangeCleared`，不能清除非空草稿标记。
- 原生释放发生在移除目标叶子之前，避免清空随后激活的其他文件；回收失败不关闭叶子、不退化为永久删除。删除期间正文变化保留编辑器并提示另存为；已切到另一文档则不触碰它。文件操作进行中禁止工作区切换。只执行真实宿主接口，不改写bundle、ASAR或伪造磁盘保存。

宿主依据为已核对Typora 1.14.10原始`appsrc/window/frame.js`的`loadFile`、`reloadFromDisk`和`ChangeType.NSChangeCleared`（ASAR摘要见原生证据）。`document.switchToUntitled`只转换主进程身份并保留快照，不能独立释放renderer旧正文。
