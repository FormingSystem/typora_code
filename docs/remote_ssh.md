# R070 SSH远程工作区

2026-09-22：用户授权左侧远程入口，用SSH管理远程Markdown与项目，每个独立功能验证后提交并推送。用户指定测试主机从本机映射和OpenSSH配置确定；账户和凭据不写入版本控制。

## 上游与目标

以[VS Code Remote SSH官方操作](https://code.visualstudio.com/docs/remote/ssh)的连接主机、认证反馈、远程目录、编辑保存和断开为交互依据。它在远端运行服务，不把网络映射盘当作SSH；本项目同样通过SSH执行远程文件操作。固定工作台基线`88e44fa0e00b08f7758b4f6d05632e4fd5e4df6f`的`remoteExplorer.ts`定义远程视图容器，图标使用固定Codicons的`src/icons/remote-explorer.svg`，字号、树行、菜单和按钮复用本工作台共同规则。

## 实施与交付次序

1. SSH连接、取消和诊断，远程目录浏览、文本读取/编辑/冲突保护保存；Markdown阅读与源码编辑，独立远端身份和草稿保护。先完成可用读写闭环并真实验证。
2. 远程项目操作继续接入相同连接服务：文件管理、终端和Git能力逐项核对现有所有者后实现。每项未实装的上游能力保持明确未完成，不以入口或首个读写测试冒充全部Remote SSH。

VS Code Server、扩展宿主、调试和完整端口转发并非本项目既有能力，不能宣称已支持。首个远端后端以Linux/Python3为验证环境；其他远程系统支持按实际适配与测试记录。

## 所有者与失败行为

- OpenSSH是认证、主机密钥和SSH配置的唯一所有者，保留用户`~/.ssh/config`、代理与密钥配置。首次主机确认通过认证提示明确展示；变更主机密钥不绕过。密码/口令仅经短生命周期认证管道传递，不进入命令行、持久化配置、远端源码或日志。
- 连接服务拥有一个SSH进程与请求代际、超时和取消；UI只订阅状态。远端Python进程按JSON请求处理路径，不将文件名拼接为Shell命令；不安装或启动后台常驻服务。
- 远程资源包含连接身份和POSIX路径，不能交给本地fs/Git/宿主打开。编辑器拥有当前正文及已读摘要；读写失败或断线不清空正文、不冒充已保存。
- 保存先核对基线摘要和真实文件身份，写同目录独占临时文件后原子替换；保留权限并清理失败临时文件。外部变化明确拒绝覆盖。检查与替换间仍存在非协作写入竞态，不声称跨进程CAS。
- 关闭、切换连接、退出与工作区切换先保护未保存内容；远程工具不能绕过现有统一保存/关闭服务。迟到结果不写入新连接或新标签。
- 连接参数只保存非机密部分。断开后可重连，不自动反复弹认证框。

## 首期操作与边界

左侧远程资源管理器中输入SSH配置别名或`user@hostname`，点击连接；已有Host别名作为输入建议，端口、密钥和代理沿用OpenSSH配置。主机指纹必须先核对，密码不保存。连接后从远端用户目录逐级打开项目目录，上一级/刷新始终操作当前远端。

点击文件打开独立文本编辑标签，Ctrl+S或保存按钮写入远端；UTF-8 BOM和编辑器行尾保留，不支持二进制或非UTF-8编辑。Markdown可切换共同只读预览；当前预览不加载图片、不跟随其中链接。新建采用排他创建，重名不会覆盖；删除仅针对打开的单个文件，明确永久删除，按已读版本拒绝删除外部修改。保存保留权限，文件所有权/ACL/扩展属性不保证沿用；首期不支持跨窗口移动、远程自动保存、会话恢复和远程本地历史，关闭仍保护内存草稿。

SSH模块复用公共侧栏、语义交互、Codicons/Seti、Monaco、阅读渲染及文档关闭服务。工具栏随可用宽度换行，沿用现有社区侧栏13px/35px标题角色和目录26px行，不声称VS Code Remote SSH界面像素等价。目录最多10000项，分批200项绘制，读取/保存上限16MiB，预览2MiB；超限反馈而不静默截断。

## 第二期：远程项目终端与Git状态

2026-09-22继续实施：在当前远程目录提供“项目终端”和“Git状态”。前者复用已有底部PTY/xterm和启动进度，启动系统OpenSSH交互会话并切到远端选中目录。终端认证直接在终端完成，不把文件连接密码再次注入命令；会话独立，文件连接断开不静默终止Shell，用户通过终端关闭入口结束。

终端会话的临时启动配置由终端服务拥有，保持原配置不落盘；移动和拆分保留/复制远程启动身份，不能回落为默认本地PowerShell。远端路径单引号转义，参数不展开本地workspace/env模板。错误保持终端状态可见。Git状态由远端执行固定只读status命令，不调用本地Git控制器；远程修改、提交、拉取等由项目终端正常操作，首期不把本地Git Graph伪装成远端Graph。

验收：特殊目录名转义、固定SSH参数、临时会话选择和重启/拆分、真实PTY认证、pwd与Git仓库身份、断线和普通本地Shell回归；不在用户已有项目提交或推送测试数据。

当前目录工具栏点击“项目终端”后在底部立即显示SSH启动状态；终端内按提示认证，已有密钥/代理按OpenSSH配置使用。点击“Git状态”只读显示分支与工作树摘要，可刷新；非Git目录、缺少Git、超时明确显示原因。项目终端关闭不结束文件连接，文件连接断开也不结束已打开的终端。拆分/重启返回启动时选择的远端目录，不跟踪Shell运行中自行cd后的目录。用户Shell启动脚本仍可改变目录。

## R070.3 VS Code交互复核与慢操作隔离

2026-09-22用户再次明确SSH同样以VS Code为准。核对官方Remote SSH说明的“Connect to a remote host”“Opening a terminal on a remote host”：连接有进度和诊断，远端目录与命令共享明确的远程身份，编辑和终端不能被查询窗口锁住。沿用本项目固定工作台视图/编辑组契约；以下表格区分现有功能和仍需补齐的交互，不将基础SSH读写表述为完整等价。

| 操作 | 当前实现及差距 |
| --- | --- |
| 主机连接与认证 | 复用OpenSSH配置与认证，提供取消和错误；主机历史/配置管理界面仍需对照补齐 |
| 远端文件夹/工作区 | 目前独立SSH目录浏览与编辑标签；尚非完整远程工作区，不能把本地搜索/Git命令应用到远端 |
| 终端 | 明确的项目终端在远端目录启动；默认新建终端仍由本地工作区决定，不宣称VS Code远程窗口语义已完成 |
| Git | 远端只读状态、写操作使用项目终端；远程SCM/Graph尚未接入 |
| 断线与草稿 | 保留内存正文，重连原主机后可保存；会话恢复、自动保存与历史仍待实现 |
| 扩展/调试/端口转发 | 尚未实现，不显示虚假可用入口 |

本次修复范围：Git状态改为独立只读审阅标签，同主机和目录复用一个标签，进度/错误/刷新都留在本视图；可切换其他文件或关闭标签，不弹模态窗。标签身份固定到原主机/目录，断线不清空已显示结果，错误可重试；关闭后丢弃迟到展示，不以关闭标签断开其他SSH操作。身份验证与破坏性删除继续按各自语义确认。

远端文件协议保留串行文件读写，以避免引入写入竞态；仅固定只读Git查询放到一个有界独立执行槽。正在查询时其他Git请求明确反馈忙碌，不积累无限后台任务，目录与文件请求继续响应。查询最长15秒；关闭视图撤销展示，不承诺取消已发送的Git进程，连接退出清理执行资源。JSON输出用同一锁逐行发送，保证并发响应不交错。

验证必须包含：注入慢Git后同连接读写先完成；重复Git请求有界且失败可重试；真实空仓/非仓/嵌套仓状态；Git标签复用、关闭/断线/失败后迟到结果、本地编辑/终端不中断；明暗与缩放采用共享控件。真实SSH与原生Typora分别记录环境，替身不得冒充实机；本次安装及卸载必须使用同一候选。
