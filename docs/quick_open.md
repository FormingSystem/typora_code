# R058 文件快速打开

2026-09-20：修复顶栏与 Ctrl+P 共用入口的路径漏匹配、错误排序与缺少高亮。截图工作区不同，验收必须固定同一目录和查询；不跨工作区拼接文件。目录查询如 `samples/bringup` 返回该路径匹配的文件，目录本身不作为可编辑文档。

## 设计与职责

查询准备、文件名/路径评分、高亮范围及同分比较采用 VS Code 1.136.2 固定提交 `88e44fa0e00b08f7758b4f6d05632e4fd5e4df6f` 的 `fuzzyScorer.ts`（MIT，保留上游源码与许可），由本地适配层连接文件条目；UI 不另算匹配位置。依据 `anythingQuickAccess.ts`：路径分隔符等价，多词全部命中，引号要求连续匹配，文件名优先规则在路径查询时调整，同分比较匹配紧密度、长度和名称。上游第三方名称仅限 vendor 边界。

目录枚举属于选择器会话，最多4个并发；移除50000项硬扫描截止，仅虚拟绘制可见行。评分分时间片，完整保留有序结果；关闭/切库/销毁使扫描与评分失效，迟到结果不能恢复旧工作区或打开旧文件。文件打开继续走唯一文件服务，失败显示原因，不能清空当前文档。扫描失败明确提示不完整；空结果显示当前搜索目录，避免无内容弹窗。

名称和父目录分别按上游返回范围渲染文本高亮，使用文本节点防止文件名注入；选中行高亮仍可辨认，路径不整体降透明。使用22px行与含边框600px宽度，窄窗口不溢出，保留公共焦点/关闭机制。新增键盘语义不改变整个工作台布局。

## 验收

单元：固定上游对照文件名、路径、反斜线、多词、引号、Unicode、长路径、同分顺序与高亮；功能：真实 Chromium 输入/键盘、选中/未选中高亮、错误、取消、切库；系统：临时真实文件目录打开目标；压力：超过50000候选的后段命中、快速输入与事件循环间隔，20/100/1000查询。证据登记测试目录并关联本设计。

上游搜索后端是独立文件搜索服务；此工程保留本地枚举与宿主文件服务，不声称移植 VS Code 扩展宿主。当前保留 `.git` / `node_modules` 默认枚举排除；显式相对或绝对文件路径会另外探测存在性，可直接打开排除目录中的已知文件。目录符号链接不递归。未迁移 VS Code 的 MRU 历史分组、完整 search.exclude/files.exclude 配置体系及远程搜索服务；本需求三项缺陷的匹配、排序和高亮按固定算法验收，不能将此称为全部Quick Open功能等价。

## 性能与错误处理

移除50000扫描截止和自定义负分过滤；2026-09-25按R075取消512候选上限。候选按固定比较器排序；虚拟列表使用22px固定行高，只挂载视口及少量前后行，滚动和键盘可访问全部项。ResizeObserver、监听器、计时器按选择器所有者释放。读取失败明确提示不完整；输入框悬停显示当前根，空结果直接显示范围。打开进行中去重，切库事务及epoch变化拒绝旧动作；文件服务失败保持结果和现有文档。

首次把100候选提升到512但全量构建DOM时，5万候选基准出现64ms事件循环间隔。改为可见行绘制后同机目标测得19ms，输入同步处理10ms；这是一次隔离Chromium测量，不是所有硬件性能保证。

## R058 2026-09-21 搜索空窗与异步路径探测

反馈：已打开的源码文件输入完整相对路径后仅剩输入框。本次小工作区和原始宿主直接查询可通过，现场触发条件尚未完全复现；不能据此认定用户操作错误。

已发现的缺口：显式路径的stat位于整个筛选之前，等待期间清空结果且未使“正在筛选”可见；磁盘探测迟迟不返回时，目录中已枚举的匹配文件也无法显示。扫描刷新还会反复取消同一查询的分片计算。目标是使已知候选可立即筛选，路径探测独立补充，扫描增量不饿死当前排序。

选择器持有查询、扫描和路径探测的生命周期；路径探测异步完成后仅补充当前根、当前查询的候选，不阻塞已知结果。文件不存在继续普通搜索，权限或设备错误明确显示，等待阶段显示实际状态。关闭、切库、新查询均拒绝旧探测结果；Enter等待新查询的有效结果，不能打开前一查询的文件。同查询扫描增量等待当前分片结束后合并，输入新查询立即取消旧评分。保留原有匹配、排序、高亮和文件服务，不增加新面板或改用户排除配置。

验收补充：延迟stat时已枚举文件仍显示并可打开、未枚举显式路径完成后出现、迟到路径不覆盖新查询、扫描过程中状态可见、关闭/重开清理及连续输入；保留原始宿主完整路径/源码已打开场景。关联用例沿用TC-quick-open-ui、TC-quick-open-stress及TC-quick-open-native，现场重启复核边界单独记录。

固定上游anythingQuickAccess.ts的快速候选/异步additionalPicks与取消令牌已复核；本工程将已枚举文件作为可用候选提前呈现，属于本地扫描实现适配，不宣称新增了上游MRU分组。

本次构建、完整check、3组UI及原始Typora30项检查通过，安装/两种卸载/重装及本机交付通过；详见[2026-09-21异步搜索证据](../enhancements/tests/evidence/quick_open_async_20260921.json)。用户窗口未重启，需正常重启复核现场；未推送。

## R058.1 共同目录服务与快速打开复用（2026-09-27）

问题：资源树、快速打开、正文搜索与Git子仓库发现虽然使用同一个文件访问适配，但各自readdir；快速打开关闭时丢弃目录，重开完整遍历。用户进一步明确要求统一架构接口。

共同职责：workspace_directory_service管理同一文件系统身份下的目录快照、并发读取合并、目录变更通知、快速打开名称目录以及清理。原始IO仍由workspace_resource_fs负责本地/SSH路由；资源树拥有展开与选择，搜索拥有查询/正文读取及忽略规则，Git拥有仓库发现策略和Git命令结果，不能把Git历史当作文件名索引。固定VS Code 6807068的fileService.ts提供文件变化事件，ExplorerService消费文件服务，文件快速打开缓存由文件搜索所有者管理；采用共同文件服务/领域投影分工，不照搬扩展宿主。

生命周期：窗口内复用，以文件系统对象、工作区根和连接代次隔离。首次需要时扫描文件名；反复打开只订阅同一结果，关闭取消自己的结果呈现，不重复启动相同IO。修改只使相关目录与名称投影失效；手动刷新、工作区切换、已知文件操作通知都走同一入口。本地可用时一个递归watch监视根，其他本地平台用已读目录的共享watch；远端缺少递归事件端口，仅展开目录沿用共享轮询，名称扫描不为未展示目录创建长期轮询且不保留无法验证的完整缓存；不让每个UI再持有一套。监听失效则下次读取重试，不把失效目录永久当作有效缓存。释放最后一个持有者/切库时关闭watch、取消迟到发布并释放目录，不写磁盘缓存或配置。

失败：读取错误不缓存为成功；关闭/换根不发布旧结果；文件正文与Git状态不从名称缓存推断。目录过滤、符号链接边界、Git忽略、读取并发仍按各领域策略。无可用watch的环境不能承诺外部变更即时通知，重新打开时重新验证目录；保留手动刷新。

验收：初次/重复20及100次打开的readdir次数、资源树先展开再搜索共享同一读取、正文搜索/Git发现共同入口、创建/重命名/删除/内容修改、并发读取、扫描中修改、失败重试、取消/换库/销毁及监听回收；真实宿主复核搜索关闭重开无重新计数，统计和界面响应分开记录。SSH由独立适配夹具验证，不声称本次实连企业远端。

本次远端边界：共同接口与身份接线适用SSH，但远端完整名称目录暂不跨搜索会话复用；需远端递归变更端口才能安全实现与本地相同的长期缓存。此边界保留正确性与原有按需行为，不用成千上万轮询换取缓存。
