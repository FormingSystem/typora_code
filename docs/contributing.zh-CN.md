# 参与 Typora Code 开发

简体中文 | [英文](contributing.en.md)

Typora Code 在本独立仓库维护。希望改动进入官方工程时，先与维护者对齐需求和设计。独立分叉仍遵守随源码发布的许可。请阅读 [LICENSE](../LICENSE) 和当前[项目声明](../COPYRIGHT.md)，声明原文为中文。

## 开发流程

1. 检查 `git status --short`，保留无关本地修改。阅读 `AGENTS.md`、项目首页、`enhancements/README.md` 和 `docs/development_handoff.md`。
2. 登记稳定需求编号、原意及验收条件，在 `docs/requirements_design.md` 关联持续维护的设计。本地进度与临时证据放在忽略目录 `.cache/issue_tracking/`。
3. 实施前追踪实际调用方和状态归属。界面呈现状态，共享命令与领域服务负责行为，原生能力复用既有适配。每份业务状态与配置只有一个所有者。
4. 保持已授权的布局和范围，局部修复不授权全面重设计。调整几何、配色、图标或交互前，核对固定上游版本的设计事实。
5. 先执行目标检查，再按影响扩大范围。记录实际结果和未测边界。原生与平台验收独立于隐藏窗口或替身测试。

自有标识采用英文 `snake_case`，常量可用 `UPPER_SNAKE_CASE`。语言及第三方强制接口保留原名。新增及修改代码注释使用英文，文档按语言独立维护。读写显式使用 UTF-8；含非 ASCII 字符的 Windows PowerShell 5.1 脚本保留所需的 UTF-8 字节顺序标记。

## 构建与测试

```powershell
cd enhancements
npm ci
npm run build
npm run check
npm run check:ui
```

`npm run check:ui -- --list` 列出界面套件，也可在 `--` 后指定测试文件。`npm run test:quality -- --list` 列出关联需求的分类套件。新增测试复用目录和运行器，明确模块所有权、清理、实现验证及压力验证用途。共享构建产物串行生成。

临时仓库、宿主副本和安装载荷使用受管产物生命周期，保留日志与证据，回收明确归属的临时载荷。禁止使用用户真实仓库测试推送、拉取、丢弃等改写数据的操作。

## 交付

功能候选必须包含已验证的本机安装。同一候选在隔离环境执行安装、检查、卸载、重装和再次检查，覆盖有效备份恢复及无兼容备份的入口撤销。真实用户环境在最终安装前只做卸载只读预检，保留文档、配置与恢复资料。

分别说明源码变化、构建成功、资产安装、窗口加载和行为验证。不能关闭用户窗口或丢弃草稿，需手动重启时明确说明。公开功能候选递增发行序号并附用户可见公告；未发布候选不等于远端可获取版本。

审查差量并执行 `git diff --check`，仅暂存明确审查的路径。提交使用约定式格式，标题说明中文结果，空行后每行正文以 `- 详情` 开始。通过 `scripts/check_commit_messages.py --message-file <file>` 校验，以 `git commit -F <file>` 提交并核对实际正文。未经明确授权不推送。

详细设计、问题台账、安装与历史验证记录目前仍为中文，英文迁移由 R082 跟踪。本指南不替代这些记录，也不表示此前问题全部解决。
