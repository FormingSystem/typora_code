# 中英文发布与本地化设计

## R082：发布语言契约（2026-09-29）

用户要求为正式发布提供独立的纯英文、纯中文文档，自有代码注释使用英文，界面支持中文和英文。此约定覆盖 AGENTS.md 中代码注释使用中文的旧规则；中文设计和交接文档仍使用中文，英文文档独立维护。

### 范围与状态所有者

- GitHub 首页提供独立英文及简体中文入口；安装、操作、开发与贡献说明都应有明确语言和对应入口。技术标识、命令、路径、产品名称及原始许可不翻译。
- 自有界面文字包括菜单、工具提示、无障碍名称、状态、空状态、对话框、设置、引导和错误提示。用户正文、文件名、Git 提交内容、进程输出及第三方插件自有文字不是翻译对象。
- 共享语言服务持有语言解析及选择；领域词典保留语义键与具名插值。Git 和 Monaco 接入相同解析，不新增第二份配置。默认跟随 Typora，显式选择中文或英文；没有可识别宿主语言时使用英文。
- 切换语言的生效边界需覆盖模块初始化时生成的菜单、设置注册表和 Monaco。采用保存后手动重启生效，不能为了文字更新重建正文、丢失草稿或终止终端。失败保留原配置。
- 自有代码注释翻译为英文，保留含义；原始许可证、第三方原始源码及测试中作为数据的中文不机械删除。安装器日志和脚本交互单独清点，不能以 renderer 已翻译声称发行包完整双语。

### 实施方案与取舍

先清点现有文档、注释与硬编码界面文字。复用已有 Git 双语词典的占位符契约，将语言解析提取为共享服务；各调用点在产生文字时使用词条，不遍历/替换正文 DOM，不替换任意用户字符串。持久化由共同设置入口接入，读取时校验允许值。

英文和中文文档按页面分离，提供互相切换链接，使用相同命令、功能范围及验收限制。历史证据、需求编号和已有设计链接保持可追溯；迁移前建立链接映射，不截断历史或以摘要冒充全文翻译。正文中的专业名词允许使用通行英文。

### 验收与发布门槛

1. 核对英文/中文入口、相对链接、命令及声明一致；逐页记录尚未翻译项。
2. 两种语言词条键和占位符一致；未支持语言回退英文；中文/英文/跟随宿主设置、损坏配置及重新启动读取分别验证。
3. 两种语言下核对顶栏、侧栏、设置、文件/Git/搜索/终端/预览、错误与动态提示、无障碍名称及引导；长英文文字、窄窗、明暗和键盘行为保持共同几何契约。
4. 注释检查区分真实注释、字符串及第三方内容；构建和现有相关测试验证行为未变。运行时不得在线调用翻译服务。
5. 功能候选执行构建、检查、同候选隔离安装→检查→卸载→重装→检查、本机只读卸载预检及安装资产校验。未完成翻译或未执行的界面/平台验收保持未完成，不标为正式发布就绪。
