# R075 用户内容容量与运行失败

2026-09-25用户明确要求取消按预设文件大小、数量或处理量提前拒绝功能的限制：设备是否能够处理由真实运行结果决定，用户自行裁剪文件。此前Markdown比较的两侧合计1MiB与10000块回退规则被本要求覆盖。

## 行为与范围

普通文件读写、窗口移交、预览、大纲、Git正文/差异/状态/仓库发现、搜索及替换、SSH文件协议、会话恢复不得因产品内置容量常量拒绝、漏掉或截断用户内容。下载、证书及插件包同样不以任意体积作为格式有效性判据。取消固定计算时限引发的内容处理拒绝；网络连接/凭据等待超时不等同于内容容量限制。

保持流式传输、并发队列、按批次让出主线程、可见行虚拟化、缓存淘汰与差异算法的低成本回退：这些方式处理完整内容，不应限制最终可访问结果。用户明确设置的搜索范围、历史保留策略等仍有效；默认不能偷偷代替用户限制输入大小。操作系统/第三方引擎的真实格式、长度或内存错误如实报告，不伪装成预判能力。

此要求不取消文件身份/并发冲突、编码、二进制格式、权限、路径边界、TLS、压缩包路径穿越、未保存文档和不完整替换保护。分块大小只决定传输方式，不是文件总大小限制。

## 所有者与实现

容量规则随各领域服务清理，不增加全局“大文件服务”或将所有处理搬入UI。Markdown比较保留代际取消与分批构建；文本文件保持完整快照及原子保存；Git保持流消费者背压与取消；搜索Worker可由用户取消，不预先按文件大小或结果数量中止；SSH本地响应与远端读写同步取消容量限制，避免单侧放开后仍被下游拦截。

实际读取、分配或渲染异常通过原有错误通道呈现；失败不得清空当前文档、冒充成功、保存截断内容或覆盖其他操作。用户取消/切换后迟到结果仍需拒绝。进度、缓存、分页和用户设置不得混作能力上限。

## 验证与交付

先扫描调用链和原有容量分支，再用超过原门槛的真实内容验证：Markdown大于1MiB、文本及Git大于16MiB、搜索大于旧文件/快照门槛、SSH大内容与目录、超过原结果上限的路径搜索。覆盖完整字节、末尾结果、保存/取消/失败与主题/位置保留，复用已有测试；不能用提高常量或删除旧断言替代行为验证。按最终同候选构建、安装检查、隔离卸载重装并交付，未覆盖平台如实记录。

实际扫描与最终验证见[2026.09.25.2证据](../enhancements/tests/evidence/resource_capacity_20260925.json)；不声称第三方编辑器及操作系统容量无限。

2026-09-25补充：用户明确64GiB设备可尝试300MiB文件。验收加入300MiB完整读写及重复加载后GC的heap/external/arrayBuffers/RSS采样。观测数据用于定位所有者是否释放资源，不能据此恢复预设拒绝阈值；单进程内存上涨或RSS不立即回落不单独作为泄漏结论。工作台常驻监控不是本次放开容量的前置条件。

SSH的request_timeout现在只控制协议握手；已连接文件/Git请求不因处理时长触发任意拒绝，连接存活仍由OpenSSH保活和用户断开控制。请求序列化失败不登记待回应队列，响应分配失败清理连接及待回应对象。

内存复测入口：在enhancements目录执行 `node scripts/test_resource_capacity.mjs`，生成临时300MiB文件并输出完整性断言与各轮内存采样。该入口不读取用户文档，不作为产品常驻监控或拒绝打开条件。
